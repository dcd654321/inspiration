# Change: 应用清晰轻页并修复现有照片链路

## Why

用户已从三个可操作候选中选择 A「清晰轻页」，要求实际改版，并反馈照片不能正常上传展示。当前页面仍使用旧暖底、较大的首页介绍和各页不同的文字、表单及清单密度；照片选择错误被统一当作取消，真实失败可能没有说明。照片能力还依赖受信拉取的开关、存储前缀、共享环境权限，不能用客户端放开权限解决。

## What Changes

- 将 A 的冷白、靛蓝、连续清单、中文无衬线字阶和紧凑输入布局应用到现有十三个页面，保留四个主导航。
- 收紧记录页介绍，优先呈现输入和保存；保留连续记录、未提交输入与未知保存保护。
- 统一灵感、待办、归档、详情、成稿及辅助页的标题、清单、表单、主次操作和状态反馈。
- 复查照片选择、压缩、上传、关联确认、私有下载及图片错误状态，修复可复现的本地缺陷；平台开关、实际函数版本、权限和真实上传另行核实。
- 记录用户选择、设计约定、回归测试和微信编译/隔离模拟器证据。
- 按用户后续明确要求补齐首页添加照片与标签：标签与正文一次保存，确认后直接从首页添加和查看照片，继续不建立照片草稿。

## Impact

- 受影响规范：clear-page-ui、photo-capture 的既有行为。
- 主要代码：`miniprogram/app.wxss`、`miniprogram/pages/*`、照片服务及对应回归测试。按实际根因决定最小范围。
- 非目标：新增生成式 AI、恢复内容公开分享、离线持久化、调整可信身份、数据库迁移、放宽存储权限、新增云资源、部署或 Git 提交。
- 原型中的未展开入口按现有功能承接，不凭候选示例新增未确认功能；现有记录时间继续显示到秒。

## Authorization

用户原话为「选择A，改吧，顺便改下照片没法正常上传展示的问题」。本提案记录已授权的实施范围，实际云配置/部署与发布不在该授权内。

后续用户明确追问「首页的的添加照片和标签呢」，授权补齐这两个可实际使用的首页入口；云协议、资源和部署范围不变。
