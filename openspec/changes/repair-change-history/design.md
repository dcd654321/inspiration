## Context

旧版本随整条灵感一起提交，服务端校验字段并保护已存在的历史。缺口位于读取与展示：修改记录页仅显示正文，留档未区分两种历史字段。

## Goals / Non-Goals

- Goals：正文与补充的旧文字可以找到、查看、留档，入口数量与实际内容一致。
- Non-Goals：历史恢复或删除、数据迁移、服务端协议改造、云端部署及真实账户写入。

## Decisions

- 扩展现有 `pages/history`。仅带灵感 ID 时展示正文和有历史的补充分组；另带 `supplementId` 时只显示对应补充。目标缺失显示缺失态，不回退到另一对象。
- 当前内容与旧版本分开标识，旧版本按修改时间倒序；现存的已并入正文或已合并补充保留历史入口。
- 主入口数量为正文旧版本数与现存补充旧版本数的总和；补充入口数量为该补充自身旧版本数。
- 历史页面沿用页面版本、store 与账户 epoch 守卫，隐藏或失效时清空内容；只读，不保存查询状态或私人内容到设备。
- 留档函数内部区分正文和补充字段，使用实际数据结构中的 `text` 与 `content`，不迁移数据。

## Risks / Trade-offs

统一页面可能较长，按对象分组及单条补充入口帮助定位。小屏与长文需要原生渲染验收；本地数据库替身不代表正式云端数据和权限已验证。
