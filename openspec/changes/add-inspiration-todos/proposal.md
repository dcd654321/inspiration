# Change: 灵感待办与看板

## Why

用户需要把已有灵感和补充直接作为可执行事项，统一查看待办与已办，并保留随手记录及独立归档的使用方式。

## What Changes

- 正文及每条补充可独立设为待办、设置计划完成日、完成、恢复及移除待办；内容与状态不复制、不级联。
- 底部新增待办看板，包含总数、状态切换、搜索、日期分组及来源定位；启动仍进入记录。
- 有未办事项时归档先提示但允许继续；归档事项在看板可见只读，取消归档后处理。
- 复用账户快照和版本写入，兼容旧数据及旧客户端，不新增集合、索引或 action。

## Impact

- 修改客户端、根 server 源码和两个云函数构建副本，保留已有未提交改动。
- 不包含微信提醒、重复任务、协作、提交推送、云部署或发布。

## Acceptance

- 普通记录默认无待办，正文和补充可独立处理；文字修改、收起、并入不丢待办。
- 看板数量、分组、搜索及来源定位一致，归档事项不漏项且不可直接修改。
- 云确认后更新状态，未知回执、冲突及账户变化不误报完成，不重放旧整条内容。
- 自动化、规范、原生编译/模拟器、真实云、多账户和真机分别登记证据。
