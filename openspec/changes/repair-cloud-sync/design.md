# 设计：云端备份与恢复闭环

## 现状核对

- `services/store.js` 会先写本机快照、入队、尝试一次 `snapshot.push`，但没有启动或回到前台时的 pull/重试调度；`QUEUE_WRITE_FAILED` 时快照已写入但操作未入队。
- `snapshot.push` 客户端请求没有 `baseVersion`；`server/repository.js` 对 `generation` / `baseVersion` 仅在传入数字时检查。协议文档要求的冲突保护因此并未端到端成立。
- `deleteInspiration` 通过写入软删后的快照推送，未调用 `inspiration.delete`；后者才执行云存储文件清理和物理删除。
- 本机键 `linggan:v1:snapshot` / `linggan:v1:queue` 未按账户分区。代码测试里的两个账户服务端隔离，不代表同一台设备切换账户时本机缓存安全。

## 拟定顺序

1. **确认作用域**：云函数从可信上下文识别账户，返回用于本机分区的稳定不透明作用域标识；客户端只把它当缓存分区，不当认证凭据。未确认作用域前不展示旧全局缓存。旧数据先做只读盘点与备份，归属无法证明时保留原件并提示用户，不能擅自挂到当前账户或清空。
2. **取得服务器基线**：在无未同步操作时拉取快照；存在未同步操作时先保留本机意图，获取云端版本和代际，再决定能否继续提交。禁止以一次 pull 覆盖尚未备份的本机内容。
3. **推送与重试**：请求必须带 `baseVersion` 和 `generation`；同一待同步操作在重试时复用 `requestId`。启动、回到前台及用户主动点击重试可触发有界重试；同一账户同一时刻只允许一个同步循环。网络失败可等待重试，冲突和代际落后不可盲目重试。
4. **冲突处理**：`CONFLICT` 时保留当前本机稿和云端稿的可查看副本，由用户选择保留哪一版或手动合并；未决定前不覆盖。`STALE_GENERATION` 时停止旧队列回传，保留本机内容的安全导出路径，经确认后才更新本机快照。
5. **删除闭环**：删除使用 `inspiration.delete`，服务端清理照片并确认后才从本机移除；失败时保留内容或明确的待处理标记。删除操作的重试 ID 不与普通 upsert 混用。
6. **用户状态**：分别显示「备份完成」「备份未完成，可重试」「内容尚未存入本机」「需要处理冲突」。不要把函数调用成功当成云端已写入；显示最近确认时间时注明其含义。

## 兼容、部署与回滚边界

服务端若将版本/代际字段从可选改为必填，须评估仍在运行的旧客户端；应先设计兼容期和最低可用版本，不能直接上线一个会拒绝旧端保存的协议。现有 `linggan:v1:*` 可能包含未备份内容，迁移前不得覆盖或删除；需要给出精确目标、备份方式、回滚位置和失败恢复步骤。新资源继续使用 `linggan_` 前缀。云函数副本由 `scripts/build-cloud.cjs` 生成，部署到正式环境需另行授权。

## 待确认设计点

- 可信账户作用域的取得方式，以及无网络时如何安全选择本机分区。
- 旧全局缓存：用户于 2026-09-24 确认没有须保留的真实记录；代码继续保留旧键但不展示或迁移，不再设计真实数据迁移。
- 冲突界面：本轮实现先提供两份文字的查看与复制；用户可显式选择最新云端版本，客户端先把本机快照及待处理操作原子存成同账户的只读恢复副本，再切换活动快照。自动合并与逐字段选择未实现。
- 自动重试的触发频率、退避上限和前台状态；平台限制和真实耗电需实测。
- 含照片删除：当前保持拒绝，不把逐项删除的部分成功假称为可回滚；等待用户选择后再定后续协议。
