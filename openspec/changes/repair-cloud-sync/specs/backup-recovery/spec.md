# Backup Recovery

## Purpose

确保用户记录与删除的备份状态真实可见，离线重试不重复、不跨账户、不静默覆盖其他设备的内容。

## ADDED Requirements

### Requirement: 可信账户的本机数据隔离

系统 MUST 仅在可信平台身份对应的本机作用域内展示缓存与待同步操作；无法证明归属的旧缓存 MUST 保留但不得自动挂到当前账户。

#### Scenario: 同一设备切换账户
- **WHEN** 同一设备从账户 A 切换到账户 B
- **THEN** 账户 B 看不到账户 A 的本机快照与待同步内容，也不能把它们提交到 B 的云端

#### Scenario: 旧缓存归属不明
- **WHEN** 升级后发现没有可信账户归属信息的旧缓存
- **THEN** 系统保留原件供安全恢复，不自动删除、覆盖或向当前账户展示其中正文

### Requirement: 带版本的拉取与推送

系统 SHALL 在受信账户下取得云端快照基线；推送 MUST 携带代际与基础版本，服务端 MUST 拒绝缺少或不匹配的值。

#### Scenario: 推送缺少版本信息
- **WHEN** 客户端提交不带合法 `generation` 或 `baseVersion` 的 `snapshot.push`
- **THEN** 服务端拒绝整批请求，不写入用户数据

#### Scenario: 拉取时存在待备份内容
- **WHEN** 本机队列中仍有未确认备份的操作
- **THEN** 拉取云端快照不得覆盖本机内容或丢失该操作

#### Scenario: 其他设备已经更新
- **WHEN** 本机基础版本落后于云端版本
- **THEN** 系统停止自动写入并保留本机与云端可查看内容，等待用户决定，不静默覆盖

#### Scenario: 用户采用云端版本
- **WHEN** 用户在冲突提示中明确选择采用最新云端版本
- **THEN** 系统先将本机未确认内容与操作原子保留为该账户的只读恢复副本，再切换活动快照；保留副本失败时不得切换或丢弃原队列

### Requirement: 有界且幂等的备份重试

系统 SHALL 为待同步操作保留稳定请求标识，在可用时有界重试，并 SHALL 将无法重试的状态明确告知用户。

#### Scenario: 断网后恢复
- **WHEN** 保存已写入本机但首次云端请求失败，之后网络恢复
- **THEN** 同一操作可使用原请求标识重试，云端只保留一份内容，成功确认后才清除待处理状态

#### Scenario: 不同设备请求标识碰撞
- **WHEN** 同一账户的不同操作意外使用相同请求标识
- **THEN** 服务端不得将第一项操作的成功响应当作第二项操作的成功，第二项内容不得被静默丢弃

#### Scenario: 暂时性服务端失败后重试
- **WHEN** 一项操作收到暂时性服务端失败，随后以原请求标识重试
- **THEN** 服务端重新执行该操作，不将首次失败作为固定结果返回

#### Scenario: 本机原子写入失败
- **WHEN** 本机快照与待备份操作的单次持久化写入失败
- **THEN** 系统不留下半条状态，页面保留用户输入并说明本次未保存

#### Scenario: 服务端代际领先
- **WHEN** 旧设备携带过时代际试图回传内容
- **THEN** 服务端拒绝写入；客户端停止重试旧操作，并保留本机内容的安全恢复路径

### Requirement: 删除与照片清理闭环

系统 MUST 通过具有照片清理语义的删除动作处理云端记录，未确认成功前 MUST NOT 报告删除已完成。

#### Scenario: 删除成功
- **WHEN** 用户删除一条带照片的灵感且云端确认清理完成
- **THEN** 该条记录和对应云文件被移除，本机才将删除标记结清

#### Scenario: 删除失败
- **WHEN** 云端删除或照片清理失败
- **THEN** 系统保留可恢复的数据与重试入口，明确说明未完成，不让旧设备把该条作为普通新增记录回传
