# Design: 分享与意见反馈

## Context

私有内容保存在 `linggan_accounts`，客户端经 `linggan_api` 使用微信可信上下文访问。现有 `wx.shareFileMessage` 发送 TXT，不提供可撤销的分享页；“我的”页 `open-type="feedback"` 不产生本产品可查的反馈记录。朋友圈打开小程序处于单页、未登录模式，不能假定既有私有函数可用。[带参分享说明](https://docs.cloudbase.net/recipes/add-share-with-params-miniprogram)、[未登录权限说明](https://docs.cloudbase.net/error-code/PERMISSION_DENIED)。

## Decisions

1. 私有账户文档不因分享而拆分。公开可转发的文字快照单独存 `linggan_shares`，反馈单独存 `linggan_feedback`；两者与既有账户集合均禁止客户端直连。
2. 分享必须由所有者主动创建，服务端从已备份的账户记录取正文及用户选择的当前有效补充。仅文字，不含照片、修改历史、账户身份、其他记录。分享页与海报展示同一不可变快照。
3. 聊天卡片落到 `pages/shared/index`。浏览者持不可猜测的令牌经服务端只读动作取快照；令牌是持有即能访问的凭证，不伪称仅指定好友可看。撤销、过期或原记录删除均拒绝读取。
4. 朋友圈首版采用用户手动发布的文字海报。小程序无法代用户自动发表朋友圈；海报一经外发无法撤回，页面在生成前说明。海报首尾附小程序码，码携带短令牌，打开完整小程序的分享页；海报内容分页而非截断。
5. 分享入口（不含内容）可用 `onShareAppMessage` 与 `onShareTimeline`。内容的原生朋友圈卡片需要额外证明单页模式下安全读取；不得在现有共享环境直接开启环境级未登录访问。它是后续发布门槛，不作为首版已交付能力。
6. “我的分享”呈现创建时间、快照摘要、意图渠道、状态和撤销/重新分享，不记录收件人或“已发出”；“我的反馈”只显示本人的提交记录和处理状态。

## Risks and trade-offs

- 令牌可被收到它的人转发；用户确认页必须说明“拿到链接的人都能查看”。不能把分享设计成指定人 ACL。
- 撤销可以关闭小程序链接，但不能收回聊天截图、复制文本或已发布的朋友圈海报。
- `linggan_accounts` 与 `linggan_shares` 跨文档；读取分享时再次校验来源记录仍存在，删除流程先使分享失效，避免半提交泄露。
- 朋友圈单页模式下无 OpenID，CloudBase 默认拒绝未登录访问。若未来要做原生内容卡片，先设计独立公共读取边界、审查共享环境影响与权限规则，再单独获授权部署并真机验证。

## Rollback

代码回退时先停止创建新分享，保留已有分享读取及撤销路径直至到期或全部撤销；不能直接删集合导致用户无法管理已发链接。海报外部副本不可远程删除，反馈数据按独立保留政策处理。新集合与索引的部署/删除必须单独授权。
