  - **2026-09-22 需求变更后重做。** 原实现守着已被撤销的「原文不可改写」，那两条用例（「不导出任何可改写原始正文的路径」「追加补充后原始正文与初始值全等」）已改写，没有保留。现行约束是「改原文必须留历史」：`updateText` 的签名**强制要求** `historyId`，让「改写但不留历史」在调用层面根本写不出来。

- [x] 1.4 实现单条补充的直接操作：`editSupplement`（修改并留历史）、`foldIntoText`（合并进灵感）、`unfoldSupplement`（恢复）、`removeSupplement`（真删）。验证：已通过，用例覆盖修改后旧内容进该条自己的历史、合并后原文追加且本条收起、合并撑破正文上限时整条拒绝、恢复已并入的补充不回退原文、删除后从时间线移除。→ **两个实现要点**：① 删除汇总结果时必须顺带恢复指向它的补充，否则留下悬空 `mergedInto`，那些补充会永远收着出不来（有用例专门断言）；② 合并的长度校验必须做在这里，补充上限 1000、正文上限 2000，接近上限的两条相加就会越界。
