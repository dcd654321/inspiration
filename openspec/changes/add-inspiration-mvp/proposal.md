# Proposal

## Why

灵感往往在一瞬间出现，又在一瞬间消失。用户现在只能靠备忘录或聊天窗口随手记，记完之后既没有地方继续补充，也无法把一句话变成可判断的东西。本变更要把「记下来 → 补充 → 拍照留证 → AI 帮我展开」串成一个闭环，让灵感从一句话变成能继续推进的想法。

（原本设想的第五环「哪条更值得做」由热度提炼承担，已于 2026-09-22 决定暂缓，见 What Changes 末条。）

工程已于 2026-09-22 完成初始化骨架（OpenSpec 目录、构建与检查脚本、可导入开发者工具的最小页面），业务代码尚未编写。本提案描述拟新增的行为，不代表任何功能已经实现或验收。

## What Changes

- **灵感记录与补充**：一句话即可落记录；之后可多次追加补充，形成完整时间线。
- **原文可直接编辑，且保留历史**：灵感正文不再是只读的，用户可以直接改；每次改写前被替换掉的版本会被保留，可回看。（2026-09-22 决定。**这推翻了本提案初稿的核心约束「原始记录不可改写」**，理由见下方「为什么改掉不可变」。）
- **拍照上传**：为灵感附加照片，支持拍照与相册多选，压缩后上传；上传失败可重试且不产生重复文件；删除灵感时同步清理云端文件。
- **AI 扩展灵感**：把灵感原文与选定补充交给 AI，生成结构化想法草案（要点、可执行的下一步、可能的风险）；**必须由用户确认后**才写入，AI 输出先通过结构校验与内容安全校验。
- **AI 汇总**：把同一灵感下的多条补充汇总成一条，或把勾选的多个灵感汇总成一个。两种汇总都**由用户选择**「覆盖原来的」还是「另存一条新的」；选「覆盖」时，被汇总掉的内容**只标记为已合并，不删除**，随时可恢复。
- 新增本项目专属云端资源：云函数 `linggan_api`（业务读写）、`linggan_ai`（AI 能力，默认不启用）、集合 `linggan_accounts`、云存储前缀 `linggan/`。
- **非目标（仅限本次变更）**：不做社交、评论、关注与分享；不做多人协作或团队空间；**本次变更内不接入支付与会员**；不抓取或展示外部热榜/搜索指数；不做全文检索与标签体系；不自动迁移任何历史备忘录数据；不修改其他小程序的函数、集合与共用认证配置。

> **关于会员（2026-09-22 确认）**：**会员是要做的，只是排在 MVP 之后。** 所以上面那条准确的读法是「本次变更内不做」，不是「永远不做」——初稿把它写成了绝对的非目标，已改。
>
> 第一批会员能力是「操作可撤回」（修改、合并进灵感、删除的撤回），已记入 `docs/BACKLOG.md`，等 MVP 完成后再立项。届时它是**独立变更**，不塞回本变更里——本变更只保证一件事：**免费版的所有操作在语义上是完整的、可用的**，撤回只是补救，不是必需品。

### 为什么改掉「原文不可改写」

初稿把「原始记录不可改写」当作产品的核心承诺。实际使用中这条会挡住一类真实需求：用户记下一句话，想了两天，发现原话写偏了——他需要的是**把那句话改对**，而不是在下面追加一条「更正：上面那句应该写成……」。逼用户靠追加来绕，时间线会变成一叠补丁，而他真正想留下的那句话反而永远停在最初那个不准确的版本上。

保留历史满足了两边的诉求：**用户能改，但改不掉历史**。原来那条承诺的实质（「你说过的话不会被悄悄抹掉」）由历史版本继续承担，只是位置从「正文不可变」挪到了「版本可回看」。

### 为什么「覆盖」不真删

汇总的动作是 AI 做的。让模型生成的结果**永久顶掉用户自己写下的原话**，风险不对等：AI 汇总错了，用户丢的是原始内容；而保留成本极低——折叠一段文字而已。所以「覆盖」在界面上照常表现为覆盖（原内容默认收起），底层只打合并标记，随时能展开恢复。
- **本变更暂缓（2026-09-22 决定）**：**灵感热度提炼不做**，留待后续独立变更。原因是热度依赖补充条数、照片数量、AI 扩展次数等信号，这些在 MVP 完成前均为零，此时实现既无法验证也无法调优。本变更内不实现 `core/heat.js`，列表与详情页不出现热度展示位，界面文案不得提及热度或以「优先级评分」等名称暗示存在评分功能；灵感数据结构中保留 `heat` 字段名但不写入，避免后续变更做数据迁移。`specs/inspiration-heat/spec.md` 的内容原样保留、不删除，待后续提案时迁移，**在本变更归档前不得当作已实现能力**。

## Capabilities

### New Capabilities

- `inspiration-capture`：灵感的记录、多次补充，以及**原文编辑与版本历史**；已合并内容的标记与恢复。
- `photo-capture`：灵感的照片采集、压缩、上传、重试与随灵感删除的清理。
- `ai-expansion`：把零散灵感扩展为结构化草案，且只在用户确认后落盘。
- `ai-summarize`：把多条补充汇总成一条，或把多个灵感汇总成一个；覆盖或另存由用户选择，覆盖只标记不删除。

本变更**不含** `inspiration-heat`。该能力的规范文件 `specs/inspiration-heat/spec.md` 为暂缓期间的原样保留，不属于本变更的交付范围，也不得随本变更归档。归档前需先把它移出本变更目录。

### Modified Capabilities

无。当前 `openspec/specs/` 为空，本变更只新增能力，不重新声明任何既有实现。

## Impact

- **已落地**（2026-09-22）：`miniprogram/core/` 的四个模块——`errors.js`、`limits.js`、`inspiration.js`、`ai-contract.js`——与对应单元测试。其中 `inspiration.js` 已按本提案的新决定改写：不可变约束撤销，改为「改原文必须留历史」，并新增合并原语；`ai-contract.js` 新增汇总结果的契约校验。见 tasks.md 第 1 节与第 5A 节。
- 拟新增：`miniprogram/pages/capture`、`miniprogram/pages/detail`、`miniprogram/pages/list` 的业务实现；`miniprogram/services/` 下的会话、草稿、本机存储、上传与 AI 调用；`cloudfunctions/linggan_api`、`cloudfunctions/linggan_ai`；`server/` 下的协议与仓库层；对应测试。
- **本变更不新增** `miniprogram/core/heat.js`（已暂缓）。
- 拟新增文档：`docs/detailed-design.md`（接口契约、状态机、错误码）、`docs/ui-design.md`（页面区块与三态呈现）、`docs/ui-mockup.html`（可视化原型）。
- 拟修改：`miniprogram/app.json`（页面注册）、`miniprogram/config/cloud.js`（环境与开关，保持 `enabled: false` 直到用户授权）、`miniprogram/config/cloud-resources.js`。
- 远端范围仅限本项目 `linggan_*` 资源。**本提案不授予任何远端变更权限**：创建集合、部署云函数、启用 AI、配置环境变量均需在实施阶段单独取得授权。
- 本地现状已核验：工程只有骨架，`config/cloud.js` 与 `config/ai.js` 的 `enabled` 均为 `false`，页面无业务逻辑。
- 验收成功标准：用户能完成「记录 → 补充 → **改原文 → 回看历史** → 拍照 → AI 扩展 → **汇总补充** → **勾选多个灵感汇总**」全流程；**被「覆盖」的内容可展开并恢复**；两个微信账户互不可见；AI 不可用时记录、补充、浏览完全可用；删除灵感后云端照片被清理。**提案完成不等于上述标准已经达成。**
