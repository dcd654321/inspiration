## ADDED Requirements

### Requirement: 前台运营会话

系统 SHALL 在可信账户确认后统计前台会话累计时长，前后台和账户失效 MUST 隔离；上报最多一次内存重试，不持久化队列。

start MUST 先确认，心跳与 end SHALL 按会话串行发送。客户端 SHALL 按成功请求的实际发起时刻与服务端返回的 startedAtMs/observedAtMs 对齐同一累计起点；startedAtMs、observedAtMs 与 elapsedMs MUST 为安全整数，时间间隔与累计值 SHALL 位于 0—36 小时范围。账户确认后的采集等待计入前台时间，账户初始化等待不计。旧服务端缺少时间回执或回执无效时 SHALL 以成功尝试的发起时刻兼容，不以 ACK 到达时刻重置累计起点。

#### Scenario: 前台开始心跳隐藏结束
- **WHEN** 用户进入前台、等待心跳并隐藏应用
- **THEN** 系统发送 start、累计前台心跳与 end，隐藏时间不计入

#### Scenario: 账户失效与单次重试
- **WHEN** 上报失败或账户会话已变化
- **THEN** 当前请求最多一次重试，旧账户迟到请求停止

#### Scenario: 首报失败后同会话恢复
- **WHEN** start 的两次尝试均失败，当前账户与代际仍有效且后续心跳或结束发生
- **THEN** 系统复用 sessionId 再确认 start 后发送后续累计值；start 回执丢失后的重复请求使用服务端首次起点，不重复计访问

#### Scenario: 跨午夜慢回执与本机时差
- **WHEN** start 回执延迟跨过北京时间午夜，或本机时钟与服务端存在固定偏移
- **THEN** 客户端保持服务端对齐的累计起点，心跳排队前固定采样时刻；不能将午夜后的时间贴回前一日

#### Scenario: 后台到达的启动回执
- **WHEN** 应用已隐藏后才收到 start 成功回执
- **THEN** end 仅使用隐藏时已固定的累计时刻，迟到 ACK 不追加后台时间，新的会话或账户失效仍停止旧请求

### Requirement: 最小化运营事件

系统 SHALL 只上报白名单元信息；成功复制和生成 TXT 才记输出事件，错误原文与个人内容 MUST 不上传。

#### Scenario: 白名单错误耗时与输出成功
- **WHEN** 发生错误、业务请求完成或输出操作完成
- **THEN** 只上报稳定码和元信息，复制/生成失败不记成功事件，监控请求不自我上报

#### Scenario: 复制对象在请求时确定
- **WHEN** 用户复制稿件并在剪贴板成功回调前继续编辑
- **THEN** 系统按调用时的复制对象记录一次成功稿件复制，编辑无需等待；复制留档文字不计为成品复制，失效页面或账户的迟到回调不记录事件

### Requirement: 云端确认新增事件

系统 SHALL 在实际提交后根据新增差异生成幂等事件，可信 sourceUserId MUST 由平台身份产生，监控失败不改变业务成功。

已提交保存的统计等待 MUST 最多 500 毫秒，超时记录固定码并返回保存确认；迟到拒绝 MUST 被处理。启动、账户绑定、前后台、复制及 TXT 成功回调的采集同步或异步异常 MUST 不改变原功能结果。

#### Scenario: 新记录补充与另存只计一次
- **WHEN** 云端确认新增记录、补充或带用途的另存记录
- **THEN** 系统分别记录 record_saved、supplement_saved、output_saved；相同重试与编辑不重复计数

#### Scenario: 冲突失败与监控故障隔离
- **WHEN** 保存冲突或事件写入失败
- **THEN** 保存未成功不记成功事件，已成功保存不因监控故障变成失败

#### Scenario: 代际变更与事件事务并发
- **WHEN** 事件事务已读旧代际而账户代际在其提交前变化
- **THEN** 同事务账户写屏障产生写冲突，重试重新校验并停止旧事件，不改变业务版本或内容
