# 修复保存回执与快照版本一致性

## Why
2026-10-09 全量审查以纯内存仓库复现两种补充丢失：相同内容重试取得其他记录更新后的版本号，但客户端仍持旧快照；等待刷新时构造的旧记录在排队后套用最新版本提交。两者都可能删除另一设备刚添加的补充。照片清理包含多次 CAS，成功回执也可能跨越多个版本。

## What Changes
- 既有写操作在调用时绑定快照版本和代际，排队期间变化则拒绝旧请求。
- 幂等的相同内容或缺失记录回执须先核对版本，过期请求由既有回读和内容核对确认。
- 成功回执跨越多个版本时回读完整快照，不能仅给旧内容设置新版本。
- 保留注册照片清理任务的幂等恢复，不增加持久队列、数据库字段或自动内容合并。

## Impact
范围为本地存储服务、仓库和照片清理源码、生成副本及回归。用户已授权全量审查并修复确认问题。未授权的正式部署、云端写入、删除、提交与发布不在本次内。既有云函数需另行部署才能获得服务端修复。
