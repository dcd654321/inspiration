# 快照版本修复设计

## Context
服务端成功信封只返回版本与动作摘要，不携带完整快照。客户端只可对已取得的完整快照应用来自同一基线的单次写入；其他设备内容不能由版本号推导。

## Decisions
`serialWrite(work)` 在调用时捕获版本/代际，进入串行执行时复核；版本变化返回 CONFLICT，代际变化返回 STALE_GENERATION。新增、补充与独立删除共用此约束。

服务端 push 相同内容回执前核对 baseVersion；缺失记录的删除及照片清理空操作同样核对。已登记的照片清理任务仍允许以原请求恢复，因为文件删除无法回滚。

成功回执版本大于当前视图版本加一时，复用 pull + isConfirmed 路径。回读失败保留原版本并返回可重试未知结果；回读成功使用完整快照，仅内容或删除确实匹配时确认成功。

## Verification
纯内存仓库和真实客户端服务复现未知保存、另一条记录并发补充、排队刷新、删除空操作及多次 CAS 回执。真机、多账户云端并发和部署分别验收。
