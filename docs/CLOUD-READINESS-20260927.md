## 4. 已确认的部署阻断与仍未知项

1. **不能先上传新版 API 再慢慢建集合。** 本地 `server/rate-limit.js` 依赖限流集合；`server/cloud-sharing-db.js` 的业务写入依赖分享、反馈和配额集合。缺少资源时本地设计会失败关闭。
2. **删除也依赖分享资源。** `cloudfunctions/linggan_api/index.js` 把 `sharing.revokeForSource` 传给 repository；删除无照片灵感时先查询/撤销来源分享，再执行账户条件写入。若将此版本部署到缺少 `linggan_shares` 的环境，删除会因撤销前置失败而停止。这是源码依赖推断，未在生产调用验证，也不说明线上旧版此刻存在同一故障。
3. **AI 不能只开开关。** 用量集合缺失，现有函数超时过短；模型、预算、服务端开关和审核权限也未确认。客户端仍保持 enabled=false。
4. **维护函数暂缓执行。** 函数未部署，没有自动清理证据。以后即使部署，也保持维护开关关闭、无自动触发器；先经授权演练，实际删除另行确认。

### 第一批：分享/反馈基础资源准备（待授权）

精确环境仍为 `cloud1-d6g4hu8txdd86e48c`，只涉及：

- 新建 `linggan_shares`、`linggan_feedback`、`linggan_usage`、`linggan_rate_limits` 四个集合；
- 按数据库设计建立业务与清理查询索引，唯一索引失败立即停止，不删除冲突数据；
- 对这四个集合设置客户端全拒绝规则，并核验既有 `linggan_accounts` 规则；既有规则若需修改须明确影响后确认；
- 不写业务文档，不修改其他集合，不修改共享认证/存储权限，不部署函数，不开启 AI，不创建清理触发器。

影响：新增空集合和索引会占用环境资源，实际配额/费用未在本轮核实。恢复边界：没有业务数据时也不自动删除新增资源；一旦开始写入，停止新写并保留数据，不以删集合回退。

当前 CLI 缺少权限规则读写动作；只创建集合或索引不算完成本批，必须完成控制台权限确认后才能进入部署。

确认当前工作区的提交范围并提交 dev；记录线上版本与回退点；确认共享资源安全、分享凭据、审核权限和兼容条件后，再授权部署本项目函数。使用受控账户和合成内容验证记录、补充、同步、复制另存、分享创建/接收/撤销、反馈及删除前撤销。

不能以“客户端云开关已开”“函数 Active”或“Node 测试通过”替代本批证据。
