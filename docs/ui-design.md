## 1. 全局约定

**样式令牌**（沿用 `miniprogram/app.wxss`，不新增令牌）

**视觉原则**（决定了上面这些值怎么用）

1. **原文是锚点。** 详情页的原始正文**不放进卡片**，直接落在页面底色上，用全页最大的字号（`38rpx` / 行高 1.78）。其余所有内容都从属于它。
2. **层级用留白和分隔线做，不用阴影。** 列表是连续承载面加发丝分隔线，不是一张张浮起的卡片。全页只有手机外框带阴影（那是原型的容器，不是产品的一部分）。
3. **草案是临时的。** AI 草案用虚线描边、浅底、并显式标注「尚未写入」。这不是装饰——它把规范里「确认前不得写入用户数据」这条规则变成了看得见的信息。
4. **同步状态只在异常时出现。** 正常同步的条目不带任何标记，避免每一条都挂一个无意义的徽标。
5. **承载面用在真正需要「一整块内容」的地方**（列表、隐私说明、草案），不滥用卡片把页面切成一格一格。

**可视化参考**：品牌图形见 `assets/branding/miniprogram-avatar-144.png`；交互原型见 `docs/ui-mockup.html`。

**当前界面截图**见 `docs/evidence-development-20260928/`（14 张，2026-09-28 由开发者工具离线样例工程逐页截取）。这批图证明的是当前代码在**模拟器**里的静态呈现，**不是真机**，也不覆盖分享创建、海报、AI 生成等需要云端能力的路径；边界见 `VERIFICATION.md` 当日小节。更早的 `docs/evidence-development-20260927/` 与 `docs/audits/2026-09-23-product-optimization/` 对应的是当时的界面，**已不代表现状**，只作为历史记录保留。

原型只用于对齐布局与交互，不是可运行的小程序；当前页面以 WXML / WXSS 为准，真实编译与渲染仍需在微信开发者工具中确认。

**提示方式**：分两类，不能混用。

- **页面内联提示**——用于用户会据此误判数据状态的场景（保存失败、同步失败、删除失败、上传失败）。`wx.showToast` 会自动消失，用户错过之后会以为已经成功，所以这类提示必须常驻在页面上，直到状态改变。
- **轻提示 `wx.showToast`**——仅用于已确定成功、无需用户处理的正向反馈（如补充添加后的「已添加」）。

**三态覆盖**：每个页面、每个异步数据区都必须写出**空态、加载态、失败态**三种呈现。骨架版本里只写了正常态的占位，这是 AI 实现时最容易漏的部分。

**实现约定**：

- 页面 `.wxss` 只放该页独有样式，通用样式一律加进 `app.wxss`。
- 三个 tab 使用同一套 81px 线性 PNG 图标，选中态统一为主色；源文件由 `scripts/build-tab-icons.ps1` 生成。
- 所有可点击元素的 `disabled` 状态必须有视觉区分，不能只靠逻辑拦截。
- 按钮文案在异步过程中要改变（如「保存」→「保存中…」），不能静默等待。

**导航栏标题**（2026-09-22 补。此前没规定过，结果原型与代码各写各的，分叉了一次）：

| 页面 | 导航栏标题 | 理由 |
| --- | --- | --- |
| 三个 tab 页（记录 / 灵感 / 我的） | **小程序名「灵感拾光簿」** | tab 栏已经标了区块名，导航栏再重复一遍是冗余。改用小程序名，让人随时能确认打开的是哪个小程序；页面功能由**页内标题**承担（「记录想法，持续完善」「我的灵感」「我的」） |
| 二级页 | 功能名：「灵感详情」「修改记录」「整理与留档」「选材整理」「整理想法」「查看照片」「分享文字」「查看分享」「我的分享」「意见反馈」「分享小程序」 | 它们没有 tab 标签，导航栏必须回答「我在哪」 |

**排查「标题没变」时先看页面自己的 json**：`app.json` 的 `window.navigationBarTitleText` 只是**全局默认值**，任何页面在 `pages/*/index.json` 里设了自己的标题就会把它盖掉。改全局值不影响这些页面——这是这次踩到的坑。

## 2. 记录页 `pages/capture`

Tab 首页，冷启动默认落地页。设计目标：**一次输入 + 一次点击完成记录**。

### 区块

| 区块 | 内容 |
| --- | --- |
| A 标题区 | 品牌图形 + 标题「记录想法，持续完善」+ 副标题「点子、计划和问题，都可以在这里记录、补充并整理使用。」；同时说明记录对象与后续价值 |
| B 输入卡片 | `textarea`（`maxlength` 取 `LIMITS.textMaxLength`，`auto-height`）+ 右下角字数计数器 + 全宽主按钮「记下来」 |

**移除**骨架版本中的 `.placeholder` 说明块——它属于工程说明，不应出现在产品界面。

### 状态

| 状态 | 呈现 |
| --- | --- |
| 空态 | 占位符「此刻想到什么？」。计数器显示 `0 / 2000`。保存按钮 **disabled**（置灰） |
| 输入中 | 计数器实时更新。超过上限 90% 时计数器转为警示色 |
| 保存中 | 按钮文案「正在记下…」且 disabled，`textarea` 设为只读 |
| 保存成功 | 清空输入，计数器归零，按钮恢复「记下来」并回到 disabled。页面内联显示「已记下。可以继续记录，或查看刚才的想法。」和「查看这条」入口，直接进入刚记下的详情 |
| 备份未完成 | **输入照常清空**——本次内容已写入当前设备。页面内联提示「已记下，但备份未完成。请暂时不要清理小程序数据。」并保留「查看这条」入口。有界重试已实现（前台网络恢复时再试），但**页面不承诺「稍后会自动完成备份」**，因为重试可能一直失败 |
| 备份冲突 | 输入**保留在输入框**，提示「备份出现冲突，内容仍在输入框中。请到『我的』查看备份状态。」——冲突要用户决定，不能替他重置 |
| 写入失败 | **输入原样保留**。内联提示「存储空间不足，暂时无法保存。内容还在，可清理空间后重试。」**不得静默失败** |

**区分「同步未成功」与「写入失败」是刻意的。** 前者数据在，清空输入是对的；后者数据不在，清空输入就等于把用户刚写的东西弄丢了。两者的视觉一致（都是红色内联提示），但行为必须不同。

失败态是这一页的关键：规范要求「不报告虚假的保存成功」，因此失败时既不能清空输入，也不能用会自动消失的 toast。

超过正文上限时，`maxlength` 由 `textarea` 原生阻止继续输入，同时计数器提示上限——**不得静默截断用户已写的内容**。

## 3. 灵感列表页 `pages/list`

Tab 第二项。

### 区块

| 区块 | 内容 |
| --- | --- |
| A 标题区 | 标题「我的灵感」，右上角「记一条」。AI 汇总已接线，**只在 `aiEnabled` 为真时**显示「汇总多条灵感」；不展示不可用动作。**不写副标题**——排序是产品行为，不需要向用户报备实现方式 |
| B 工具区 | 搜索框（匹配正文、有效补充与标签，至多 100 字）＋四个筛选 chip（全部 / 有补充 / 最近七天 / 已合并）＋阶段选择＋「每日回顾」开关＋「选材整理」入口 |
| C 列表 | 连续承载面 + 发丝分隔线，**不是一张张浮起的卡片** |
| D 列表尾部 | 开始记录的主入口固定在标题区，避免长列表底部难以触达 |

### 列表项元素

| 元素 | 说明 |
| --- | --- |
| 正文首行 | 最多显示 2 行，超出用省略号。取 `text` 的首行 |
| 更新时间 | 相对时间（如「3 小时前」），取 `updatedAt`。分桶阈值见 `detailed-design.md` §7.8——**按经过时间分桶，不做日历日运算**，「昨天」按 24—48 小时计 |
| 补充条数 | 仅统计时间线上当前有效的补充，不把已并入正文或已合并的补充算进去；有补充时显示「2 条补充」 |
| 标签与阶段 | 已合并的条目显示「已合并」，否则显示阶段（想法 / 整理中 / 可使用），随后是标签。标签至多 5 个、每个 12 字 |
| 照片数量 | 当前列表不展示，照片细节留在详情页；照片功能未接通时不得用数字暗示可用 |
| 同步状态标记 | 当前列表未实现逐条状态标记；备份恢复流程立项时再确定可见状态。不得把 `dirty` 等内部术语直接展示给用户 |

**不出现**热度分数或理由。

### 已合并内容的入口（2026-09-28 修订）

原设计在列表尾部留一行「已合并 N 条」。实现在筛选 chip 里给了「已合并」，与「全部 / 有补充 / 最近七天」并列——入口更早出现、不必滚到列表底部。

**默认隐藏 + 没有入口 = 删除**这条判断不变：已合并的灵感默认不出现在列表里，`已合并` 筛选必须一直可用（它不依赖 AI 是否启用）。

### 状态

| 状态 | 呈现 |
| --- | --- |
| 空态 | 「还没有灵感」+「从一个想法开始，之后可以继续补充、整理并复制使用。」配品牌图形与「记下第一个想法」入口 |
| 加载态 | 列表区显示三行静态骨架；已有缓存数据时直接渲染缓存，不阻塞 |
| 首次读取失败 | 单独显示「暂时无法读取灵感」与「重新读取」，不得同时落入正常空状态 |
| 刷新失败 | 保留已有列表，顶部显示「暂时无法刷新，当前内容仍可查看。」与「重新读取」 |

**汇总入口**（2026-09-28 修订：选择与确认都已迁到独立页面）：

- 列表标题区右侧的「汇总多条灵感」进入 `pages/ai-workbench?scope=inspirations`，**勾选与生成都在那一页完成**，列表页只负责入口。
- 工作台内选 **2 至 20 条**才能生成；数量不足时按钮置灰说明原因。**不得在数量不足时发起调用**——白耗额度。
- 汇总结果以草案面板呈现，要求用户**显式选择**「覆盖灵感」还是「一个新灵感」，**没有默认值**；选「覆盖灵感」还须明确**写回哪一条**（见 §4 D）。
- 选「覆盖灵感」时，被汇总的灵感从列表**默认消失**；选「一个新灵感」时，被勾选的灵感**完全不动**。

**跨灵感选材入口**：「选材整理 · 组合多条灵感」进入 `pages/material-output`，与 AI 无关，AI 未启用时照常可用。

排序始终按 `updatedAt` 倒序，最近有补充的排在最前。本机有新变更但未同步的条目，仍按本机的 `updatedAt` 排序——用户看到的顺序应符合他刚才的操作。

## 4. 灵感详情页 `pages/detail`

由列表页点击进入，`query.id` 传入灵感标识。

### 区块

| 区块 | 内容 |
| --- | --- |
| A 原文区 | 正文可直接修改；存在记录时出现「查看修改记录」入口 |
| B 继续补充 | 输入区紧随原文，作为详情页主要动作；保存失败时保留输入 |
| C 操作区 | 两列排布：整理内容 / 复制内容；分享文字；扩展想法 / 汇总补充（二者只在 `aiEnabled` 为真时出现） |
| D 整理标记 | 标签（至多 5 个、每个 12 字）与阶段（想法 / 整理中 / 可使用）；来源记录缺失时给出不可用状态，不跳转错误目标 |
| E 补充时间线 | 按时间**正序**排列的补充条目；已合并的默认收起 |
| F 照片区 | 由服务端能力决定：`photosEnabled` 为真才显示图片网格与添加入口；**当前 product 未开启，因此不显示**。已有照片仍可私有预览 |
| G 删除 | 底部次要样式按钮「删除灵感」 |

> 2026-09-28 修订：原表把 C 记为「整理与复制」、E 记为「照片区」，与后面的小节编号（C 照片区、D AI 区）对不上，且未收录分享入口与整理标记。本节按实际页面重排；`pages/ai-workbench` 承担 AI 交互后，详情页不再内嵌草案面板，只保留入口。

### A 原文区

正文完整展示，不截断。**可以直接编辑**——点进去改，保存后生效。

> 2026-09-22 修订。初稿把这里做成只读，只给「我想补充」，依据是当时那条「原文不可改写」的规范。该约束已撤销：用户记下一句话、过了两天发现写偏了，他需要的是**把那句话改对**，而不是在下面追加一条「更正：上面那句应该写成……」。逼他用追加来绕，时间线会变成一叠补丁，而他真正想留下的那句话反而停在最初那个不准确的版本上。

改写保存后，原文区出现**「查看修改记录（N）」入口**（仅在确实存在记录时出现），点开按时间倒序列出历次旧内容，各自标明修改时间。

- 历史条目**只读**，不提供恢复、编辑或删除入口——它是记录，不是草稿。
- 历史**没有删除入口**。这是产品承诺「你说过的话不会被悄悄抹掉」的界面体现。
- 入口本身不强调；数量直接写在文字中，不使用醒目的徽标。

编辑正文时与其他文本输入同规则：清空不保存、超长拒绝且不截断、失败时保留输入并内联提示。

**修改记录页**（点「查看修改记录」进入）：

| 项 | 呈现 |
| --- | --- |
| 顺序 | 按修改时间**倒序**，最近一次修改前的内容在最上 |
| 每条 | 「修改于 MM-DD HH:mm」+ 旧内容。用开放时间线呈现，视觉上比当前内容弱一档 |
| 当前原文 | 固定在列表**上方**，用白底面板标出「当前内容」——先让用户确认现在是什么，再回看旧版本 |
| 操作 | **只读。没有编辑入口，也没有删除入口。** |

**没有删除入口是刻意的。** 这是产品承诺「你说过的话不会被悄悄抹掉」的界面体现——如果历史能删，那个承诺就只剩下前半句。

### E 补充时间线

每条补充显示：内容、记录时间、来源标记。`source` 为 `'ai'` 的条目**必须**带可见的「AI 生成」标记，且标注「内容可能不准确，请自行判断」。

追加补充输入区紧随原文、位于时间线上方，`maxlength` 取 `LIMITS.supplementMaxLength`。提交失败时保留输入并内联提示，与记录页同规则。修改原文时暂不展示补充输入区，避免同时编辑两处。

状态：

| 状态 | 呈现 |
| --- | --- |
| 无补充 | 时间线区显示「还没有补充」 |
| 提交中 | 按钮「添加中…」且 disabled |
| 提交失败 | 输入保留 + 内联失败提示 + 可重试 |
| 内容为空 | 按钮 disabled，不发请求。规范要求空补充不写入、也不改变更新时间 |

**选择态与汇总**（2026-09-22 新增，「AI 汇总」能力）：

- 时间线附近提供「选择」入口，进入后每条补充前出现勾选框。
- 选中**两条以上**时底部浮出「汇总」按钮；只选一条时按钮置灰并说明「至少选两条」。**不得在数量不足时发起调用**——那会白白消耗额度。
- 汇总结果以**草案面板**呈现，与 AI 扩展共用同一种视觉（虚线描边 + 浅底 + 「未写入」），并在面板内要求用户**显式选择**「覆盖补充」还是「新增补充」。**没有默认值**——这是整条链路上不可逆程度最高的一步，不能替用户预选。
- 选「覆盖补充」时，被汇总的补充在时间线上**默认收起**；选「新增补充」时，被汇总的补充**完全不动**，仍独立可见。

**已合并补充的呈现**：

| 项 | 呈现 |
| --- | --- |
| 收起态 | 一行摘要 +「展开」，位置留在时间线上原处。**两种收起的措辞必须不同**：被 AI 汇总的写「N 条已合并」，被并入正文的写「1 条已并入灵感」——只写「合并」两个字，用户分不清并到哪去了 |
| 展开态 | 逐条展示原内容与记录时间，每条带「恢复」操作 |
| 恢复后 | 该条回到时间线上的原位置（仍按时间排序），汇总结果与原文均不受影响，两者并存 |

**不能没有入口。** 已合并的内容只是默认收起，不是被隐藏。如果界面上没有任何地方能看到和恢复它们，那和删除没有区别——而规范明确要求它们可查看、可恢复。

**补充操作面板**（2026-09-22 新增，后续补充可发现性整改）：

| 选项 | 说明文字 | 后果 |
| --- | --- | --- |
| 修改 | —— | 进入编辑态，改完保存；旧内容进历史，可回看 |
| 并入正文 | 「把这条补充追加到正文末尾」 | 本条收起，可展开恢复 |
| 删除 | 「不可恢复」 | 再弹一次确认 |

视觉与交互约束：

- 每条补充提供可见的「更多」按钮；长按保留为快捷方式，但不得作为唯一入口。
- **面板标题标明操作对象**，用「这条补充 · 昨天 21:40」这样的定位，**不要直接把内容截断成一句引用**——那样引用句孤零零浮着，用户看不出它跟哪个操作有关联。
- **「删除」用危险色，且与另外两项在视觉上分开。** 不能和「修改」长得一样、紧挨着排——长按是容易误触的手势。
- **点「删除」必须再弹一次确认**，明确写出「此操作无法撤销」。一次点击就删掉用户写下的东西，是不可接受的。
- **确认弹窗要把待删内容放进一个带时间的框里**，正文写「这条补充将被移除，此操作无法撤销」，框里是内容本身与它的记录时间。这样「要删的就是这条」这件事才是连着的，而不是两句不相干的文字摆在一起。
- 「并入正文」旁要写清后果——用户需要知道这一步到底做了什么，而不是只看到一个词。
- 已合并或已并入灵感的补充，操作面板里**不提供「修改」**，只提供「恢复」与「删除」。它们已经不在时间线上正常显示，先恢复再改，用户才看得清自己在改什么。
- **「合并」在本产品里有两个用法，界面必须让目标可分辨**：操作面板的「并入正文」写入的是**灵感正文**；AI 汇总的「覆盖补充 / 覆盖灵感」写入的是**汇总结果**。完整对照见 `specs/inspiration-capture/spec.md`。

### G 删除

点击后二次确认（`wx.showModal`），确认后进入删除中的界面状态：

- 底部按钮显示「删除中…」并禁用其余写操作；
- 成功后返回列表页并移除该条；
- 失败后**全部保留**，内联提示「删除失败，请稍后重试。」；用户可再次点击删除。

不得在云端确认前从本机移除，否则会出现「本机已删、云端还在」的状态。

### 文案要求

- **不区分本机存储与云端存储。** 2026-09-22 决定：保存后自动同步云端，失败则提示，界面不呈现「本机 / 云端」的二分。因此**不要**写「数据只存在这台手机上」这类告警——那是把实现分层摊给用户看。本机存储不可靠是工程事实（见 `detailed-design.md` §3.6），但它的对策是**让云端成为数据来源**，不是让用户去理解有两层存储。
- **清单上不出现「待同步」。** 保存后立刻同步，中间态转瞬即逝，不该被渲染成常驻标记。只有 `sync_failed` 与 `conflict` 才需要出现在界面上（见 `detailed-design.md` §5.1）。
- **照片用途**在照片完整闭环接通、入口开放时单独说明；当前不展示照片相关承诺。规范里的存储和日志约束仍然有效，不因暂时隐藏文案而解除。
- **不展示内部能力状态区块。** 备份状态和重试流程正式开放后，提供最后成功时间和失败重试；不得只显示内部开关的“已启用 / 未启用”。
- **不得出现热度相关文案**。也不得用「优先级评分」「推荐指数」等别的名字暗示存在评分功能——热度已暂缓，此处暗示即为不实陈述。

## 6. 文案基调与合规红线

### 6.1 基调

**短句，陈述事实。不推销、不解释架构、不辩解、不罗列功能。**

这个产品是一个人的私人灵感本，界面文案应该像一个安静好用的工具，而不是一个急着证明自己的 App。以下七类写法一律禁止：

| 禁止 | 反例（曾出现在原型里） | 问题 |
| --- | --- | --- |
| 功能罗列当卖点 | 「先写下来，之后可以随时补充、拍照，再让 AI 帮你展开」 | 像广告语；且在 AI 默认关闭时承诺 AI 能力，属不实描述 |
| 把内部实现讲给用户 | 「按最近更新时间倒序排列」 | 排序是产品行为，不需要向用户报备实现方式 |
| 把工程流程暴露给用户 | 「两项均需先完成资源创建授权、部署与验收，不能通过直接改开关生效」 | 这是开发者的话，用户不关心也不该看到 |
| 把规范条款抄成界面文案 | 「记录、补充、拍照与浏览不受影响」 | 功能矩阵不是文案；用户只会困惑为什么突然提这个 |
| 技术名词直出 | 「不上传至任何对外展示场景、不写入日志」 | 「写入日志」对用户没有意义，是工程保证而非用户语言 |
| 过度解释与辩解 | 「已跳过，其余图片不受影响」 | 后半句是在替自己开脱；把事实说清楚就够了 |
| 推销口吻 | 「让 AI 帮你展开」 | 与「不得夸大 AI 效果」的规范冲突 |
| **开发脚手架漏进产品** | 「工程骨架版本尚未实现」「详细范围见 openspec/…/proposal.md」「启用需先完成资源创建授权、部署与验收」 | 这些是写给开发者自己的，使用者看到只会觉得产品没做完、或者被内部流程打扰 |

最后一条单独强调：**开发期的进度说明、提案路径、授权流程、任务编号，一律不得出现在任何面向使用者的位置**，包括页面文案、按钮提示、toast、以及会进包的日志。它们属于代码注释，不属于产品。
（`console.info` 这类纯开发者日志可以保留诊断信息，但不要写「骨架版本」「尚未实现」这类带开发阶段判断的话。）

### 6.2 使用自然、明确的动作语言（2026-09-22 修订）

界面是个人工具，按钮既不能像内部表单，也不需要写成规章。动作名称直接说明用户正在做什么，并与页面语境一致：

| 原措辞 | 改为 |
| --- | --- |
| 新建灵感 | 记一条灵感 |
| 提交 | 添加 |
| 删除这条灵感 | 删除灵感 |
| 不可恢复 | 此操作无法撤销 |

判断标准：用户看到按钮后，能否立即知道动作对象、结果和风险；无法据此行动的工程词与抽象词不用。

### 6.3 写入方式的选项按上下文命名

汇总的两种写入方式不要用「覆盖原来的 / 存一个新的」这类含糊说法——「原来的」指什么，取决于上下文，用户读不出来。按操作对象直接命名：

| 场景 | 覆盖 | 另存 |
| --- | --- | --- |
| 补充汇总 | 覆盖补充 | 新增补充 |
| 灵感汇总 | 覆盖灵感 | 一个新灵感 |

两个选项**都不预选**，理由见第 4 节 D。

改写的方向：**只说用户此刻需要知道的那一件事**。列表顺序不用说，缓存机制不用说，功能是否互相影响不用说。

### 6.4 合规红线

以下措辞是规范硬性要求，不是风格偏好：

| 场景 | 必须出现 | 必须不出现 |
| --- | --- | --- |
| 保存失败 | 明确说明没有保存成功 | 任何暗示已保存的措辞 |
| AI 结果 | 「由 AI 生成」「可能不准确」 | 把本地规则结果说成 AI 生成 |
| AI 未启用 | 隐藏整个 AI 区块 | 任何看似 AI 产出的内容、任何调用入口 |
| AI 草案 | 说明确认前不写入 | 让用户以为草案已经是自己的数据 |
| 照片 | 说明仅自己可见、删除时同步清理 | 任何分享、公开、对外展示的入口 |
| 删除失败 | 说明内容未做改动 | 静默失败或提前移除 |
| 热度 | —— | 任何形式的评分、热度、优先级暗示 |

## 8. 把内容带走使用（`add-content-output`）

详情页在原文之后先提供补充输入，再提供「整理内容」和「复制内容」；后者让用户选「仅正文」或「正文与当前补充」。每条补充的「更多」面板提供「复制这条」。成功才提示已复制，失败给出提示；复制文本不带品牌、时间和其他元数据。

整理页先选择当前有效补充与用途模板，再生成可编辑使用稿。未选中的补充不进入稿件；返回选择不自动覆盖稿件，重新生成须在用户修改过稿件时确认，也可返回原稿。使用稿可复制；2000 字以内可「另存为新灵感」，不得静默截断，原记录始终不改。

留档页预览当前正文、时间、现存补充及可回看的修改历史。按钮分为「复制留档文字」与「生成 TXT 文件」；文件生成后才显示「发送 TXT 文件」，由用户再次点击并选择去向。页面说明「文字留档不含照片。带出的小程序外副本不会随原记录删除。」文件生成或发送失败时保留复制入口，不给假成功提示。真实文件发送和系统菜单需真机验收。

个人内容的列表、详情、修改记录与整理留档页不进入微信页面索引；这项配置不等同于访问控制，云端账户隔离仍须独立验收。

## 9. 找回、照片与 AI（2026-09-27 实施）

跨灵感“选材整理”入口位于列表操作区，不依赖 AI。选材页默认全不选，正文/补充分段显示来源摘要、类型和选中顺序；支持搜索与只看已选。选中数量和生成按钮始终可见；生成后可编辑、复制、另存，超长提示不截断。页面提示“未另存的稿件离开后不保留”。返回选材不改稿，重新生成或刷新选材须保护编辑。加载、空素材、无搜索结果与错误分别呈现；旧账户内容不跨会话显示。

列表提供正文/有效补充/标签搜索、全部/有补充/最近七天/已合并筛选以及阶段选择。搜索为空时显示匹配空态和清空入口；读取失败不冒充空列表。每日回顾一天固定一条，跳过当日不替换；开关按账户保存在设备，不发送提醒。

详情保留正文和补充为主操作，整理、复制、分享以及已启用的 AI 按钮两列排布。标签最多五个、每个十二字；阶段为“想法”“整理中”“可使用”。已合并内容提供恢复入口，来源记录缺失时展示不可用状态，不跳转错误目标。

用途模板提供自由稿、社交内容、短视频脚本、工作提纲、行动清单；只增加可编辑结构，原始素材不截断、不扩写事实。模板选项可换行，选择卡片及主要操作占满可用宽度。

照片能力由服务端确认后显示添加按钮，已有照片仍可私有预览。相机/相册选择由用户触发；上传失败显示可重试/放弃的暂存项，文字可独立保存。删除先确认，未获服务端确认前保留记录；已实际删除的文件无法恢复。预览使用自建滑动页，关闭长按菜单，不提供图片分享或保存出口。恢复副本只能查看仍存在且有权限的原文件。

AI 扩展可选择参考补充；汇总至少两条来源。预览显示 AI 风险提示，可编辑和逐条采纳，不自动写入。汇总须明确选择新增或覆盖，灵感覆盖还须明确目标；放弃或离开清空草案。生成失败保留来源，采纳失败保留预览，来源变化要求重新生成。未启用时主页面不显示 AI 操作。

我的页把“使用统计”与“从记录到使用”分开。统计默认关闭；说明只保留当前设备最近三十天动作次数、不含内容、不自动上传，关闭即清空。查看/复制由用户主动触发，不等同发送给维护者。

所有按钮保留至少 88rpx 点击高度。开发者工具的小屏截图用于布局检查，键盘顶起、系统大字号和读屏仍须真机验收。证据见 VERIFICATION.md。

三条与页面有关的边界，容易在改动时踩坏：

- **`pages/shared` 是唯一的对外页面。** 必须独立只读渲染，不能复用所有者详情页，也不能出现编辑入口、照片、昵称或账户身份。分享页禁止页面索引，但**访问控制靠令牌校验，索引配置不算权限**。
- **私人工作页一律不进微信页面索引**：列表、详情、修改记录、整理留档、选材整理、AI 工作台、照片查看、分享预览、我的分享、意见反馈。索引配置不代替账户隔离，两者分别验收。
- **`pages/welcome` 是公共入口**，不携带 `accountKey`、OpenID 或私人查询参数。
