# 界面设计

> 状态（2026-09-22）：本文档描述 `add-inspiration-mvp` 四个页面的区块划分、元素构成与状态呈现。
> 本文档只解决「页面长什么样、空态/加载态/失败态各显示什么」，不重复描述需求与验收标准。
> **热度提炼已暂缓**，四个页面均不含热度展示位。WXML/WXSS 的真实编译与渲染必须在微信开发者工具中确认，本文档不代替真机验收。

## 1. 全局约定

**样式令牌**（沿用 `miniprogram/app.wxss`，不新增令牌）

| 用途 | 值 |
| --- | --- |
| 页面底色 | `#f7f7fa` |
| 正文文字 | `#1f1f27` |
| 次要文字 | `#6b6b76` |
| 更淡文字 / 占位符 | `#a8a8b3` |
| 主色（按钮、选中态） | `#3d3d8f` |
| 卡片 | 白底、圆角 `20rpx`、内边距 `32rpx`、间距 `24rpx` |
| 主按钮 | `.button-primary`，圆角 `16rpx` |

**提示方式**：分两类，不能混用。

- **页面内联提示**——用于用户会据此误判数据状态的场景（保存失败、同步失败、删除失败、上传失败）。`wx.showToast` 会自动消失，用户错过之后会以为已经成功，所以这类提示必须常驻在页面上，直到状态改变。
- **轻提示 `wx.showToast`**——仅用于已确定成功、无需用户处理的正向反馈（如「已保存」）。

**三态覆盖**：每个页面、每个异步数据区都必须写出**空态、加载态、失败态**三种呈现。骨架版本里只写了正常态的占位，这是 AI 实现时最容易漏的部分。

**实现约定**：

- 页面 `.wxss` 只放该页独有样式，通用样式一律加进 `app.wxss`。
- 所有可点击元素的 `disabled` 状态必须有视觉区分，不能只靠逻辑拦截。
- 按钮文案在异步过程中要改变（如「保存」→「保存中…」），不能静默等待。

## 2. 记录页 `pages/capture`

Tab 首页，冷启动默认落地页。设计目标：**一次输入 + 一次点击完成记录**。

### 区块

| 区块 | 内容 |
| --- | --- |
| A 标题区 | 标题「记下这一句」，副标题「先写下来，之后可以随时补充、拍照，再让 AI 帮你展开。」 |
| B 输入卡片 | `textarea`（`maxlength` 取 `LIMITS.textMaxLength`，`auto-height`）+ 右下角字数计数器 + 全宽主按钮「保存」 |

**移除**骨架版本中的 `.placeholder` 说明块——它属于工程说明，不应出现在产品界面。

### 状态

| 状态 | 呈现 |
| --- | --- |
| 空态 | 占位符「此刻想到什么？」。计数器显示 `0 / 2000`。保存按钮 **disabled**（置灰） |
| 输入中 | 计数器实时更新。超过上限 90% 时计数器转为警示色 |
| 保存中 | 按钮文案「保存中…」且 disabled，`textarea` 设为只读 |
| 保存成功 | 清空输入，计数器归零，按钮恢复「保存」并回到 disabled。轻提示「已保存」 |
| 保存失败 | **输入内容原样保留**，卡片内出现红色内联提示「尚未保存成功，内容已保留，可重试」。按钮恢复可点 |

失败态是这一页的关键：规范要求「不报告虚假的保存成功」，因此失败时既不能清空输入，也不能用会自动消失的 toast。

超过正文上限时，`maxlength` 由 `textarea` 原生阻止继续输入，同时计数器提示上限——**不得静默截断用户已写的内容**。

## 3. 灵感列表页 `pages/list`

Tab 第二项。

### 区块

| 区块 | 内容 |
| --- | --- |
| A 标题区 | 标题「我的灵感」，副标题「按最近更新时间倒序排列。」 |
| B 列表 | 每项一张卡片 |
| C 底部 | 主按钮「去记一条」，跳转记录页 |

### 列表项元素

| 元素 | 说明 |
| --- | --- |
| 正文首行 | 最多显示 2 行，超出用省略号。取 `text` 的首行 |
| 更新时间 | 相对时间（如「3 小时前」），取 `updatedAt` |
| 补充条数 | 仅当 `supplements.length > 0` 时显示，形如「3 条补充」 |
| 照片数量 | 仅当 `photos.length > 0` 时显示 |
| 同步状态标记 | 仅在该条处于 `dirty / sync_failed / conflict / deleting` 时显示小标记 |

**不出现**热度分数或理由。**不出现**「已删除」的条目——处于 `deleting` 态的条目仍要显示并标注「删除中」，因为此时云端尚未确认。

### 状态

| 状态 | 呈现 |
| --- | --- |
| 空态 | `.placeholder` 区块：「这里还没有灵感。先记下第一句吧。」 |
| 加载态 | 列表区显示「加载中…」占位；已有缓存数据时直接渲染缓存，不阻塞 |
| 失败态 | 内联提示「读取失败」+ 「重试」按钮。**已缓存的内容继续显示**，不能因为刷新失败就清空 |

排序始终按 `updatedAt` 倒序，最近有补充的排在最前。本机有新变更但未同步的条目，仍按本机的 `updatedAt` 排序——用户看到的顺序应符合他刚才的操作。

## 4. 灵感详情页 `pages/detail`

由列表页点击进入，`query.id` 传入灵感标识。骨架版本目前只显示 `id`，需整体重做。

### 区块

| 区块 | 内容 |
| --- | --- |
| A 原文卡片 | 原始正文，**只读展示** |
| B 补充时间线 | 按时间**正序**排列的补充条目 + 「追加补充」输入区 |
| C 照片区 | 图片网格 + 「拍照」/「从相册选择」入口 |
| D AI 扩展区 | 入口按钮 + 草案面板（仅当 `ai.js` 的 `enabled` 为 true 时可调用） |
| E 删除 | 底部次要样式按钮「删除这条灵感」 |

### A 原文卡片

正文完整展示，不截断。区块内提供「我想补充」按钮而不是可编辑的输入框——规范明确要求引导用户改为新增补充，而不是改写原文。

### B 补充时间线

每条补充显示：内容、记录时间、来源标记。`source` 为 `'ai'` 的条目**必须**带可见的「AI 生成」标记，且标注「内容可能不准确，请自行判断」。

追加补充输入区位于时间线下方，`maxlength` 取 `LIMITS.supplementMaxLength`。提交失败时保留输入并内联提示，与记录页同规则。

状态：

| 状态 | 呈现 |
| --- | --- |
| 无补充 | 时间线区显示「还没有补充」 |
| 提交中 | 按钮「提交中…」且 disabled |
| 提交失败 | 输入保留 + 内联失败提示 + 可重试 |
| 内容为空 | 按钮 disabled，不发请求。规范要求空补充不写入、也不改变更新时间 |

### C 照片区

网格布局，每张图带独立状态角标：

| 照片状态 | 角标呈现 |
| --- | --- |
| `uploading` | 「上传中…」遮罩 |
| `upload_failed` | 「上传失败，点击重试」+ 可点击 |
| `uploaded` | 无角标 |
| `rejected` | 不进入网格，以提示条说明「该图超过 2 MB，已跳过」 |

达到 `LIMITS.photosPerInspiration`（9 张）后，添加入口变为 disabled 并说明「最多 9 张」。

状态：空态显示「还没有照片」；权限被拒时**不读取任何图片**，显示内联说明与开启指引，且不影响本页其余区块。

### D AI 扩展区

未启用时（`ai.js` 的 `enabled` 为 `false`）：显示说明文案「AI 扩展尚未开放」，**不展示**可点击的调用入口，也不展示任何看起来像 AI 结果的本地内容。

启用时的草案面板：

- 三个分区展示：要点 / 下一步 / 风险，每项前带采纳勾选框；
- 顶部固定标注「以下内容由 AI 生成，可能不准确，请自行判断」；
- 每项支持行内修改后采纳；
- 底部两个操作：「采纳所选」与「放弃」。

草案面板的所有状态都是**页面内存态**：关闭、返回、杀进程后不保留，重新进入不得出现半成品。

### E 删除

点击后二次确认（`wx.showModal`），确认后进入 `deleting` 态：

- 页面顶部出现内联提示「删除中…」，条目保持可见；
- 成功后返回列表页并移除该条；
- 失败后**全部保留**，内联提示「删除失败，内容未做改动」+ 可重试。

不得在云端确认前从本机移除，否则会出现「本机已删、云端还在」的状态。

## 5. 我的页 `pages/mine`

Tab 第三项。骨架版本已有结构良好，按下表调整文案与区块即可。

### 区块

| 区块 | 内容 |
| --- | --- |
| A 能力状态 | 云端同步 / AI 扩展 两行状态，取 `app.globalData` |
| B 数据与隐私 | 数据存放说明 + 照片用途说明 |
| C 使用帮助与反馈 | `open-type="feedback"` 按钮 |

### 文案要求

- **照片用途**必须单独说明：照片仅用于用户自己查看，不上传至任何对外展示场景、不写入日志、删除灵感时同步清理云端文件。
- **不得出现热度相关文案**。也不得用「优先级评分」「推荐指数」等别的名字暗示存在评分功能——热度已暂缓，此处暗示即为不实陈述。
- 能力状态区块的说明文案需要更新：当前写的是「骨架版本两项均为未启用」，实现后应按真实开关状态动态生成，且仍需说明「启用需先完成授权与验收，不能通过直接改开关生效」。

## 6. 文案与合规红线

实现这一版界面时，以下措辞是规范硬性要求，不是风格偏好：

| 场景 | 必须出现 | 必须不出现 |
| --- | --- | --- |
| 保存失败 | 明确说明「尚未保存成功」 | 任何暗示已保存的措辞 |
| AI 结果 | 「由 AI 生成」「可能不准确」「请自行判断」 | 把本地规则结果说成 AI 生成 |
| AI 未启用 | 说明尚未开放 | 任何看似 AI 产出的内容 |
| 照片 | 说明仅自己可见、删除时同步清理 | 任何分享、公开、对外展示的入口 |
| 删除失败 | 说明内容未做改动 | 静默失败或提前移除 |
| 热度 | —— | 任何形式的评分、热度、优先级暗示 |
