**视觉原则**（决定了上面这些值怎么用）

1. **原文是锚点。** 详情页的原始正文**不放进卡片**，直接落在页面底色上，用全页最大的字号（`38rpx` / 行高 1.78）。其余所有内容都从属于它。
2. **层级用留白和分隔线做，不用阴影。** 列表是连续承载面加发丝分隔线，不是一张张浮起的卡片。全页只有手机外框带阴影（那是原型的容器，不是产品的一部分）。
3. **草案是临时的。** AI 草案用虚线描边、浅底、并显式标注「尚未写入」。这不是装饰——它把规范里「确认前不得写入用户数据」这条规则变成了看得见的信息。
4. **同步状态只在异常时出现。** 正常同步的条目不带任何标记，避免每一条都挂一个无意义的徽标。
5. **承载面用在真正需要「一整块内容」的地方**（列表、隐私说明、草案），不滥用卡片把页面切成一格一格。

**可视化参考**：品牌图形见 `assets/branding/miniprogram-avatar-144.png`；交互原型见 `docs/ui-mockup.html`。

**当前界面截图**见 `docs/evidence-development-20260928/`（14 张，2026-09-28 由开发者工具离线样例工程逐页截取）。这批图证明的是当前代码在**模拟器**里的静态呈现，**不是真机**，也不覆盖分享创建、海报、AI 生成等需要云端能力的路径；边界见 `VERIFICATION.md` 当日小节。更早的 `docs/evidence-development-20260927/` 与 `docs/audits/2026-09-23-product-optimization/` 对应的是当时的界面，**已不代表现状**，只作为历史记录保留。

原型只用于对齐布局与交互，不是可运行的小程序；当前页面以 WXML / WXSS 为准，真实编译与渲染仍需在微信开发者工具中确认。

**提示方式**：分两类，不能混用。

- **页面内联提示**——用于用户会据此误判数据状态的场景（保存失败、同步失败、删除失败、上传失败）。`wx.showToast` 会自动消失，用户错过之后会以为已经成功，所以这类提示必须常驻在页面上，直到状态改变。
- **轻提示 `wx.showToast`**——仅用于已确定成功、无需用户处理的正向反馈（如补充添加后的「已添加补充」）。

**状态图标按形状区分语义**（2026-09-30 补）：成功 `✓`、警示 `!`、失败 `✕`，三种**形状不同**，颜色只是辅助。不允许三种状态共用一个图标、只靠底色区分——灰度或色觉障碍下也必须能分辨。成功提示用主色系（`#eeeef8` 底 + `#34377f` 字），**不用点睛色**：琥珀是品牌图形的专属信号，成功染成琥珀会读起来像警告，而「记下了」这一刻不该带不确定感。

**三态覆盖**：每个页面、每个异步数据区都必须写出**空态、加载态、失败态**三种呈现。骨架版本里只写了正常态的占位，这是 AI 实现时最容易漏的部分。

**实现约定**：

- 页面 `.wxss` 只放该页独有样式，通用样式一律加进 `app.wxss`。遮罩、底部面板（`.mask`/`.sheet`/`.sheet-item`）、确认框（`.dialog*`）与面板动作行（`.panel-acts`）已是全站共用组件（2026-09-30 从详情页提升），列表筛选、详情「更多」、整理页三个面板共用同一套。
- **给 `<button>` 写宽度或左右外边距，必须用两层选择器**（2026-09-30 补）。小程序 `button` 的默认样式带固定宽度和左右 `auto` 外边距，**单类选择器盖不住它**。`app.wxss` 已用 `.page button`（外加 `.welcome-page button`、`.viewer button`）统一复位，只复位宽度与左右外边距、不动上下外边距；页面要通栏或特定宽度时用 `.page .btn-block`、`.sheet .sheet-item`、`.notice-acts .btn` 这类两层选择器覆盖。不这样做的话改了不生效、而且不报错——列表页的「记一条」和详情页的「更多」曾因此离右边距有 80px 空档，操作面板的条目也缩成过一条居中的窄列。
- 三个 tab 使用同一套 81px 线性 PNG 图标，选中态统一为主色；源文件由 `scripts/build-tab-icons.ps1` 生成。
- 所有可点击元素的 `disabled` 状态必须有视觉区分，不能只靠逻辑拦截。
- 按钮文案在异步过程中要改变（如「保存」→「保存中…」），不能静默等待。

**导航栏标题**（2026-09-22 补。此前没规定过，结果原型与代码各写各的，分叉了一次）：

| 页面 | 导航栏标题 | 理由 |
| --- | --- | --- |
| 三个 tab 页（记录 / 灵感 / 我的） | **小程序名「灵感拾光簿」** | tab 栏已经标了区块名，导航栏再重复一遍是冗余。改用小程序名，让人随时能确认打开的是哪个小程序；页面功能由**页内标题**承担（「记录想法」「我的灵感」「我的」） |
| 二级页 | 功能名：「灵感详情」「修改记录」「整理成稿」「选材成稿」「整理想法」「查看照片」「分享文字」「查看分享」「我的分享」「意见反馈」「分享小程序」 | 它们没有 tab 标签，导航栏必须回答「我在哪」 |

**排查「标题没变」时先看页面自己的 json**：`app.json` 的 `window.navigationBarTitleText` 只是**全局默认值**，任何页面在 `pages/*/index.json` 里设了自己的标题就会把它盖掉。改全局值不影响这些页面——这是这次踩到的坑。

## 2. 记录页 `pages/capture`

Tab 首页，冷启动默认落地页。设计目标：**一次输入 + 一次点击完成记录**。

### 区块

| 区块 | 内容 |
| --- | --- |
| A 标题区 | 52px品牌图形与品牌小字，价值标题「记下一闪念，整理成可用稿」，说明「先写一句。需要时，把零散想法整理成能直接使用的文字。」 |
| B 输入卡片 | 常驻标签「此刻的想法」+160px原生输入（`maxlength="-1"`，保留全文，提交层校验）+计数与未保存提示+主按钮「记下来」；成功后输入区仍可见，主按钮改为「再记一条」，下方显示紧凑的上一条反馈 |

**移除**骨架版本中的 `.placeholder` 说明块——它属于工程说明，不应出现在产品界面。

### 状态

| 状态 | 呈现 |
| --- | --- |
| 空态 | 占位符「此刻想到什么？」。计数器显示 `0 / 2000`。保存按钮 **disabled**（置灰）。**不放示例行**（2026-09-30 用户决定去掉——引导由占位符承担） |
| 输入中（未提交） | 计数器实时更新；非空时一行小字「尚未保存，退出后可能丢失。」；超过上限 90% 计数器转警示色。粘贴超过 2000 字符时**保留全文**，显示「超出 N 字符，请缩短后保存。」并禁用保存——不静默截断 |
| 保存中 | 按钮「正在记下…」，辅助文字「正在保存，请稍候。」，`textarea` 只读；本次提交内容冻结，禁止重复提交 |
| 保存成功 | 清空输入并撤回焦点，保留原生输入区。主操作「再记一条」点击请求焦点，也可直接点击输入框写下一条。按钮下方以紧凑提示显示「上一条已记下」、一行摘录和轻量「继续补充 / 整理这条」；开始新输入时清除旧反馈。整理只导航当前账户已确认lastSavedId；不自动跳页 |
| 结果未知（超时、连接中断等） | **输入原样保留**。标题「尚未确认保存」，说明「内容还在输入框中。退出前请重试保存或复制内容。」，动作「重试保存」与「复制内容」。重试复用同一记录标识，不产生第二条；复制只在用户点击后执行，成功/失败都给常驻小字 |
| 确认被拒绝（有确定回执） | 标题「未能保存」，说明按已知原因给出。**没有确定回执时不得编造原因** |
| 账户读取失败 | 输入仍在当前页面；不展示之前账户的列表，提示联网重试 |

没有云端确认就不清空输入；只有成功确认后才显示「已记下」。网络类失败（`NETWORK`/`INTERNAL`）属于**结果未知**，不能用「确定没保存」的口吻；「尚未保存」与「尚未确认保存」是两种状态，不同时出现。

**写了一半离开**（2026-09-30 补）：输入非空且未提交时用 `wx.enableAlertBeforeUnload` 提示一次「尚未保存的内容会丢失。」；提交中与结果未知时不开启该提示——那时输入框上已有「正在保存」或「尚未确认保存」的常驻状态，再叠一层返回询问只会让人误以为内容丢了。输入清空或保存成功后解除。这是**提示**，不是暂存——产品仍然不建本机草稿（见 `cloud-confirmed-saves`）。「随手记」被打断是常见情境，而输入只在会话内存里，这是把损失说清楚的最低成本做法。

失败态是这一页的关键：规范要求「不报告虚假的保存成功」，因此失败时既不能清空输入，也不能用会自动消失的 toast。

超过正文上限时**不得静默截断**：输入层完整接收粘贴内容，计数器显示实际长度/超出差额，保存按钮置灰并在计数器旁写明「超出 N 字符，请缩短后保存。」；提交层继续遵守 2000 上限。

2026-10-08 录入焦点修复：原生输入框获得焦点时保持 `inputFocus=true`，在 `bindblur` 和页面隐藏时复位为 `false`。普通进入不请求键盘；「再记一条」请求焦点后，聚焦事件不得立即撤回。仅提交中的 `saving` 禁用输入，聚焦、失焦不修改草稿或保存状态。

## 3. 灵感列表页 `pages/list`

Tab 第二项。

### 区块

| 区块 | 内容 |
| --- | --- |
| A 标题区 | 标题「我的灵感」，右上角「记一条灵感」固定 88rpx 热区、不换行。**不写副标题**——排序是产品行为，不需要向用户报备实现方式 |
| B 工具区 | **只在有记录时出现**（有效记录 + 已合并记录 > 0）。搜索框（匹配正文、有效补充与标签，至多 100 字；内置「清空搜索」只清搜索词）＋默认筛选行「全部 / 有补充 / 筛选」。七天内、阶段、已合并都在**筛选面板**里，有生效条件时 chip 显示「筛选·N」（N 只统计面板内条件，不含搜索词） |
| C 段落头 | 左侧「最近更新 · 共 N 条」，右侧是整份列表动作：「选材成稿」，以及 `aiEnabled` 为真时的「AI 汇总」。不展示不可用动作 |
| D 列表 | 连续承载面 + 发丝分隔线，**不是一张张浮起的卡片**。整行可点，行内不重复「查看」按钮 |
| E 回顾行 | 「回看一个想法」轻量一行（96rpx），**串在第一条记录之后**；点击才展开一条正文预览与「继续补充 / 本次先不看」 |

**空数据时不渲染工具区与段落头**（2026-09-30 补）。搜索、筛选、选材成稿在没有任何记录时都没有作用对象。空态下页面只有三个元素：标题行、空态卡、「记下第一个想法」。

**真空态只认「有效记录与已合并记录都为 0、且读取成功」。** 仅剩已合并内容时，工具区与筛选入口必须保留，并显示可从筛选查看已合并内容的提示——不能用默认列表为空来决定隐藏入口（2026-09-30 补）。

**回顾不再是首屏的大色卡**（2026-09-30 补）。入口设为第一条真实记录之后的轻量一行，默认不展开、不自动弹出；「本次先不看」只在当前会话隐藏，重新启动后按默认规则恢复，不承诺「今天不再显示」。列表不足两条时不占位，不留空容器。

**列表页没有「每日回顾」开关**（2026-09-30 补）。开关在「我的」里，列表只保留上面的回顾行。

开始记录的主入口固定在标题区，避免长列表底部难以触达。

### 列表项元素

| 元素 | 说明 |
| --- | --- |
| 正文首行 | 最多显示 2 行，超出用省略号。取 `text` 的首行 |
| 更新时间 | 相对时间（如「3 小时前」），取 `updatedAt`。分桶阈值见 `detailed-design.md` §7.8——**按经过时间分桶，不做日历日运算**，「昨天」按 24—48 小时计 |
| 补充条数 | 仅统计时间线上当前有效的补充，不把已并入正文或已合并的补充算进去；有补充时显示「2 条补充」 |
| 标签与阶段 | 默认阶段「想法」不单独占行；非默认阶段与「已合并」才显示。标签最多显示 2 个，超出写「+N」；完整信息进详情查看 |
| 停留位置 | 同账户、同筛选从详情返回时保留查询与滚动位置；内容更新导致重排时以离开时点击的记录定位，目标被删除则落到原偏移。账户变化立即清空查询、筛选与旧内容 |
| 照片数量 | 当前列表不展示，照片细节留在详情页；照片功能未接通时不得用数字暗示可用 |
| 保存状态 | 仅展示云端已确认的记录；未确认的修改留在操作页，不在列表生成待同步条目 |

### A 原文区

正文完整展示，不截断。**可以直接编辑**——点进去改，保存后生效。

> 2026-09-22 修订。初稿把这里做成只读，只给「我想补充」，依据是当时那条「原文不可改写」的规范。该约束已撤销：用户记下一句话、过了两天发现写偏了，他需要的是**把那句话改对**，而不是在下面追加一条「更正：上面那句应该写成……」。逼他用追加来绕，时间线会变成一叠补丁，而他真正想留下的那句话反而停在最初那个不准确的版本上。

改写保存后，「更多」面板出现**「修改记录（N）」入口**（仅在确实存在记录时出现），点开按时间倒序列出历次旧内容，各自标明修改时间。

- 历史条目**只读**，不提供恢复、编辑或删除入口——它是记录，不是草稿。
- 历史**没有删除入口**。这是产品承诺「你说过的话不会被悄悄抹掉」的界面体现。
- 入口本身不强调；数量直接写在文字中，不使用醒目的徽标。

编辑正文时与其他文本输入同规则：清空不保存、超长拒绝且不截断、失败时保留输入并内联提示；提交按钮写「保存修改 / 保存中…」，取消恢复进入前的文字。

**修改记录页**（点「查看修改记录」进入）：

| 项 | 呈现 |
| --- | --- |
| 顺序 | 按修改时间**倒序**，最近一次修改前的内容在最上 |
| 每条 | 「修改于 MM-DD HH:mm」+ 旧内容。用开放时间线呈现，视觉上比当前内容弱一档 |
| 当前原文 | 固定在列表**上方**，用白底面板标出「当前内容」——先让用户确认现在是什么，再回看旧版本 |
| 操作 | **只读。没有编辑入口，也没有删除入口。** |
| 没有历史时 | 「还没有修改记录」＋说明「正文还没有改过。修改后，旧内容会保留在这里。」＋「返回这条灵感」按钮；对象缺失时改「找不到这条灵感」并给「返回灵感列表」，读取失败显示「暂时无法读取灵感 / 重新读取」。不能只留一句「共 0 条修改记录」让用户对着空白页猜 |

**没有删除入口是刻意的。** 这是产品承诺「你说过的话不会被悄悄抹掉」的界面体现——如果历史能删，那个承诺就只剩下前半句。

### E 补充时间线

每条补充显示：内容、记录时间、来源标记。`source` 为 `'ai'` 的条目**必须**带可见的「AI 生成」标记，且标注「内容可能不准确，请自行判断」。

追加补充输入区紧随原文与轻量动作、位于时间线上方。输入层 `maxlength="-1"` 完整接收、上限（1000）在提交层校验，超出时提示「超出 N 字符，请缩短后保存。」并禁用提交。固定两档高度：空且未聚焦 64px，聚焦后 160px，失焦且有内容保持 160px，清空并失焦后回到 64px；`auto-height` 关闭，多余文字在输入框内部滚动。提交失败时保留输入并内联提示，与记录页同规则；成功后以「已添加补充」轻提示确认。修改原文时暂不展示补充输入区，避免同时编辑两处。

状态：

| 状态 | 呈现 |
| --- | --- |
| 无补充 | 时间线区显示「还没有补充，可以从上方写下一句。」；只读或已合并状态不显示此引导 |
| 提交中 | 按钮「添加中…」且 disabled |
| 提交失败 | 输入保留 + 内联失败提示 + 可重试 |
| 内容为空 | 按钮 disabled，不发请求。规范要求空补充不写入、也不改变更新时间 |

**选择态与汇总**（2026-09-22 新增，「AI 汇总」能力）：

- 时间线附近提供「选择」入口，进入后每条补充前出现勾选框。
- 选中**两条以上**时底部浮出「汇总」按钮；只选一条时按钮置灰并说明「至少选两条」。**不得在数量不足时发起调用**——那会白白消耗额度。
- 汇总结果以**草案面板**呈现，与 AI 扩展共用同一种视觉（虚线描边 + 浅底 + 「未写入」），并在面板内要求用户**显式选择**「覆盖补充」还是「新增补充」。**没有默认值**——这是整条链路上不可逆程度最高的一步，不能替用户预选。
- 选「覆盖补充」时，被汇总的补充在时间线上**默认收起**；选「新增补充」时，被汇总的补充**完全不动**，仍独立可见。

**已合并补充的呈现**：

| 项 | 呈现 |
| --- | --- |
| 收起态 | 一行摘要 +「展开」，位置留在时间线上原处。**两种收起的措辞必须不同**：被 AI 汇总的写「N 条已合并」，被并入正文的写「1 条已并入灵感」——只写「合并」两个字，用户分不清并到哪去了 |
| 展开态 | 逐条展示原内容与记录时间，每条带「恢复」操作 |
| 恢复后 | 该条回到时间线上的原位置（仍按时间排序），汇总结果与原文均不受影响，两者并存 |

**不能没有入口。** 已合并的内容只是默认收起，不是被隐藏。如果界面上没有任何地方能看到和恢复它们，那和删除没有区别——而规范明确要求它们可查看、可恢复。

**补充操作面板**（2026-09-22 新增，后续补充可发现性整改）：

| 选项 | 说明文字 | 后果 |
| --- | --- | --- |
| 复制补充 | —— | 复制这条补充的文字；失败不给假成功 |
| 修改补充 | 「旧内容会保留在修改记录中」 | 进入编辑态，改完「保存修改」；旧内容进历史，可回看 |
| 并入正文 | 「把这条补充追加到正文末尾」 | 本条收起，可展开恢复 |
| 删除补充 | 「此操作无法撤销」 | 再弹一次确认 |

已收起（已合并或已并入）的补充不提供修改与并入，只提供「恢复为补充」与「删除补充」。

视觉与交互约束：

- 每条补充提供可见的「更多」按钮；长按保留为快捷方式，但不得作为唯一入口。
- **面板标题标明操作对象**，用「这条补充 · 昨天 21:40」这样的定位，**不要直接把内容截断成一句引用**——那样引用句孤零零浮着，用户看不出它跟哪个操作有关联。
- **主标签与说明文字分行**（2026-09-30 补）：说明另起一行、左对齐放在主标签下方。曾经用 `flex` + `space-between` 把说明排在右侧，长说明会把主标签挤成逐字换行（「修」/「改」各占一行）。
- **「删除」用危险色，且与另外两项在视觉上分开。** 不能和「修改」长得一样、紧挨着排——长按是容易误触的手势。
- **点「删除」必须再弹一次确认**，明确写出「此操作无法撤销」。一次点击就删掉用户写下的东西，是不可接受的。
- **确认弹窗要把待删内容放进一个带时间的框里**，正文写「确定删除这条补充吗？此操作无法撤销。」，框里是内容本身与它的记录时间（摘录最多 4 行）。删除灵感同规则：标题「删除灵感」，正文「确定删除这条灵感吗？正文、补充和照片会一并删除。」+ 摘录与时间。这样「要删的就是这条」这件事才是连着的，而不是两句不相干的文字摆在一起。
- 「并入正文」旁要写清后果——用户需要知道这一步到底做了什么，而不是只看到一个词。
- 已合并或已并入灵感的补充，操作面板里**不提供「修改」**，只提供「恢复」与「删除」。它们已经不在时间线上正常显示，先恢复再改，用户才看得清自己在改什么。
- **「合并」在本产品里有两个用法，界面必须让目标可分辨**：操作面板的「并入正文」写入的是**灵感正文**；AI 汇总的「覆盖补充 / 覆盖灵感」写入的是**汇总结果**。完整对照见 `specs/inspiration-capture/spec.md`。

### AI 草案面板（`pages/ai-workbench`）

> 2026-09-28 修订：草案面板已从详情页迁到独立页面 `pages/ai-workbench`，详情页只留入口。下面的面板设计仍然有效，只是呈现位置变了。

承载两个动作：**扩展**（把一句话展开成结构化草案）与**汇总**（把多条补充收成一条）。两者共用同一种草案面板视觉，不各自发明一套。

2026-10-02 用户授权打开客户端入口。详情显示「AI 扩展想法」「AI 汇总补充」，已收起的灵感隐藏写入入口；列表有效灵感至少两条时显示「AI 汇总」。客户端关闭时隐藏这些入口，直达工作台只显示「暂时无法使用此功能」和返回列表。服务端不可用时保留素材、显示失败说明与手动整理出口。

照片区同理：服务端未确认照片能力时不渲染空壳区块。

启用时，**扩展**的草案面板：

- 三个分区展示：要点 / 下一步 / 风险，每项前带采纳勾选框；
- **视觉上明确「尚未成为你的数据」**：虚线描边 + 浅底，左上角标注「未写入」；
- 顶部标注「由 AI 生成，可能不准确。勾选后才会写进这条灵感，没勾的会被丢弃。」；
- 每项支持行内修改后采纳；
- 底部固定操作区显示「复制所选」「保存所选 N 条」，长预览滚动时仍可访问；另设「重新选择素材」和返回，离开未保存预览须确认。

**汇总**的草案面板：

- 单段文本，不分区——汇总的产物是一条连续的内容，不是分析结果；
- 同样标注「未写入」与「由 AI 生成，可能不准确」；
- 默认「新增一条补充」或「保存为新灵感」，继续保留来源；另一项说明写回和收起来源。写回灵感须明确选择目标，保存前确认收起后果；
- 底部固定操作：「复制正文」「确认保存」；未知时主按钮为「重试确认保存」；
- AI 补充汇总与灵感汇总均显示保存上限 2000 字，普通手工补充为 1000 字；超过目标上限保留全文、提示缩短、禁用保存，复制仍可用；
- 在「覆盖」选项旁用一句小字说明后果：「被合并的内容会收起，之后可以展开恢复。」——用户需要知道这一步到底做了什么，而不是只看到一个词。

草案面板的所有状态都是**页面内存态**：关闭、返回、杀进程后不保留，重新进入不得出现半成品。

本轮以「选择素材 → 核对与保存 → 已保存」标示阶段；原文与选择项分层、字数和数量常驻、输入正文至少 16px，辅助文字至少 13px，按钮至少 44px。保存中及结果未知时禁用预览编辑、勾选、模式与目标变化；未知结果可复制或重试。成功提供「查看已保存内容」「返回灵感列表」。读取失败与 AI 暂不可用分别呈现。详见 `AI-EXPERIENCE-20261002.md`，真实模型和真机证据仍待补。

### H 删除

入口在「更多」面板的危险组。点击后拉出**带摘录的自定义确认框**（与补充删除共用同一组件），确认后进入删除中的界面状态：

- 确认按钮显示「删除中…」并禁用其余写操作；
- 成功后返回列表页并移除该条；
- 失败后**全部保留**，内联提示「删除未完成，记录仍在，请稍后重试。」；用户可再次点击删除。

不得在云端确认前从会话视图移除，否则会出现「页面已删、云端还在」的状态。

## 6. 文案基调与合规红线

### 6.1 基调

**短句，陈述事实。不推销、不解释架构、不辩解、不罗列功能。**

这个产品是一个人的私人灵感本，界面文案应该像一个安静好用的工具，而不是一个急着证明自己的 App。以下七类写法一律禁止：

| 禁止 | 反例（曾出现在原型里） | 问题 |
| --- | --- | --- |
| 功能罗列当卖点 | 「先写下来，之后可以随时补充、拍照，再让 AI 帮你展开」 | 像广告语；且在 AI 默认关闭时承诺 AI 能力，属不实描述 |
| 把内部实现讲给用户 | 「按最近更新时间倒序排列」 | 排序是产品行为，不需要向用户报备实现方式 |
| 把工程流程暴露给用户 | 「两项均需先完成资源创建授权、部署与验收，不能通过直接改开关生效」 | 这是开发者的话，用户不关心也不该看到 |
| 把规范条款抄成界面文案 | 「记录、补充、拍照与浏览不受影响」 | 功能矩阵不是文案；用户只会困惑为什么突然提这个 |
| 技术名词直出 | 「不上传至任何对外展示场景、不写入日志」 | 「写入日志」对用户没有意义，是工程保证而非用户语言 |
| 过度解释与辩解 | 「已跳过，其余图片不受影响」 | 后半句是在替自己开脱；把事实说清楚就够了 |
| 推销口吻 | 「让 AI 帮你展开」 | 与「不得夸大 AI 效果」的规范冲突 |
| **开发脚手架漏进产品** | 「工程骨架版本尚未实现」「详细范围见 openspec/…/proposal.md」「启用需先完成资源创建授权、部署与验收」 | 这些是写给开发者自己的，使用者看到只会觉得产品没做完、或者被内部流程打扰 |

最后一条单独强调：**开发期的进度说明、提案路径、授权流程、任务编号，一律不得出现在任何面向使用者的位置**，包括页面文案、按钮提示、toast、以及会进包的日志。它们属于代码注释，不属于产品。
（`console.info` 这类纯开发者日志可以保留诊断信息，但不要写「骨架版本」「尚未实现」这类带开发阶段判断的话。）

### 6.2 使用自然、明确的动作语言（2026-09-22 修订）

界面是个人工具，按钮既不能像内部表单，也不需要写成规章。动作名称直接说明用户正在做什么，并与页面语境一致：

| 原措辞 | 改为 |
| --- | --- |
| 新建灵感 | 记一条灵感（空态另有「记下第一个想法」） |
| 提交 | 添加 |
| 删除这条灵感（**标签位置**） | 删除灵感 |
| 不可恢复 | 此操作无法撤销 |

删除确认句是唯一的例外：`确定删除这条灵感吗？正文、补充和照片会一并删除。` / `确定删除这条补充吗？` 必须把待删对象说清楚（UX-COPY C38）。守卫（`tests/copy-rules.test.cjs`）按「标签形态」拦截，确认句不在此列。

判断标准：用户看到按钮后，能否立即知道动作对象、结果和风险；无法据此行动的工程词与抽象词不用。

### 6.3 写入方式的选项按上下文命名

汇总的两种写入方式不要用「覆盖原来的 / 存一个新的」这类含糊说法——「原来的」指什么，取决于上下文，用户读不出来。按操作对象直接命名：

| 场景 | 覆盖 | 另存 |
| --- | --- | --- |
| 补充汇总 | 覆盖补充 | 新增补充 |
| 灵感汇总 | 覆盖灵感 | 一个新灵感 |

两个选项**都不预选**，理由见第 4 节 D。

改写的方向：**只说用户此刻需要知道的那一件事**。列表顺序不用说，缓存机制不用说，功能是否互相影响不用说。

### 6.4 合规红线

以下措辞是规范硬性要求，不是风格偏好：

| 场景 | 必须出现 | 必须不出现 |
| --- | --- | --- |
| 保存失败（有确定回执） | 明确说明没有保存成功 | 任何暗示已保存的措辞 |
| 保存结果未知（超时、连接中断） | 「尚未确认保存」＋重试与复制出口，输入仍在 | 宣布确定失败、假装成功，或与「尚未保存」同时出现 |
| AI 结果 | 「由 AI 生成」「可能不准确」 | 把本地规则结果说成 AI 生成 |
| AI 未启用 | 隐藏整个 AI 区块 | 任何看似 AI 产出的内容、任何调用入口 |
| AI 草案 | 说明确认前不写入 | 让用户以为草案已经是自己的数据 |
| 照片 | 说明仅自己可见、删除时同步清理 | 任何分享、公开、对外展示的入口 |
| 删除失败 | 说明内容未做改动 | 静默失败或提前移除 |
| 热度 | —— | 任何形式的评分、热度、优先级暗示 |

## 8. 把内容带走使用（`add-content-output`）

详情页的复制入口在「更多」面板：复制全文（可选「仅复制正文」或「正文与当前补充」）；每条补充的面板提供「复制补充」。成功才提示已复制，失败给出提示；复制文本不带品牌、时间和其他元数据。

整理页（导航与页内标题都是「整理成稿」）**进入即给出一份可编辑的自由稿**，补充默认全选——看结果不必先做选择。工具行是「调整内容 / 选择格式 / 更多」：调整内容时正文固定带入、补充可选，确认按钮「应用选择」；选择格式保留现有五种模板并写明「只整理已有文字，不自动补写。留空的部分可以自己补写。」，确认按钮「应用格式」。面板里的改动先暂存，确认才写回；用户手工改过稿件后再应用，先弹替换确认（「替换当前稿件？」「你修改过这份稿件。替换后，这些修改不会保留。」「保留编辑 / 替换稿件」），取消保留游标与全文。主按钮「复制稿件」；2000 字符以内可「另存为新灵感」，超限只禁另存、不禁复制，并显示「另存最多 2000 字符，当前超出 N 字符。」；同一稿件重复另存不新增第二条，按钮写「已另存」。原记录始终不改，零 AI 调用。

文字留档收进「更多」面板：预览当前正文、时间、现存补充及可回看的修改历史。按钮为「复制留档文字」「生成 TXT 文件」；文件生成后才显示「发送 TXT 文件」，由用户再次点击并选择去向。面板说明「包含正文、补充和修改记录，不含照片。删除原记录后，已复制或导出的文字仍会保留。」文件生成或发送失败时保留复制入口，不给假成功提示。真实文件发送和系统菜单需真机验收。

个人内容的列表、详情、修改记录与整理留档页不进入微信页面索引；这项配置不等同于访问控制，云端账户隔离仍须独立验收。

## 9. 找回、照片与 AI（2026-09-27 实施）

跨灵感“选材成稿”入口位于列表操作区，不依赖 AI。选材页默认全不选，正文/补充分段显示来源摘要、类型和选中顺序；支持搜索与只看已选。生成后可编辑、复制、另存或保存后预览分享，超长提示不截断。本次使用中的中断与稿件恢复按 §14，返回选材不改稿，重新生成或刷新选材须保护编辑。加载、空素材、无搜索结果与错误分别呈现；旧账户内容不跨会话显示。

列表提供正文/有效补充/标签搜索；默认筛选行是全部/有补充/筛选，七天内、阶段、已合并收进筛选面板（有生效条件时 chip 显示「筛选·N」）。搜索为空时显示匹配空态和「清空搜索和筛选」；单项清理分别叫「清空搜索」「重置筛选」；读取失败不冒充空列表。回顾行「回看一个想法」串在第一条记录之后，展开才显示内容；「本次先不看」仅在当前会话生效，不发送提醒。

详情保留正文和补充为主操作：「整理成稿 / 继续补充」一行等宽，低频操作（修改正文、复制全文、分享文字、修改记录、删除）收进「更多」面板。AI 整理为低强调文字入口，汇总补充在更多面板内可达。标签最多五个、每个十二字；阶段为“想法”“整理中”“可使用”。已合并内容提供恢复入口，来源记录缺失时展示不可用状态，不跳转错误目标。

用途模板提供自由稿、社交内容、短视频脚本、工作提纲、行动清单；只增加可编辑结构，原始素材不截断、不扩写事实。模板选项可换行，选择卡片及主要操作占满可用宽度。

照片能力由服务端确认后显示添加按钮，已有照片仍可私有预览。相机/相册选择由用户触发；上传并关联成功才展示图片，确定失败时提示重新选择未添加的照片，不显示暂存、重试或放弃入口，文字输入不清空。关联结果不确定时提示重新打开灵感核对，避免重复添加。删除先确认，未获服务端确认前保留记录；已实际删除的文件无法恢复。预览使用自建滑动页，关闭长按菜单，不提供图片分享或保存出口。**只有一张照片时不提示「左右滑动查看」**（2026-09-30 补）——按不动的提示只会让人以为页面坏了。

AI 扩展可选择参考补充；汇总至少两条来源。预览显示 AI 风险提示，可编辑和逐条采纳，不自动写入。汇总须明确选择新增或覆盖，灵感覆盖还须明确目标；主动放弃清空草案，本次使用中离开/回来按 §14 恢复。生成失败保留来源，采纳失败保留预览，来源变化要求重新生成。未启用时主页面不显示 AI 操作。

我的页现行布局见 §5、§15：品牌头后依次为「一起进步」「数据与支持」卡片。后者的「使用帮助」只展开产品说明；2026-09-30 删除的会话级回顾开关与诊断信息继续隐藏，回顾的会话内控制保留为列表里的「本次先不看」。使用统计服务保留但无界面入口、默认关闭。

所有按钮保留至少 88rpx 点击高度，并用 `max(88rpx, 44px)` 给 44 逻辑像素兜底（2026-09-30 补）；正文不小于 16px、辅助文字不小于 13px 的下限同样以 `max()` 表达。开发者工具的小屏截图用于布局检查，键盘顶起、系统大字号和读屏仍须真机验收。证据见 VERIFICATION.md。

## 11. 启动过渡页 `pages/launch`（2026-09-30 新增）

冷启动读取云端快照（账号确认 + `snapshot.pull`）期间的品牌过渡页，也是小程序的默认入口（`app.json` 第一项）。只做三件事：说明正在读取、展示一次品牌时刻、读完后退出。

- **读完就走。** 不设最短停留时间；快照就绪立即 `switchTab` 到记录页，不为了好看拖延可以开始写的时间。
- **不空转。** 云能力未开启（离线样例、旧基础库）时不等待，直接进记录页。读取失败展示既有账户错误文案，给「重试」与「先进入记录页」两条出路——账户未就绪时文字输入仍可用，与既有行为一致。
- **不假装。** 状态文字只说正在做什么：读取中「正在读取你的灵感…」；8 秒仍未完成改为「读取还在进行…」并露出两个按钮，不永远转圈。
- **入口例外**：分享卡片、小程序码等携带路径的打开方式**不经过本页**，直接进入对应页面。本页只覆盖不带路径的普通启动。
- **导航例外**：本页用 `navigationStyle: custom`（无导航栏）——它是品牌过渡而非工作页，没有「我在哪」要回答。这是对「一律使用原生导航」的唯一有意例外，其余页面不变。
- **动效克制**：品牌标识与两行文字为一次性淡入；「拾光」光点（琥珀圆点）沿发丝轨道往返，是全站唯一的循环动效，表达「正在进行」而非装饰；`prefers-reduced-motion: reduce` 时全部停用，光点停在轨道中部。
- **文案**：品牌句「让想法慢慢成形。」（C01）；进行中统一单个「…」。不做随机文案轮换、不加拟人角色——「有意思」来自拾光意象与节奏，不来自话多。
- 本页不进入页面索引（`sitemap.json`），不携带任何账户或内容参数。

状态：

| 状态 | 呈现 |
| --- | --- |
| 读取中 | 品牌 + 轨道光点 + 「正在读取你的灵感…」 |
| 读取超过 8 秒 | 状态改「读取还在进行…」，露出「重试 / 先进入记录页」；当前读取完成即进入；重试后仅处理最新请求回执 |
| 读取失败 | 展示既有账户错误文案 + 「重试 / 先进入记录页」 |
| 云能力不可用 | 不展示本页内容，直接进入记录页 |

## 14. 记录到成稿与受控分享（2026-10-07）

本节与 `openspec/changes/optimize-product-experience-20261007/` 对齐。方向 A 延续暖纸 `#F7F6F2`、靛蓝 `#34377F`、现有品牌图形；金色只用于品牌灵光与已有当前内容锚点。页面增加用途表达和任务主次关系，三个 Tab 保持记录、灵感、我的。

### 14.1 首页与详情

- 首页顺序：52px品牌图形与品牌名 → 两行26px价值标题 → 14px收益说明 → 常驻label/160px输入 → 计数/状态 → 48px主按钮 → 记录→补充→成稿 → 私有说明。输入使用原生内部滚动、`cursor-spacing=24`、`maxlength=-1`。不增加示例行或自动注入文字。
- 2026-10-09 连续记录修复：输入框在确认保存后常驻，主按钮改为「再记一条」，点击请求焦点；也可直接在空输入中写下一条。紧凑成功反馈置于主按钮下方，带本次服务端确认的一行摘录及继续补充、整理这条轻量入口，直接使用该条ID。新输入或点击再记清除旧反馈及恢复提示。未知或明确失败仍保留输入及既有重试/复制；没有确认成功不能展示成功反馈。
- 从合法公开用途进入时，只显示“已选择：用途名”和取消入口，用户仍从空输入写自己的内容。用途不明时不显示这行，也不复制作者的文字。
- 详情保留19px完整原文和连续时间线；常用AI入口改为低强调链接，汇总已有补充保留在更多面板。补充输入增加常驻label，空/活跃两档64/160px；已有键盘与浮动补充守卫继续适用。

### 14.2 选材与稿件

- 列表入口、选材页标题及导航统一“选材成稿”。整行素材至少72px，选中同时显示序号、靛蓝实线和浅底；补充仍显示来源。底栏保持文档流sticky，末项不会被fixed覆盖。
- 稿件输入增加“这份稿件”label，16px/1.75正文，375px参考高度280px。复制为实色主按钮，另存与分享为次操作，可自然增高和页面滚动，不将这些动作固定在键盘上。
- 未另存稿件说明：“稿件仅在本次使用中保留，关闭小程序前请复制或另存。”同账户本次使用恢复成功给低强调 `draftRecoveryNotice`；不能由文字提示推出设备持久恢复承诺。
- 未保存稿分享文案为“保存并预览分享”，已确认且内容相同为“分享这份稿件”。另存未知时锁定编辑和分享，保存按钮改“重试确认保存”；复制仍可用。稿件为空时复制/分享/另存均不可点，超过另存上限仍可复制。
- 来源变化显示黄色常驻提示“素材已变化，当前稿件仍可复制。请重新选择素材后再保存。”单条页提供重新选择内容，多素材页提供重新选择素材；重选不能悄悄覆盖已有编辑稿。
- AI预览改为“预览仅在本次使用中保留，采纳后才写入记录。”风险提示、核对、勾选、来源检查和显式保存保持原有约束。恢复说明与阶段说明分开显示。

### 14.3 分享与接收

- 分享页先展示对方将看到的文字与合法用途，再展示公开范围和补充选择。默认仅正文；已选择补充才进入预览。长预览超过180字显示6行及“展开完整文字/收起全文”，全文展开不改变公开范围。
- 底部始终可达一项主动作：未准备“确认内容并准备分享”，准备中“准备中…”，准备好“选择微信好友”。同一底栏显示“公开文字 · 链接有效期30天”，页面正文保留完整撤回边界；海报与我的分享改为低强调入口。
- fixed分享底栏预留安全区；页面bottom padding为240rpx加安全区，主按钮允许换行。实际大字体底栏高度及末项可达性仍须按截图/真机测量，不能把样式常量当成全部设备已验收。
- 接收页保留独立只读内容、日期、来源边界、复制与举报。固定底部主动作使长正文首屏与末尾都能开始自己的任务。有合法非自由稿用途时显示用途名及“用这个结构写自己的”；其他情况使用“也整理我的想法”。空上下文/失效/网络状态保持原错误语义和通用开始入口。
- 首页、欢迎页、我的品牌说明和使用帮助采用同一价值表达；分享封面复用现有品牌图形与排版，无私人正文、账户身份或模型效果承诺。

### 14.4 可读性与验证边界

通用字段label14px，正文至少16px、辅助至少13px；输入与未选择框使用 `--field-line`，主按钮至少48px、所有点击热区至少44px。按钮文案采用1.4行高并可换行，大字体保持完整文字。危险操作的辅助说明使用可读的次要墨色，危险动作本身仍用危险色。反馈、历史、我的分享、照片错误页补齐同一字号下限。
