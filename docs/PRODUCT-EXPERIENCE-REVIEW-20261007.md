审查与规则核验日期：2026-10-07，Asia/Shanghai。审查基线：当前工作区 `dev`，源码提交 `504b989`。下文现状和截图记录改版前的审查证据。用户随后授权本地优化，实施范围及验证结果见 [本地实施报告](PRODUCT-EXPERIENCE-IMPLEMENTATION-20261007.md)。云部署、真实业务写入、发布及 Git 提交未执行。

## 1. 核心结论

**最值得保留的是“接住一句想法，持续补充，整理后带走”的完整个人创作过程。**当前产品已经具备轻量记录、原文锚点、补充时间线、修改记录、单条与跨条选材、可编辑稿件、复制/另存，以及私密记录和公开文字快照的边界。暖纸、靛蓝、品牌灵光形成了可延展的视觉基础。应把这一条价值路径做清楚，而不是增加更多功能入口。

优先解决三个问题：

1. **第一次只看见“记下来”，没有迅速看见“拿来用”。**记录首页只说明记录与补充，首记成功也没有直接整理入口。用户可能将产品理解为又一个备忘录。应在首屏表达可用结果，并让首记后一次点击进入整理。
2. **真实被打断场景会损失编辑劳动。**当前多素材稿和 AI 预览在页面隐藏时清空。本轮合成工程对多素材稿调用 `onHide/onShow`，编辑文字、选材、编辑阶段均归零。建议在重新核验同账户后恢复会话内文字，旧请求继续失效，不恢复旧写权限，不新增本机落盘。
3. **传播没有接上用户最有价值的结果。**编辑稿的分享要另存、查看、更多再进入分享；接收者只会进入普通空记录页。应围绕具体用途的成品分享，并承接接收者自己的第一次有价值任务。

参赛前另有一个 **P0 验收条件：取得目标环境真实闭环证据**。本轮当前工程能读取账户、进入空列表；这不证明正式环境写入、AI、照片、双账户分享或真机完整可用。不能用 UI 改版代替这部分验收。

## 3. 整体优化方案

### 3.1 用户、场景与价值表达

**首轮目标用户假设**：经常在手机上记录工作/创作片段，稍后要用于文章、交流提纲或行动安排的人。内容创作者、教师/知识工作者、独立经营者可作为招募入口，不同时承诺服务所有群体。依据是现有社交内容、视频、工作、行动模板；真实人群仍需验证。

| 用户情境 | 现在的常见做法（待访谈核实） | 产品可提供的具体收益 | 页面落点 |
| --- | --- | --- | --- |
| 走路/通勤突然想到一句 | 发给自己、备忘录、截图；以后忘记位置 | 立即记一句，之后围绕同一原文接续 | capture可即时输入；detail原文+补充 |
| 开会后有多条零散想法 | 多处复制粘贴，逐段整理 | 找回、选择相关片段和顺序，形成一稿 | list搜索；material选择；output编辑 |
| 有方向但不知下一步 | 通用AI反复描述背景 | 在已选材料上给候选要点/下一步/风险，由用户核对 | ai-workbench；真实模型效果须另验 |
| 要发给朋友征求意见或交付 | 发送截图/长聊天，难说清范围 | 一份可读、可复制、可撤回后续访问的文字版本 | result→share-preview→shared |
| 相同需求再出现 | 重找聊天、重新写 | 搜索或可用稿筛选取用、继续未完成任务 | list/同会话继续稿 |

与普通备忘录相比，差异在**围绕同一想法接续、跨记录选择、形成可使用文字**；与通用AI相比，差异在**已有个人材料与可选择、可编辑、显式保存的过程**。这些是源码能力差异，省时和结果质量仍需同任务对照。

可直接使用的首页文案：

- 标题：**记下一闪念，整理成可用稿**。
- 说明：**先写一句。需要时，把零散想法整理成能直接使用的文字。**
- 字段标签“此刻的想法”，placeholder“此刻想到什么？”，主按钮“记下来”。
- 简短流程“记录 → 补充 → 成稿”；隐私说明“灵感默认仅你可见。”
- 保存完成“已记下”及摘录；主“继续补充”、次“整理这条”、低强调“再记一条”。不自动跳转。
- 可选的“看看如何整理”展开一个明确标为“使用示例”的静态过程，不默认填输入、不造AI结果、不新增数据。不恢复历史已取消的首屏示例行。

第一次获得有用结果的最短路径：输入自己的真实片段→服务器确认→整理这条→直接编辑自由稿→复制。分类、照片、模板、AI与分享均可稍后使用。空模板多项、长等待、过早选择AI模式、多个等权按钮、保存未确认和操作后失稿最容易削弱尝试意愿。

### 3.2 信息架构与六目标落地

保留“记录 / 灵感 / 我的”三项底栏。记录负责接住内容；灵感负责找回和整理；我的负责分享管理、隐私、支持。AI作为整理方式，不增加独立底栏。原文、补充和修改记录保持连续；照片仍作为私有附属材料。

| 目标 | 具体设计 | 判断方法 |
| --- | --- | --- |
| 美观 | 暖纸靛蓝统一；原文开放排版；成稿白色编辑面；每任务区一个主按钮 | 对比两方向，测文字清晰、重点辨认和风格一致 |
| 易用 | 首屏说收益；直接输入；首记直达整理；分享接收先展示用途 | 5秒理解、无指导首次任务 |
| 好用 | 自由稿默认；减少入口；云确认、未知保留/复制、稳定重试；同账户会话稿恢复 | 完成率、用时、错误恢复、打断接续 |
| 想用 | 展示从自己的片段到可复制文本的具体收益；按人群真实用途演示 | 自发试用、同任务对照、采用结果原因 |
| 愿意回来 | 最近更新、搜索、轻回顾、可用稿和未完成稿入口；不增加打卡/积分 | 需求再次出现时是否主动找回并接续 |
| 容易传播 | 结果页分享、明确公开范围、用途卡片、接收者自己完成结果 | 发起、接收内容渲染、首次确认保存、后续有效任务 |

### 3.4 两种视觉方向与推荐

| | A：纸页与灵光（推荐） | B：清晰工作台 |
| --- | --- | --- |
| 颜色 | 暖纸#F7F6F2、白面、靛蓝#34377F，金#E4A83A只用于品牌 | 近白#F5F9F6、深墨绿#145B4A、薄荷#DEF1E7 |

### 3.5 传播路径与取舍

**谁会分享、何时分享、为什么分享**：创作者整理好活动想法、知识工作者得到讨论提纲、个人完成行动方案时，把有用途的结果发给相关朋友/同事；理由是求建议、交流、交付或推荐一个自己用得上的结构。分享者获得可表达的成品；接收者获得有用内容或一种完成自己内容的方法。上述动机是H，需观察实际选择的对象与理由。

首选“**成品文字分享 + 接收者使用同一结构**”。已有文字快照、审核、期限、撤销和接收页，M成本可复用。通用小程序推荐保留为次入口。模板单独分享属后续方向，先验证“照这个结构写自己的”价值。协作/组队需新的身份、权限、并发、通知和治理，当前没有需求证据，L成本暂缓。送额度、积分/奖励会增加作弊与平台风险，当前不投入。

选定流程：

1. 结果页编辑完成，主“复制稿件”，次“另存”，传播次操作“保存并预览分享”。已确认同稿直接“分享这份稿件”。不在刚输入、退出或失败时催分享。
2. 分享页首屏显示完整公开文字（长文可展开）、范围摘要、可确认标题、30天有效期与撤销边界；私人原记录默认仅正文，补充显式选。用户点“确认内容并准备分享”。
3. 服务端审核并确认快照后，同位置变为“选择微信好友”；用户主动发起微信系统分享。提示“内容已准备好，选择好友后发送”；取消后不显示已分享成功。
4. 好友卡片示例标题“周末街区散步指南｜一份内容提纲”；封面1000×800px（5:4），用途小标、两行标题、最多三行经确认摘要、品牌小标；不含照片/身份/历史。通用推荐标题“随手记一句，整理成能用的文字”。
5. 接收页先显示“从零散想法整理出的内容提纲”、标题、正文/完整展开。主“用这个结构写自己的”，次“复制这份文字”，举报在末端。首次用户不先填资料、不授予不必要权限。
6. 主操作带**公开用途/模板ID**进入空输入，顶端可取消提示“本次整理：内容提纲”；不自动复制作者原文、不自动新建记录。保存确认后进入自己的可编辑稿，完成后可再次分享。

第一期低成本协议只分享已确认记录；接收的模板承接可先按固定公开用途做限定试用。任意客户端正文分享、用户可编辑卡片标题/摘要、AI来源、用途字段和受信公共读取分离，均先作OpenSpec与数据设计，不将UI稿视为已有协议能力。无完整用途元数据时用通用“也整理我的想法”，不猜测分享者用途。

缺token、格式异常、过期、撤回明确返回“分享无法查看”；网络错误返回“暂时无法查看/重新读取”。仍有“记录我的想法”，不把两类原因混写。新用户的云身份准备与头像/手机号授权分开；保留受信平台身份，不为打开率开放数据库权限。微信单聊不提供群shareTicket，不能依赖它放行。照片只在用户主动添加时按平台要求处理授权，拒绝后文字仍可用。

技术边界已核对[官方Page文档](https://developers.weixin.qq.com/miniprogram/dev/reference/api/Page.html)、[分享指南](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/share.html)、[小程序码](https://developers.weixin.qq.com/miniprogram/dev/server/API/qrcode-link/qr-code/api_getunlimitedqrcode.html)。内容提前准备，避免分享promise超过3秒回退；App进入参数处理冷/热启动，二维码scene≤32可见字符，只有短token。好友卡、朋友圈入口和海报码分别验收。第一期好友为主，不增加朋友圈强制推荐；[平台运营规范](https://developers.weixin.qq.com/miniprogram/product/)禁止相关强制/利益诱导分享。复制、另存、AI与分享彼此不作解锁条件。

测量方案见第6节。不能预测裂变系数、用户规模或获奖概率。

### 6.2 用户测试设计

首轮招募10名符合目标假设的人：至少5名内容/知识工作者，另5名需要把工作想法转成提纲/安排者；另招5名未见过产品的分享接收者。先询问最近一次真实情境和现有工具，再做无指导任务。测试主持人不替用户解释按钮含义；分享只发给事先同意的测试对象，使用无隐私内容。

任务：①5秒首页理解；②记录并补充自己的片段；③整理并复制可用结果；④从两三条记录组合内容；⑤注入可恢复保存失败；⑥取材料时切后台60秒再接续；⑦有相关接收者时尝试分享；⑧陌生接收者理解后完成自己的记录；⑨3天后找回；⑩7/14天在新需求出现时询问实际再次使用。没有新需求的人单列，不把没开App直接算拒绝产品。

| 指标 | 记录方式与设计验收目标（不是现有成绩） |
| --- | --- |
| 任务理解 | 5秒后≥8/10说出“先记录、可补充并整理使用”；记录误解原话 |
| 首次完成 | ≥8/10不求助完成记录→成稿→复制；分享接收者≥4/5完成自己的首条确认保存；小样本同时报告人数 |
| 耗时 | 首次片段到复制中位目标≤90秒，服务等待单列；多片段任务对照原工具，至少7/10不更慢且认为结果可用。记录写作时间与操作时间 |
| 错误恢复 | ≥8/10找到重试或复制，0人把未知当已保存；全部被打断者能恢复同账户文字；不可把一次测试推出全网络可靠 |
| 视觉感受 | 记录阅读清晰、主动作辨认、品牌一致的1—5评分与理由；目标中位≥4且无严重可读问题；A/B顺序随机 |
| 想用 | 至少6/10能说出下次具体用途并愿意用自己的内容试；只说“好看”不算价值验证 |
| 愿意回来 | 观察3日找回是否≤30秒、7/14日实际新增/补充/整理；先报告真实人数/情境，不预设留存结果 |
| 分享意愿 | 记录是否有自然对象、时间、用途以及拒绝原因；先比较优化前后能否自行找到入口；不要求每人必须分享 |
| 结果价值 | 询问复制后是否真的用进文章/讨论/行动，对方能否理解；复制点击不等于外部采用 |

观察表字段：受试者匿名编号/用户类型、任务起止、系统等待、操作数、错误、是否求助、结果是否可用、用户原话、后续真实情境。经同意录屏；报告隐去身份和正文，不把私人灵感传播成比赛材料。首轮失败点迭代后再测5名新用户，避免学习效应。

### 6.3 传播测量

第一阶段人工观察；新增线上采集单独提案和授权。仅记录事件类型、时间、页面、结果码、经服务端聚合的标识与必要公开模板类型；不收集正文/照片/原始token/好友群关系。定义并验证去重、同意、保留期和删除。

- 分享发起率：触发`onShareAppMessage`的去重会话 / 看到可分享结果的去重会话；另列准备失败和准备后放弃。
- 接收打开：内容成功渲染的独立接收会话/用户数，排除分享者自开。
- **真实接收打开率**需要卡片送达或曝光分母；当前API没有这项事实时无法计算。代理为“每100次发起带来多少独立接收打开”，群转发可超过100，不能称CTR。官方统计若以后提供曝光，再另列真正打开率。
- 首次任务完成率：成功看见分享的首次接收者中，完成自己服务器确认首存的比例；同时看首存后复制/另存/补充，不能把读别人的稿算完成自己的任务。
- 后续使用：首次完成者7/14日再次新增、补充或整理比例；只有打开和有效接续分开。
- 二次传播：接收者自己的成品产生分享发起的比例及原因，不要求转发原作者私人内容。

分享菜单success只代表接口调用，不能证明发送；链接创建只代表准备，不能证明对方打开。全部增长收益为待验证假设。
