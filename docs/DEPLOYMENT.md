## 部署前必做的一件事

```bash
node scripts/build-cloud.cjs
```

微信云函数**只上传函数目录本身**，`server/` 与 `core/` 是靠脚本同步进去的副本。忘了这一步，上传的是上一次同步的旧代码——**而它照样能跑**，只是行为不对。

跑 `npm run check` 也可以，它会核对副本是否与源码一致，不一致直接报错。

## 步骤

### 1. 开通云开发

开发者工具顶部点「**云开发**」，先确认已配置环境。不得另建付费资源或假定现有额度足够。

**验证**：在资源方管理入口确认环境为 `product-d2g59zty74d7d1ec1`。不要把客户端项目 AppID 改为资源方 AppID；共享调用与资源管理是不同入口。

### 2. 建集合

云开发控制台 → **数据库** → 集合管理 → 新建集合，名字**必须**是：

```
linggan_accounts
linggan_shares
linggan_feedback
linggan_usage
linggan_rate_limits
linggan_ai_usage
```

**验证**：集合存在且名称正确。若已有记录，保留原数据；不得为验收清空。

### 3. 配权限

逐个选中上述六集合 → **权限设置** → 选「**所有用户不可读写**」。每个集合分别核验，不因已创建而假设规则符合要求。

集合禁止客户端直读写，所有访问经过云函数中的身份、版本与内容校验。微信提供的可信身份和数据库创建者权限不等于本项目完整的业务授权。

**验证**：权限设置页显示「所有用户不可读写」。

### 4. 建业务索引

完整 15 个索引（含 5 个唯一）见 `deployment/product/indexes/` 与数据库设计；`linggan_usage` 无需额外业务索引。先回读已有定义，只补缺失项。下表为账户集合的唯一索引，不能代替其余集合的索引创建与核验。

集合 → **索引管理** → 新建索引：

| 项 | 值 |
| --- | --- |
| 索引名 | `accountKey_unique` |
| 字段 | `accountKey`，升序 |
| 唯一 | **勾上** |

**验证**：索引列表里出现它，且标记为唯一。

> 为什么这条重要：「一个账户一份文档」这条约束**数据库能替我们守住**，就一定让它守。靠代码去「先查再插」，并发下会插出两份账户文档。

### 5. 部署云函数

开发者工具左侧资源管理器 → `cloudfunctions` → 右键 `linggan_api` → 「**上传并部署：云端安装依赖**」。

等它跑完，再分别对 `linggan_ai`、`linggan_maintenance` 做同样的部署。AI 保持关闭，维护函数不配置触发器、不执行清理。

**验证**：云开发控制台 → 云函数 → 三个函数分别取得部署成功结果、回读状态正常；再核验平台配置与合成内容调用。仅看见函数存在不代表业务可用。

### 6. 配云存储权限

先只读核对存储规则对 `linggan/` 路径的实际隔离能力。product 是共享环境，**不得直接把整个存储桶的规则改成新的预设**；若当前规则不能满足仅创建者私有读写，先说明对其他应用的影响并单独取得规则变更授权。

**验证**：权限设置页显示已生效。

### 7. （可选）AI 环境变量

当前适配器走云开发 AI（`@cloudbase/node-sdk` 锁定版本 3.16.0），不需要自建供应商密钥。启用前确认模型访问权限、预算、审核云调用权限及 `linggan_ai_usage` 集合（客户端全拒绝，索引见数据库设计 §13）。

云开发控制台 → 云函数 → `linggan_ai` → 配置 → 环境变量：

| 变量名 | 值 |
| --- | --- |
| `LINGGAN_AI_ENABLED` | 仅明确授权启用时设 `true`；其余关闭 |
| `LINGGAN_AI_MODEL` | 平台已开通并核验的模型标识，不能填展示名称猜测 |
| `LINGGAN_AI_DAILY_LIMIT` | 默认 20，可向下调整 |
| `LINGGAN_AI_MINUTE_LIMIT` | 默认 3，可向下调整 |

云函数超时需至少 60 秒；服务端业务截止 50 秒、客户端 55 秒。超时不承诺取消底层模型调用，并保留本次额度；明确失败退还日额度但不退频率。输入和输出逐块审核，任一块未知或失败不展示。

**验证**：在受控账户、非私人样例上验证真实生成、契约失败、审核失败、超时、跨实例配额及重复请求；随后才授权打开客户端 `config/ai.js`。仅看见环境变量不能认定 AI 可用。回退关闭客户端及服务端 AI 开关，记录/补充/手动整理不受影响。

### 8. 翻开关（已完成）

`miniprogram/config/cloud.js` 的 `enabled` 已于 2026-09-22 改为 `true`，环境 ID 也已填。

**但开关打开不等于云端就绪。** 它只表示客户端会去调 `linggan_api`——函数有没有部署、集合有没有建、权限规则有没有配，客户端一概不知道。

所以第 1—6 步**仍然必须做完**。判断方法很简单：

**打开后每条保存都显示「还没同步到云端」→ 回控制台查第 5 步（函数部署）与第 2、3 步（集合与权限），不要查客户端代码。**

回滚：把 `enabled` 改回 `false` 重新编译，不影响云端数据。

## 部署后要做的验收

翻开关只是让它"能跑"，不等于"跑对了"。以下四项要分别留证据（见 `openspec/changes/add-inspiration-mvp/tasks.md` 第 8 节）：

| 验证 | 怎么做 | 看什么 |
| --- | --- | --- |
| **双账户隔离** | 两个微信账号各记一条 | 各自只看得到自己的；`linggan_accounts` 里是两份文档 |
| **伪造身份被拒** | 构造一个带 `accountKey` 字段的请求 | 返回 `IDENTITY_FIELD_REJECTED`，且服务端数据不变 |
| **删除闭环** | 删一条带照片的灵感 | 云存储文件列表里对应的对象消失 |
| **离线重试** | 断网存一条，恢复网络 | 先显示「还没同步到云端」，恢复后自动补上 |

## 回滚

| 想回退什么 | 怎么做 | 影响 |
| --- | --- | --- |
| 客户端行为 | `cloud.js` 的 `enabled` 改回 `false`，重新上传 | 不影响云端数据；应用退回纯本机模式 |
| 云函数 | 控制台里回退到上一版本 | 集合与存储桶不动 |

**不要做**：删集合、清空存储桶。那是不可逆的，而且没必要——回滚靠开关和版本就够。

2. 按 `docs/database-design.md` §10.3 建索引并核对唯一属性：`linggan_shares.tokenHash`、`(ownerAccountKey,requestId)` 唯一；`(ownerAccountKey,_id desc)`、`(ownerAccountKey,sourceInspirationId,revokedAt)` 普通索引。`linggan_feedback.(accountKey,requestId)`、`dedupeKey` 唯一；`(accountKey,_id desc)`、`(status,createdAt desc)` 普通索引。唯一索引创建失败时**停止部署**，先查冲突数据，不自动删除。

4. 核对 `cloudfunctions/linggan_api/config.json` 的 `security.msgSecCheck`、`wxacode.getUnlimited` 云调用权限。审核不可用、结果不明或小程序码失败都应失败关闭；先用**非真实个人内容**做受控调用，核对实际 SDK 返回结构。不能仅凭 Node mock 认定审核已生效。
5. `node scripts/build-cloud.cjs`、`npm test`、`npm run check`、OpenSpec 严格校验通过后，才评估云函数/客户端配套部署。用两账户验证分享创建与他人只读、本人列表、越权拒绝、撤销/源删除后新读取失效、反馈隔离、过期与海报小程序码；分别留开发者工具和 iOS/Android 真机证据。

**回退**：先把 `LINGGAN_SHARE_CREATE_ENABLED=false`，停止新建分享但保留 `share.get` 和 `share.revoke`，直到所有有效链接到期或撤销；不能直接回退到完全没有分享读取接口的旧函数，否则已发出的链接立即失效。不得为回退而删新集合或清空内容。海报图片已在用户相册/朋友圈，无法远程收回。§10.4 的清理任务已有本地代码，但**未部署、未执行**，不能把保留策略说成已自动执行。
