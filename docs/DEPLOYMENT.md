## 部署前必做的一件事

```bash
node scripts/build-cloud.cjs
```

微信云函数**只上传函数目录本身**，`server/` 与 `core/` 是靠脚本同步进去的副本。忘了这一步，上传的是上一次同步的旧代码——**而它照样能跑**，只是行为不对。

跑 `npm run check` 也可以，它会核对副本是否与源码一致，不一致直接报错。

## 步骤

### 1. 开通云开发

开发者工具顶部点「**云开发**」→ 新建环境。免费额度够用。

**验证**：控制台能打开，概览页显示环境 ID。确认它就是 `cloud1-d6g4hu8txdd86e48c`。

### 2. 建集合

云开发控制台 → **数据库** → 集合管理 → 新建集合，名字**必须**是：

```
linggan_accounts
```

**验证**：集合列表里出现它，且当前 0 条记录。

### 3. 配权限

选中 `linggan_accounts` → **权限设置** → 选「**所有用户不可读写**」。

> 这一条不能妥协。选「仅创建者可读写」的话，客户端的身份来自它自己声明的 `_openid`，而规范要求「客户端提供的身份字段不得授予访问权」。**只有云函数能碰这个集合**，身份才不可能被伪造。代价是每次读写都要过一次云函数调用，这个代价必须付。

**验证**：权限设置页显示「所有用户不可读写」。

### 4. 建唯一索引

集合 → **索引管理** → 新建索引：

| 项 | 值 |
| --- | --- |
| 索引名 | `accountKey_unique` |
| 字段 | `accountKey`，升序 |
| 唯一 | **勾上** |

**验证**：索引列表里出现它，且标记为唯一。

> 为什么这条重要：「一个账户一份文档」这条约束**数据库能替我们守住**，就一定让它守。靠代码去「先查再插」，并发下会插出两份账户文档。

### 5. 部署云函数

开发者工具左侧资源管理器 → `cloudfunctions` → 右键 `linggan_api` → 「**上传并部署：云端安装依赖**」。

等它跑完，再对 `linggan_ai` 做一次同样的事。

**验证**：云开发控制台 → 云函数 → 看到两个函数，且状态正常。点进 `linggan_api` 的日志，至少能看到它被创建过。

### 6. 配云存储权限

云开发控制台 → **存储** → 权限设置 → 「**仅创建者可读写**」。

**验证**：权限设置页显示已生效。

### 7. （可选）AI 环境变量

**只有在决定自建调第三方模型时才需要**（`PENDING-INPUT.md` 2.1）。走云开发内置 AI 能力的话跳过这步。

云开发控制台 → 云函数 → `linggan_ai` → 配置 → 环境变量：

| 变量名 | 值 |
| --- | --- |
| `LINGGAN_AI_KEY` | 你的密钥 |
| `LINGGAN_AI_ENDPOINT` | 你的接口地址 |

**密钥只放这里**，不进仓库、不进前端包。`npm test` 里有一条用例长期守着这件事。

**验证**：环境变量列表里能看到它们（值会被打码）。**没配的话 `linggan_ai` 会返回 `AI_DISABLED`**，这是有意的——它绝不伪造一个看起来像 AI 的结果。

### 8. 翻开关

前面都做完，再改这一个值：

```js
// miniprogram/config/cloud.js
enabled: true,
```

**顺序不能反。** 提前翻开关的话，应用每次保存都会去调一个不存在的云函数：界面仍能用（降级成「已保存。还没同步到云端」），但日志里一直报错，**而真正的失败原因被那条降级提示盖住了**。

**验证**：改完之后重新编译，记录一条灵感。列表页那条应该**不带任何同步标记**（正常同步的条目不带标记，只有失败才带）。

## 部署后要做的验收

翻开关只是让它"能跑"，不等于"跑对了"。以下四项要分别留证据（见 `openspec/changes/add-inspiration-mvp/tasks.md` 第 8 节）：

| 验证 | 怎么做 | 看什么 |
| --- | --- | --- |
| **双账户隔离** | 两个微信账号各记一条 | 各自只看得到自己的；`linggan_accounts` 里是两份文档 |
| **伪造身份被拒** | 构造一个带 `accountKey` 字段的请求 | 返回 `IDENTITY_FIELD_REJECTED`，且服务端数据不变 |
| **删除闭环** | 删一条带照片的灵感 | 云存储文件列表里对应的对象消失 |
| **离线重试** | 断网存一条，恢复网络 | 先显示「还没同步到云端」，恢复后自动补上 |

## 回滚

| 想回退什么 | 怎么做 | 影响 |
| --- | --- | --- |
| 客户端行为 | `cloud.js` 的 `enabled` 改回 `false`，重新上传 | 不影响云端数据；应用退回纯本机模式 |
| 云函数 | 控制台里回退到上一版本 | 集合与存储桶不动 |
| 数据代际 | 递增 `generation` | 旧设备的离线队列视为失效，**不写回已清理的数据** |

**不要做**：删集合、清空存储桶。那是不可逆的，而且没必要——回滚靠开关和版本就够。
