# 灵感拾光簿：文案定稿与验收补充

日期：2026-09-30。配套：[体验审查与实施交接](UX-HANDOFF-20260930.md)、[五页视觉稿](UX-HANDOFF-20260930.html)。这是本轮推荐方案的文案定稿；产品源码与旧版规范尚未同步。本文的 C 编号是后续实施依据，不能作为已上线事实。

## 1. 校对结论与范围

原稿基调基本一致，但还不能称为全量一致。优点是短句、直接、没有强行煽情；不足是同一动作多种叫法、部分状态承诺过于确定、少数句子像开发说明。此次统一本轮交接文档和视觉稿，并给现有产品列出替换映射。

核对材料包括：本轮 22 张页面证据、`app.json` 列出的 14 个页面的静态文字、关键状态分支、`docs/ui-design.md` 第 6 节、文案守卫、本轮 MD 与 HTML。运行截图只覆盖证据表中的状态；AI 关闭页等未运行分支仅作源码审查。服务端所有动态错误、微信系统提示、所有账户与设备状态未逐一触发，不能据此宣称整个产品已完成文案验收。

| 发现 | 依据与性质 | 本轮处理 |
| --- | --- | --- |
| 同一整理结果混用“使用稿 / 稿件”；复制动作名称不同 | `output`、`material-output` 静态文案；本轮方案 | 结果统一“稿件”，操作统一“复制稿件”；“自由稿”仅作为格式名称 |
| “跳到补充（N） / 去补充”都指向输入框，数字却像查看已有条目 | 本轮方案与视觉稿；设计判断 | 统一“继续补充”；已有数量只放在补充标题旁 |
| “尚未保存”与“尚未确认保存”同时出现，超时被当作确定失败 | 本轮视觉稿状态切换；旧规范 §6.4 | 编辑、进行中、确认失败、结果未知分开，见 C10—C16 |
| “清空筛选”没有说明是否也清搜索词 | 列表源码、本轮方案 | 整体重置写“清空搜索和筛选”；只清一项时明确对象 |
| “继续一个旧想法”“结构空项”读起来生硬 | 本轮方案；设计判断 | 改为“回看一个想法”“留空的部分可以自己补写” |
| “还没有灵感”把没有记录说成没有想法 | 当前空态 O18；设计判断 | 改为“还没有记录”；保留明确开始按钮 |
| “每天 / 今天”容易暗示跨退出记忆 | 当前设置、列表源码；行为与承诺核对 | 改“显示回顾入口”“本次先不看”，明确下次重新启动恢复默认 |
| 品牌句各处重新发明，温度不连贯 | 现有欢迎分享标题与本轮稿面标题 | 沿用“让想法慢慢成形”，保留记录页原有副标题 |

设计判断：采用安静、亲切、准确的个人工具语气。品牌句提供记忆点；提示语给行动依据；错误说明说清结果和恢复方法。是否更受目标用户喜欢仍需测试。

## 2. 统一术语与文字规则

| 词 | 使用范围 | 规则 |
| --- | --- | --- |
| 想法 | 内容意义、品牌介绍、输入引导 | “此刻想到什么？”自然保留；不机械地全改成“灵感” |
| 灵感 | 产品中一条可保存、查看、删除的对象 | “我的灵感”“删除灵感”“另存为新灵感”；不用“笔记 / 点子 / 条目”另起同义名称 |
| 正文 | 一条灵感的主体文字 | 修改正文、并入正文；“原文”只在前后对比的解释中使用 |
| 补充 | 附属于灵感的后续文字 | 继续补充＝进入/定位输入；添加补充＝提交输入，二者不能互换 |
| 稿件 | 整理后可编辑、复制或另存的文字 | 不再与“使用稿 / 成品 / 文章”轮换；格式名“自由稿”保留 |
| 整理成稿 | 单条整理入口、页面标题；多条选材完成后的动作 | 手动组合不写“AI 生成”；跨条入口仍叫“选材整理” |
| 修改记录 | 已有内容的修改历史 | 导航、入口与空态保持一致，不另叫“版本库” |
| 分享文字 / 分享小程序 | 分享选定内容 / 推荐产品入口 | 对象不同，必须区分；不能统一成含糊的“分享”按钮 |

文字规则：

1. 品牌句固定为“让想法慢慢成形”。展示为独立句时带句号；分享卡标题使用“灵感拾光簿｜让想法慢慢成形”。不把它放到错误提示、确认按钮里。
2. 页面标题、按钮、短状态标题不加句号；完整说明句加“。”；提问加“？”；进行中统一用单个“…”而非三个英文点。
3. 产品字符串中数字紧接中文单位，如“2条补充”“30天”；中文标点用全角。“正文 + 2条补充”和“0 / 2000”是允许的计数格式。
4. 数量上限按当前领域长度规则计算，展示使用“字符”，不以“字”掩盖表情计数差异。帮助说明“表情等符号可能占多个字符。”；本轮不更改校验算法。截图示例的数字也必须由示例文本计算。
5. 同一动作、同一对象、同一结果使用同一名称；上下文不同可以不同。例如列表“记一条灵感”、首次空态“记下第一个想法”、保存后“再记一条”都是已批准的场景用语；不随意新增变体。
6. “复制内容”仅用于紧邻输入框的保全操作；“复制稿件 / 复制全文 / 复制补充 / 复制文字 / 复制留档文字”按真实复制范围命名。复制成功统一 C52，不暗示保存。
7. 未知原因不归因于网络、权限或删除。已识别网络错误才出现“请检查网络”；未知结果不写“肯定没保存”；恢复入口必须实际可用。
8. 不使用“灵感已被温柔收藏”“把碎片交给时光”等替代成功反馈，也不使用“激发无限可能”等效果承诺。美感来自节奏与用词，不增加用户解读成本。

## 3. 关键页面定稿

下表中的引号不进入界面；`{N}`、`{摘录}`是运行时占位符。各状态互斥，不把所有提示同时铺到页面上。字符上限、日期和业务枚举仍取现有配置。

| ID | 位置 / 状态 | 定稿 | 行为与限制 |

| C06 | 记录主按钮 | 记下来 | 空白、超限时不可提交 |

| C16 | 成功后的动作 | 继续补充 / 再记一条 | 前者打开这条详情并定位输入；后者聚焦记录页空输入 |
| C17 | 可拦截的编辑离开确认 | 标题：离开编辑？；说明：尚未保存的内容会丢失。；操作：继续编辑 / 离开 | 仅适用未提交编辑；正在保存或结果未知时不能套用，应先处理 C11/C12 |
