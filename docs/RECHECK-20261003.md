2026-10-04 纠正：本记录关于「补充汇总只能保存 1000 字」的判断错误。core.appendSupplement 对 AI 且至少两个 sourceIds 的汇总允许 2000 字，服务端同样允许；上一轮误加了限制。本轮已恢复实际契约并增加跨层保存测试。以下截图和 1000 字描述仅保留作当时误判的历史证据，不作为当前验收标准。

## 发现与修复

原 458 项测试全通过，源码复核仍发现漏测。首次增补的 8 项回归用例在修复前均失败；修复后及追加的保存回执用例全部通过。不能用原有绿灯代替代码审查。

| 问题 | 触发与影响 | 修复 |
| --- | --- | --- |
| 补充汇总保存上限不一致 | 合法模型汇总可到 2000 字，但补充只能保存 1000 字；原页面仍允许点击保存，随后被领域校验拒绝 | 补充/灵感分别显示 1000/2000；超限保留全文并禁存，可复制、缩短；提示放在长正文之前 |
| 来源字段排列被误判为内容冲突 | 来源记录仅字段顺序变化，也会被 JSON 字符串比较当成变化 | 规范化字段顺序再比较；真实内容变化仍拦截 |
| 单条整理的迟到账户读取 | 页面卸载、账户切换或新读取后，旧读取仍可构建旧稿件；初次 onShow 可能重复读取 | loadVersion、store、sessionEpoch 守卫；初次显示复用正在进行的有效读取；准备中拒绝输入事件 |
| 过期重读和替换确认 | 重读完成或旧替换确认可覆盖期间的新稿；确认时未复核面板、素材及保存状态 | 重读使用同一版本守卫；替换只作用于原稿、面板、选项、素材及当前会话 |
| 复制、另存与 TXT 的迟到回执 | 失败提示、保存成功状态或旧文件路径可能回填新页面 | 成功/失败均核验当前页面版本与账户；过期生成成功仅清理自身文件 |

新增 9 项行为用例位于 `tests/ai-experience.test.cjs` 和 `tests/ui-interaction-repair.test.cjs`。覆盖补充超限后缩短保存、字段顺序、读取/重读、替换确认、复制失败、文件生成/发送及另存回执。旧 `content-output` 测试的 getApp mock 原每次创建新 store，已改成稳定 App 实例，并让文件发送测试走实际 onLoad；保留原行为断言。

没有修改 server/ 或 miniprogram/core/，不需重建云函数副本；结构检查仍核对副本一致性。规范补充在既有 enable-ai-workbench、repair-ui-interactions 中，设计与覆盖表同步。
