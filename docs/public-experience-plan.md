# 灵感拾光簿：面向公众的体验计划

> 2026-09-23。本文是产品与验收建议，不代表公开发布已获授权，也不把未接通的能力写成现有功能。当前实现与验证边界见 `docs/spec-coverage.md`、`docs/VERIFICATION.md`。

## 一句话说明

记录当下的想法，随时补充完善。

「灵感」不只指创作点子。普通用户也会遇到想做的事、突然想到的问题和一时说不完整的念头。首屏用这些日常场景说明用途，同时只保留一个输入框和一个「记下来」动作。不要用教程、功能清单或 AI 承诺占据首屏。

## 第一次打开，应该发生什么

1. 看见标题和具体例子，知道这里可以写什么。
2. 不注册、不选分类，直接写一句并保存。
3. 保存后看见明确结果，可以点「查看这条」进入详情，发现还能继续补充。
4. 再回到列表，看到刚记的内容，而不是示例数据或空白页面。

2026-09-23 的界面迭代已完成第 1—3 步的入口与文案；第 4 步需要在微信开发者工具和真机中走通。反馈文案必须区分当前设备写入成功与备份完成，不能承诺尚不存在的自动重试。

## 为什么会再次使用

现有产品最明确的理由是：一条念头不必一次写完，回头可以补充、修改，并查看修改记录。`add-content-output` 进一步让用户复制、整理和带走文字，记录不再是终点。详情页仍应让「补充」容易发现，列表要让人快速回到最近继续想的那条。

搜索、分类、提醒、自动整理可以解决后续规模问题，但当前没有真实使用数据证明该先做哪一个。先观察用户保存多少条、能否找到旧内容、是否真的会回来补充，再分别提出 OpenSpec 变更；不要一次加满工具栏。

## 如何让别人愿意试

- 平台名称、头像、简介与首屏说同一件事：随手记一句，之后继续补充。当前代码名称是「灵感拾光簿」；公开前核对微信后台实际名称、简介和头像是否一致。
- 面向朋友推荐时分享的是**小程序入口**，不自动带上任何人的灵感正文、照片或历史。应用入口分享仍需单独提案和隐私检查。`add-content-output` 的 TXT 文件发送是另一回事：只有记录所有者主动生成并再次点击发送，才由其自行选择去向。
- 展示真实可用的记录与补充。照片和 AI 尚未接通，不在介绍页、分享卡片或平台简介中当作现有卖点。
- 用少量陌生用户测试首用流程：不解释产品，让他们说出用途、记下第一条、再找到刚记的内容。记录卡住的原话和步骤，再修改界面。

## 公开使用前的优先级

| 优先级 | 要完成的事 | 当前证据边界 |
| --- | --- | --- |
| P0 | 验证云函数、集合、权限规则与两个账户的数据隔离 | 客户端云开关已打开；不能据此推断资源已部署或权限正确 |
| P0 | 完成失败后的备份重试与可确认的状态，或给用户明确的手动恢复路径 | 当前只有待处理队列，没有自动重试调度 |
| P0 | 微信开发者工具真实编译与 iOS、Android 主流程验收 | Node 测试和结构检查不能代替 WXML/WXSS 渲染 |
| P1 | 用真实用户验证首屏文案、保存后去向与列表找回效率 | 本轮仅完成代码实现，尚无用户观察数据 |
| P1 | 若旧内容开始难找，再提案搜索或轻量筛选 | 目前没有搜索，不能在介绍里承诺 |
| P2 | 若需要靠朋友推荐传播，再提案只分享小程序入口的能力 | 不自动附带用户内容，不改动现有数据可见范围 |

每一项新功能、数据同步或权限变更，先按 `AGENTS.md` 走 OpenSpec 提案与授权。公众发布、云端部署和用户验收是后续独立动作。
