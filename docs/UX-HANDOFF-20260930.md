## 1. 产品体验判断

### 1.1 用户、场景与价值

**目标用户假设 H**：经常产生零散点子、需要隔几天继续思考或拿去使用的个人，例如内容创作者、产品/策划人员和做个人项目的人。还没有访谈证明哪一群是主力；本轮以“个人随手记录者”为共同基线，不把产品改成团队工作台。

主要任务是：**记下一句话 → 找回上下文 → 补充 → 整理成能复制使用的文字**。最小价值是确认记住了这一句；完整价值是再次需要时找得到、接得上、拿得走。

| 情境 | 用户当时要完成的事 | 设计取舍 |
| --- | --- | --- |
| 通勤、散步、聊天间隙 | 用十几秒写下一句，确认保存 | 输入优先，不加分类必填、不提前要头像或手机号 |
| 数日后有新线索 | 找到原来的想法，补一句 | 原文与补充相邻，定位比标签设置更重要 |
| 要写文案或做事情 | 带走一份完整文字 | 默认能看到可编辑结果，结构模板按需选择 |
| 从好友分享进入 | 读清内容、理解产品用途 | 先显示分享内容，之后提供“记录我的想法” |

目标权重为设计排序、不是量化研究结果：**好用≈会用 > 想用 > 愿意回来 > 愿意推荐**。回来应来自旧想法仍有用途；推荐应来自“一句话能一直补充，最后拿去用”的明确价值。本期不增加打卡、积分、榜单、弹窗召回或订阅消息。

### 1.2 当前优势，作为回归保护项

1. **直接开始**：冷启动进记录页，没有强制教程或额外登录页；标题、输入框、保存按钮构成完整入口。【O01、02；S app.json】
2. **确认才算保存**：离线样例点击保存后出现常驻“已记下。查看这条”；代码仅在 `ok && synced === true` 后清空输入。真实云端保存本轮未验证。【O03、04；S capture/index.js】
3. **内容可以继续生长**：原文可改，修改历史可读，补充可复制、编辑、并入正文；删除有内容摘录与不可撤销提示。【O07—10；S detail/history】
4. **整理保留原记录**：模板拼接不新增事实，稿件可编辑与复制。【O11、12；S content-output.js】
5. **近期修复应保留**：空列表已隐藏筛选；成功与失败有不同符号；补充操作面板文字不再挤成竖排；标签表单默认收起；详情非 AI 操作已一行等宽。【O03、09、17、18、20】

### 1.3 核心障碍与最值得改变的三件事

**核心障碍 J：记录入口已经够短，后续“找回—继续—取用”仍承受较多控件和前置决策。**

1. **把详情页的原文、输入与已有补充放到一起**。照片和整理标记下移，长正文提供可达的“继续补充”。有照片样例中，首条补充起点距页面内容顶约 **745 CSS px**；当时 `windowHeight=671`。无照片状态已经能看到首条补充，不能泛称所有详情都看不到。【O07、08、20；本轮 detail-layout.json】
2. **让最近记录先出现，回顾按需展开**。现有列表先显示搜索、五项筛选、醒目回顾卡，再进入最近记录。回顾有价值，但不应挡住有明确寻找目标的人。【O05；J】
3. **单条整理先给结果，再调整材料和格式**。目前进入后先看两种模式、五种模板、补充选择及多段说明，再点“生成使用稿”。自由稿已是默认，补充已默认全选，可以直接展示同样的稿件。【O11、12；S output/index.js；J】

另外将“未保存输入的退出风险”设为 P0 核验门槛：没有观察到真实丢失，但平台返回提示不能覆盖关闭、回收等情境，必须如实提示并验证恢复路径，不能宣称自动暂存。

### UX01：未保存输入与中断恢复

- **场景/依据**：记录页已输入、保存失败、中途退出。失败画面会保留内容并写“内容仍在输入框中”【O17，状态注入】；输入时没有持续的未保存提示【O02】。`guardDraft` 调用了返回询问 API【S】，但官方说明仅覆盖特定非根页返回，手势返回不拦截，也不应阻止退出。[微信官方说明](https://developers.weixin.qq.com/miniprogram/dev/api/ui/interaction/wx.enableAlertBeforeUnload.html)
- **影响 J/H**：用户可能把“还在输入框”理解为下次打开也在；尚无真实用户误解或丢失证据。
- **修改**：非空输入尚未提交时显示“尚未保存，退出后可能丢失。”；提交中改为“正在保存，请稍候。”；成功立即移除。结果未知时撤掉编辑提示，显示“尚未确认保存”与“内容还在输入框中。退出前请重试保存或复制内容。”，主按钮“重试保存”，次按钮“复制内容”。确认被拒绝则按已知原因提示“未能保存”。复制是用户明确点击才执行，不自动写剪贴板。
- **流程**：输入 → 保存中（冻结本次提交）→ 成功/未完成；未完成 → 重试同一内容或复制保全；修改内容后回到编辑态。不能把网络超时说成“绝对没保存”，未知结果使用 C12—C13，不能与“尚未保存”同时出现。
- **界限**：沿用会话内存，不新增 storage、磁盘草稿、离线队列；不承诺强杀/重启恢复。账户切换立即隔离输入和迟到回执。跨页面的受控离开可确认，微信系统行为按官方能力处理。
- **收益/代价**：更清楚地表达未保存状态；输入区多一行提示和失败时一个按钮，需验证不造成过度焦虑。
- **验收**：AC01、02、03、11。对超时后实际已写入的情况也须验证幂等，不能重试生成重复记录。

### UX02：详情页优先接回想法

- **场景/依据**：带两条补充和照片的详情，原文后依次是编辑、完整输入框、三按钮、整理标记约102 px、照片约130 px，再到补充【O07、08，实测】；长正文占满多屏【O21，注入】。无照片页面已有改善【O20】。
- **影响 J**：用户要先滚过无关区块才知道上次想到哪；长文时补充入口很远。
- **推荐顺序**：时间与“更多” → 原文 → 轻量动作“整理成稿 / 继续补充” → 紧凑补充输入 → 补充时间线 → 一行“标签与阶段” → 照片 → 其他低频信息。正文编辑、复制全文、分享文字、修改记录、删除移入页内“更多”面板；已有补充的操作面板继续保留。
- **输入布局**：空输入64 px高，始终看得见；下方计数与44 px高“添加补充”。聚焦后为160 px，多余文字在输入框内部滚动；失焦且仍有内容时保持160 px，清空并失焦后回64 px。`auto-height=false`，避免固定高度与自动增高冲突；键盘规则见§6。不增加“进入编辑模式”的必经步骤。
- **长文规则**：默认仍完整显示，不自动截断原文。正文区上方提供“继续补充”，数量单独放在补充标题旁；仅当正文超过6行时，在滚动离开顶部后显示44 px高的“继续补充”浮动按钮，键盘打开隐藏。点击只定位并聚焦补充框，不修改数据。
- **时间线**：保持现有时间正序、可查看已收起内容，不引入倒序或“只显示最近三条”的隐性变化。新补充确认后可见并读到“已添加补充”；失败不插入确认列表、不清空输入。
- **收益/代价**：上下文集中；复制/分享/修改正文多一次打开“更多”，这是明确取舍。若测试发现编辑正文比补充更常见，保留其行内入口，再评估工具栏密度。
- **验收**：AC04、05、11。固定样例“正文60汉字、两条各35字补充、无照片/有照片两种、AI关闭、390×844”中，首条补充标题与至少两行正文在首屏内；照片不得改变这个位置。文字放大1.3倍只要求无裁切及跳转可达，不要求硬塞首屏。

### UX03：列表先帮助找到，再邀请回顾

- **场景/依据**：O05 中五项筛选加回顾卡在最近记录之前，最近记录只占首屏下部；O18 真空态已正确隐藏控件，保留。
- **影响 J/H**：面向“回来找上一条”的用户，回顾可能造成绕路；还需测试“随便翻翻”的用户是否偏好当前形态。
- **修改**：保留搜索。默认筛选行只放“全部 / 有补充 / 筛选”；“七天内 / 阶段 / 已合并”放入同一面板，有选择时标“筛选·2”。回顾从大色卡变为**第一条最近记录之后**的44—56 px轻量行“回看一个想法”，点击展开一条正文预览；关闭动作写“本次先不看”。默认不展开，不自动弹出。
- **内容行**：正文2行，默认阶段“想法”不单独占行；只显示非默认阶段、最多2个标签，超出写“+N”；更新时间与补充条数同一行。整行可点击，移除每行重复“查看”按钮。保持按 `updatedAt` 倒序。
- **状态计算**：`activeCount` 与 `mergedCount` 分开计算。仅 `activeCount + mergedCount === 0` 且读取成功才是真空态；有已合并内容时保留筛选入口；搜索无结果仍保留搜索/已选条件与“清空搜索和筛选”。不直接用筛选后的 `items.length` 或默认列表的 `total` 决定工具区是否存在。
- **返回规则**：同账户、同筛选从详情返回保留查询与滚动位置；若内容更新导致重排，以原首个可见记录ID锚定，目标删除则落到相邻项。账户变化清空查询、选择和旧内容，不能借“保留列表”泄漏上一账户数据。
- **收益/代价**：首屏更多真实内容；高级筛选多一次点击，状态逻辑需回归。回顾仍是会话内状态，不能使用“今天不再显示”这一跨会话承诺。
- **验收**：AC06—08、15。默认390×844至少可见两条各2行的记录；回顾不出现在首条之前；已合并内容入口不会因为默认列表为空而消失。

### UX04：整理先见结果，结构按需调整

- **场景/依据**：O11 的模式、五个模板、说明、材料选择在稿件前；O12 显示自由稿只组合已有文字。S 中 `templateId=free`、补充默认全选，进入时仍需点生成。
- **影响 J/H**：用户还不知道输出是什么，就被要求选使用方式；“生成”可能被误解为 AI 写作（尚未访谈证实）。
- **修改**：详情入口统一叫“整理成稿”；进入 `pages/output` 默认用现有规则构建自由稿并展示编辑器；顶部摘要“正文 + 2条补充”，次入口“调整内容”和“选择格式”；主按钮“复制稿件”，次按钮“另存为新灵感”；“文字留档”保留在页内更多菜单，不删除能力。
- **调整内容**：打开材料面板，正文固定带入，补充可选；确认按钮“应用选择”。如果当前稿件有手工修改，确认前给出“替换当前稿件？”、“你修改过这份稿件。替换后，这些修改不会保留。”与“保留编辑 / 替换稿件”。取消必须保留原稿、光标及选择。未修改时可直接替换。
- **选择格式**：默认“自由稿”；提供现有四种结构选项，不新增模板。展示一句“只整理已有文字，不自动补写。留空的部分可以自己补写。”。换格式遵守同一替换保护；不自动联网、不调用AI、不添加事实。
- **另存**：遵守2000字符限制；超出允许继续编辑和复制，另存按钮禁用且显示“另存最多2000字符，当前超出N字符。”。相同稿件重复点击不得新增重复灵感；编辑后算新的候选内容。成功提示“已另存为新灵感”及“查看新灵感”。
- **跨条选材**：`material-output` 保留先选后出稿，因为无法推断用户要选哪些；与单条页面统一结果区样式。保持40段/20条来源/12000字符等既有边界，不能套用“默认全选”。
- **收益/代价**：详情到可复制稿少一次显式生成操作；需改变初始状态与替换确认路径，属于行为变更。实施前补 OpenSpec 提案；不重写领域层拼接规则。
- **验收**：AC09、10。进入即有可编辑结果；原文、补充、历史、标签不变；生成过程零AI调用；剪贴板写入成功后才报“已复制”。

### UX05：找不到内容时给出可执行出口

- **场景/依据**：直接访问不存在ID的整理页，画面写“请返回列表”，但没有页面内返回按钮【O22，实际本地缺失路径】。左上系统主页入口存在，但不会明确告诉人将去哪。
- **修改**：标题“找不到这条灵感”；说明“它可能已被删除，可以返回列表查找其他记录。”；44 px高主按钮“返回灵感列表”，调用明确的 tab 路由。详情、历史、照片、整理统一此规则。读取失败不能冒充删除：用“暂时无法读取灵感”并提供“重新读取 / 返回灵感列表”。
- **收益/代价**：从深链接进入仍有出口；单页低成本，需核对同类页面，不新增自动跳转。
- **验收**：AC12。无导航栈也能退出到正确列表，不执行 `navigateBack` 空栈；不会误删数据或在错误页显示旧账户内容。

### UX06：小屏、长文、键盘与可访问性

- **依据**：本轮只验证一种模拟器逻辑尺寸，未验证真实键盘；当前多个按钮为88rpx，在320 CSS px宽度上只约37.5 px【S/J】，不能直接当成44 px点击区。O21长文中主操作被挤出首屏。
- **修改**：可操作区域 `min-height:44px; min-width:44px`，视觉尺寸可用rpx；正文使用可换行内容，不设固定行高容器裁字；细分隔线不承担表单边界，表单边框加深；错误用符号+标题+恢复按钮，状态不只改色。
- **验证/代价**：AC11、14、16。高风险是键盘、系统字体和输入法，必须iOS/Android真机测；不能以网页原型或 `npm run check` 替代。样式成本中等，实际平台确认成本单列。

### UX07：首次进入与成功后衔接

- **依据**：现有“记录想法 / 先写下来，之后再补充。”清楚而克制【O01】，不增加教程。成功是下方单行反馈【O03】，缺少刚记内容的摘录但路径可达【O04】。
- **修改**：保留现有标题与副标题；输入框空白下方只给一行非按钮示例“例如：把周末散步路线整理给朋友”。示例不自动填入、首次输入就隐藏，不显示促销式说明。成功区用“已记下”+刚保存文字的两行摘录+“继续补充”，下方“再记一条”；前者打开对应详情，后者聚焦空输入。用户直接输入下一条时撤掉旧成功卡。仍保留空输入区域，连续记录不被强制跳页。
- **收益/代价**：结果身份更明确，更早传达“可继续”；成功卡比当前条幅高约80—120 px。若连续记录测试因此变慢，回退为单行成功+二级“继续补充”，不改保存协议。
- **验收**：AC01、13；T01、T02。此项在核心结构完成后再做，不能为了视觉稿重造品牌或增加欢迎页。

### UX08：分享是确认内容后由用户发起

- **依据**：当前页面已有正文预览、选补充、有效期与撤销边界【O15】；准备成功后另出现“选择微信好友”【S】。本轮未创建分享链接、未发消息。
- **修改**：同一主按钮位置按状态替换：未准备“确认内容并准备分享”→进行中“准备中…”→就绪“选择微信好友”（真正的 `open-type="share"`）。修改选择使旧准备结果失效并回到未准备。海报作为次入口，称“制作海报”，不写“一键发朋友圈”。
- **接收页**：保留“只读分享”及“这是分享时的文字。原作者之后的修改不会更新到这里。”与记录入口；确认网络错误使用“暂时无法查看 / 请检查网络后重试。”，未知原因使用“请稍后重试。”，动作统一“重新读取”；失效“分享无法查看 / 分享已失效，可请分享者重新发送”，不推断是撤销还是到期。不可在只读页出现修改原作者内容的按钮。
- **收益/代价**：减少同时存在两个相似发送按钮的歧义；准备与系统分享仍是两次明确用户动作。允许取消，取消不能报“已发送”，不添加分享奖励或自动转发。
- **验收**：AC17、18。真实准备、审核、好友收取、扫码、过期与撤销在获授权的测试环境单独验收；链接服务和内容审核不以视觉改版为由放宽。

### UX09：“我的”按用途分组

- **依据**：首屏有“从记录到使用”说明和重复列表入口、每日回顾设置、分享区【O14】；会话统计与隐私说明在源码中存在【S】，本轮没有将未截图的下半页当成观察证据。
- **修改**：保留品牌和一句说明；列表组“我的分享 / 数据与隐私 / 使用帮助 / 意见反馈 / 关于”；“查看我的灵感”重复入口删除。回顾设置改名“显示回顾入口”，旁注“设置仅在本次使用期间有效，下次重新启动小程序后恢复默认。”。会话统计放“使用帮助—诊断信息”，默认关闭，保留用户主动复制，不自动上报。
- **收益/代价**：工具页更短，设置承诺更准确；诊断查看多一步。不得把该调整实现成云端偏好存储，没有此授权。
- **验收**：AC15、19。删除入口不等于删除功能；分享、反馈、隐私仍在2次页面内点击以内可达。

## 3. 优化前后的核心用户流程

步数不计算打字字数和系统键盘操作；当前路径来自离线样例，优化路径为设计目标。

| 任务 | 当前路径 | 推荐路径 | 变化与保护 |
| --- | --- | --- | --- |
| 第一次记下 | 记录 → 点输入 → 写 → 记下来 → 已记下 | 同一路径 → 内容摘录+继续补充/再记一条 | 不增加必填、登录和引导；仍需服务端确认 |
| 找回并补充 | 灵感 → 越过筛选和回顾 → 详情 → 填写 → 添加 | 灵感 → 最近内容/搜索 → 详情 → 上下文相邻的输入 → 添加 | 保留查询与位置；照片不插在输入和补充之间 |
| 长文补充 | 详情 → 滚过完整正文 → 输入 → 添加 | 详情 → 继续补充 → 输入 → 添加补充 | 原文完整保留；加定位，不默认折叠内容 |
| 单条取用 | 详情 → 整理内容 → 模板/材料 → 生成使用稿 → 编辑/复制 | 详情 → 整理成稿 → 编辑/复制；按需调整材料/格式 | 少一次显式生成；不自动改写 |
| 多条取用 | 灵感 → 选材整理 → 选材料 → 生成 → 复制 | 保留路径，统一结果编辑与反馈 | 不能默认选中所有私人内容 |
| 保存异常 | 输入 → 保存 → 错误提示 → 重试原按钮 | 输入 → 保存 → 尚未确认 → 重试保存/复制内容 | 不清空、不假成功、不重复生成记录 |
| 外部分享进入 | 只读分享或错误 → 记录我的想法 | 先读内容 → 复制文字/记录我的想法；失败给准确恢复入口 | 不要求先读教程；不承诺可编辑作者原文 |

自然回访亮点限三项：

| 体验亮点 | 解决什么问题 / 感受到的时刻 | 学习与维护成本 |
| --- | --- | --- |
| **一句话的后续** | 保存后的“继续补充”，详情将原文与时间线连在一起；用户下次有新线索时接得上 | 基于既有补充与历史，主要为重排和文案；不新增数据模型 |
| **拿走一份完整文字** | 一进整理就能编辑和复制；用户准备使用时才发现格式选项 | 复用拼接与复制；需维护替换确认和上限，不新增生成服务 |
| **旧想法，自己决定何时看** | 最近记录之后轻量回顾，用户闲时点开一条 | 复用推荐服务；会话内隐藏即可，不引入通知、跨日承诺或数据库偏好 |

## 4. 两个视觉方向与推荐

| 维度 | A：纸页与靛墨（推荐） | B：清晰工作台 |
| --- | --- | --- |
| 产品气质 | 私人的文字本；用户内容是画面主角，暖纸承载，靛墨指出操作 | 面向整理任务的工具；白底与冷灰分区，蓝色强调执行 |
| 配色 | 纸底 `#F7F6F2`，白承载，文字 `#191A23`，主色 `#34377F`，浅靛 `#EEEEF8` | 底 `#F3F6FA`，面 `#FFFFFF`，文字 `#172033`，主色 `#2459BA`，浅蓝 `#EAF0FB` |
| 字体层级 | 系统无衬线；标题24/600，内容17/400，详情原文19/500，辅助13/400；强调靠字号和留白 | 系统无衬线；标题22/600，内容16/400，区块标签13/600；强调靠网格和分隔 |
| 布局 | 20 px边距，12—16 px圆角；原文直接落底，编辑器白底；列表用连续内容行 | 16 px边距，8 px圆角；更紧凑的列表、直线分区；操作区集中到底部 |
| 识别元素 | 沿用现有书本标识，琥珀只在标识中；不新增插画或纸纹 | 沿用标识的小尺寸版本，弱化品牌区，强调搜索与结果数量 |
| 适用原因 | 承接现有风格，适合低压力随手记录，改造集中在层级和可读性 | 更适合经常批量整理大量材料、偏工作用途的人 |
| 风险 | 留白过大可能压低内容量，靠明确布局阈值约束 | 可能被理解为普通任务工具，个人想法的温度与辨识度较弱 |

**推荐 A**：当前产品已有相近色系与标识，保留可识别资产，优化集中在任务顺序。选择基于产品用途和实施成本；用户尚未做过偏好测试。B保留作同内容对照，不能以“多数人会喜欢”当结论。

### V01 首次进入：记录

顺序：原生导航栏“灵感拾光簿” → 40rpx页面边距 → 48px品牌标识+“记录想法”+“先写下来，之后再补充。” → 20px间隔 → 白色输入区 → 计数 → 主按钮。保持底部原生三tab“记录 / 灵感 / 我的”。

- 输入标签“此刻想到什么？”，正文上限2000，初始不弹键盘。示例仅当空输入时出现，不进入value。
- 空白/纯空白主按钮禁用；1—2000字符可点；提交中“正在记下…”且阻止重复提交，禁止同时编辑本次提交值。计数与当前领域校验统一沿用JavaScript字符串长度，不在本轮更改数据库长度口径。粘贴超限内容时保留全文，显示“超出N字符，请缩短后保存。”并禁用提交，不静默截断；实施时输入层允许完整接收，提交层继续遵守2000上限。补充输入同理，上限1000。
- 有未保存内容才出现未保存提示；错误紧邻提交按钮，不使用会消失的toast承载唯一失败信息。
- 使用原生导航和胶囊，不在WXML重复绘制。视觉稿的顶栏仅标示区域。

### V02 完成反馈：已记下

- 原输入区清空，保持可继续写。成功卡显示“已记下”、**实际此次确认记录**两行摘录和“继续补充”；下方“再记一条”聚焦输入。
- 不自动跳详情，不弹庆祝，不自动分享。成功卡保留到下次有效输入或离开页面；不是固定3秒消失。
- “继续补充”只能带本次保存ID，不能使用列表第一项替代。会话切换或未确认时不显示该ID。
- 若长文字摘录含换行，展示最多两行，不修改已保存内容。此稿用于验证连续记录与补充两条后续路径。

### V03 再次进入：我的灵感

- 标题24px，右侧44px热区“记一条灵感”；搜索48px高；一行“全部 / 有补充 / 筛选”。筛选活动状态同时有文字计数和视觉底色。
- “最近更新”区首先显示至少一条真实记录；回顾行在第一条之后，不占第一条位置；内容数量<2且没有候选时隐藏，不留空容器。
- 正文2行、元信息1行；有非默认阶段/标签再增加一行。多标签最多2个+数量，完整信息进详情查看。
- 真空态仅品牌、文案“还没有记录”、主按钮“记下第一个想法”；搜索无结果保留搜索和已选条件；读取失败用重试，不能展示真空态。
- 内容较多采用现有数据能力，先对100/500条测试滚动与搜索；如超预算再单独提分页/虚拟化提案，不假定后端已支持分页。

### V04 核心操作：详情与补充

- 顶部时间、“更多”，原文完整；其下“整理成稿”“继续补充”。短原文下直接是64px补充输入框；已有补充紧随输入区。
- 时间线显示时间、正文、“更多”（可访问名称标明补充对象）；AI来源只有实际来源为AI才显示。选中/错误不只靠颜色区分。
- 标签与阶段为时间线后的一行“整理中 · 城市散步 · 修改标记”，展开后有标签输入、阶段选择、保存标记/取消。取消恢复未编辑前值，保存失败保留输入；已有内容的默认展示不依赖表单打开。
- 照片在标签行后，能力关闭时隐藏添加入口；有既存照片仍可私有查看。图片失败保留占位信息“照片未加载 / 重新加载照片”，不会整个区块静默消失。
- “更多”项目顺序：修改正文、复制全文、分享文字、修改记录（有记录时）、删除灵感（危险组）。每行44px起，标签不被说明挤压；点击遮罩/取消关闭，焦点回到触发处。删除沿用明确对象确认，不能新增“撤销”假按钮。

### V05 查看结果：整理成稿

- 顶部“整理成稿”；一行“正文 + 2条补充”；“调整内容 / 选择格式 / 更多”；下方直接可编辑自由稿，原文和补充以空行分隔。
- 编辑器最小240px，长稿允许滚动，光标与最后一行不被底部操作区遮住。主按钮“复制稿件”，次按钮“另存为新灵感”。复制不执行另存。
- 复制成功常驻行“已复制，可粘贴到需要的地方。”；复制失败“复制未完成，请重试。”。所有通知必须来自实际回调。
- 更多包含“文字留档”；留档继续显示包含项、排除照片、外部副本不会随删除消失的说明。生成TXT、发送TXT仍需平台适配，不移除现有能力。
- 缺失/网络失败按UX05显示，不进入空白编辑器。

## 6. 统一视觉规范与关键交互

### 6.1 单位与适配

- 设计基准为375 CSS px宽；WXML布局采用750rpx基准。`实际px = rpx × windowWidth/750`。文档写的px均为逻辑像素，非截图物理像素。
- 边距/组件圆角可用rpx；**字体、44px最小热区和1px边框用逻辑px兜底**，避免320宽时整体缩得过小。如沿用rpx字号，需使用min/max规则确保正文不低于16px、辅助不低于13px；实测基础库CSS支持后实现。
- 小屏320、360/375；常用390；大屏430均检查。长文自然换行，按钮不限制固定height，使用min-height+上下padding，1.3倍字号仍可增高。
- 使用原生navigationBar和tabBar。普通页面底部为24px留白+实际安全区；固定操作区才另加自身高度的内容padding。不要重复加原生tabBar高度、不要把截图里的状态栏写死为导航高度。
- 非tab页如需底部固定操作栏，内容底部padding至少为栏实际高度+16px，安全区只算一次。`getWindowInfo().safeArea` 缺失时按0兼容，不能假设所有设备有home indicator。[官方窗口信息](https://developers.weixin.qq.com/miniprogram/dev/api/base/system/wx.getWindowInfo.html)

### 6.2 颜色与字阶（A方向）

| Token | 值 | 用途 / 规则 |
| --- | --- | --- |
| paper / surface | #F7F6F2 / #FFFFFF | 页面底/可编辑承载面，不用多层卡片套娃 |
| ink / ink-secondary | #191A23 / #5F6070 | 正文/解释文字 |
| ink-tertiary | #6F6F7B | 时间与计数；13px起，不用于关键错误 |
| brand / brand-soft | #34377F / #EEEEF8 | 主按钮、选中/轻强调；白字主按钮 |
| field-border | #858596 | 输入框边界；不能用装饰分隔线当唯一输入提示 |
| separator | #E6E4DE | 非交互分隔，不能承担状态或控件识别 |
| success / success-bg | #24604B / #EDF6F0 | 成功文字及底；同时写明确结果，可沿用已区分的成功符号 |
| danger / danger-bg | #B43C32 / #FBEEEC | 失败/危险动作；有标题和恢复动作 |
| warning / warning-bg | #805B1F / #FDF4E3 | 未确认、接近上限；不拿警告形状表示成功 |
| disabled | #E7E7EB + #72727D | 禁用；非空白占位，不代表错误 |
| spark | #E4A83A | 仅现有品牌标识，不用于正文和白底细小状态文字 |

| 类型 | 字号 / 字重 / 行高 |
| --- | --- |
| 页面标题 | 24px / 600 / 1.3 |
| 详情原文 | 19px / 500 / 1.65，统一系统无衬线以减少双端字族差异 |
| 记录/稿件编辑内容 | 17px / 400 / 1.65 |
| 列表正文/补充 | 16px / 400 / 1.6 |
| 按钮 | 16px / 500或600 / 1.4 |
| 区块标题 | 15px / 600 / 1.5 |
| 辅助、时间、计数 | 13px / 400 / 1.5 |

文字与底色普通文字目标≥4.5:1；大字≥3:1；关键控件边界和状态识别目标≥3:1。这是本次工程验收目标，不宣称完整WCAG合规。具体组合与计算见证据目录的 `contrast.json`。

### 6.3 间距、圆角与组件

| 对象 | 规格 |
| --- | --- |
| 间距系统 | 4/8/12/16/20/24/32px；同组8—12，区块20—24，页面水平20 |
| 圆角 | 输入/按钮8px；卡片12px；弹层16px；标签4px；不把所有元素做胶囊 |
| 主按钮 | 高度至少48px，宽度随容器；每个操作区仅一个实心主按钮 |

### 6.4 状态矩阵

所有面向用户的字符串使用[文案定稿](UX-COPY-20260930.md)。品牌句沿用“让想法慢慢成形”，操作名称、计数单位和状态说明不得各页自行改写。

| 场景 | 展示 / 可操作项 | 保留与清理规则 |
| --- | --- | --- |
| 首次进入/空数据 | 输入主入口；空列表只有开始按钮 | 读取成功才判空 |
| 首次加载 | 静态骨架或“正在读取…”；超时后出现重试 | 不先闪空态；不显示旧账户内容 |
| 同账户刷新中/失败 | 保留已确认列表；顶部“刷新未完成”+重试 | 不把失败覆盖为空列表；账户变化除外 |
| 输入中 | 字数、未保存提示、有效内容才可保存 | 仅会话内，不承诺跨退出恢复 |
| 提交中 | 按钮具体进行中文案、禁重复 | 本次内容快照冻结；UI回执必须匹配账户/请求 |
| 已确认成功 | 成功形状/文字、明确对象及下一步 | 成功才清空；不靠定时器假设成功 |
| 确认被拒绝保存 | “未能保存”及已知原因 | 不编造失败原因，原输入保留 |
| 弱网/超时且结果未知 | “尚未确认保存”+重试保存/复制内容；见 C12 | 不同时显示“尚未保存”；重试幂等；迟到成功后清除错误 |
| 版本冲突 | “这条内容有更新，请重新读取后再保存。”+重新读取 | 先保留本次输入/复制入口，不能静默覆盖他端内容 |
| 权限拒绝 | 摄像头“未获得相机权限，可从相册选择或去设置。”；隐私未同意“同意隐私说明后可添加照片。” | 区分用户取消、隐私拒绝、相机拒绝、保存相册拒绝；文字记录仍可用 |
| 图片失败 | 单图“照片未加载 / 重新加载照片” | 不把临时路径当公开链接，不记录图片内容日志 |
| 内容缺失/分享失效 | 明确不可用、返回列表或开始记录 | 网络失败不显示已删除；不把私有原文放入错误页 |
| 长文本/很多内容 | 全文可达、搜索、长文定位 | 不静默截断，不默认选中大量内容 |

| T01 理解与开始 | “看一下这个小程序，告诉我你觉得它能做什么，再记下你刚想到的一件事。” | 5秒内能说出记录并以后继续/使用，10秒内找到输入入口；至少4/5人无讲解完成。时间目标需先测基线后校准 |

| T03 再次查找 | “这里有20条记录，请找到含‘雨天替代安排’的那条并补一句。” | 至少4/5人无求助完成；记首次点击、搜索词、误触、回退、耗时；目标中位耗时≤30秒，须先测现状再定改进幅度 |
| T04 取用与修改 | “把这条正文和两条补充整理成可以粘贴的文字，改一句，再换格式但保留你的修改。” | 至少4/5人理解稿件与原文区别；所有人取消替换后编辑不丢；复制内容准确，无虚构事实 |
| T05 弱网与退出理解 | “这里提示保存还没确认，你会怎么处理？如果现在退出，你觉得会怎样？” | 所有人能判断尚未确认，不保证下次存在；能指出重试或复制。记录提示是否造成误解或焦虑 |
| T06 视觉与推荐 | 展示随机顺序的A/B，同任务操作后追问偏好与原因 | 记录可读性、可信度、识别度和工具感；至少能用一句话介绍产品价值；不以投票数直接宣称A更好 |

记录模板：匿名受试者编号、情境、任务、起止时间、是否完成、是否求助、犹豫位置（停顿≥3秒仅作观察标记）、误触/返回次数、原话、问题等级、证据时间戳。任务内容用合成数据；不记录私人灵感和身份信息。

后续如获上线数据授权，再观察“首次确认保存”“成功后继续补充”“按需复制稿件”“带目标的再次查找”这些事件。分母、观察窗口和样本量须先定义；现有会话统计不能作为跨天留存数据。本轮没有转化率、留存率提升结论。
