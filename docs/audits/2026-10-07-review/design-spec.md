# 灵感拾光簿：关键页面改版规格

日期：2026-10-07。交付性质：审查后的建议设计；本轮未修改小程序代码、服务端、部署配置或数据库。配套可视化为同目录 `design-board.html`。其中人物、文字、条数和时间均为设计样例；AI 区的文字由设计者编写，不是实际模型输出。改版稿不证明真实功能可用。

## 1. 设计依据与保留项

已读 `AGENTS.md`、`docs/detailed-design.md` §0 文档地图、`docs/ui-design.md`，并核对 `miniprogram/app.wxss`、`app.json` 及 capture、list、detail、output、material-output、ai-workbench、share-preview、shared 的 WXML 与相关服务。以下“当前”指 2026-10-07 源码，运行观察由主审查报告另行标注；历史 HTML 原型与旧截图不作为本轮实际观察。

| 值得保留 | 当前源码依据 | 用户收益与本轮处理 |
| --- | --- | --- |
| 暖纸底色、靛蓝主色、金色品牌小标记 | `app.wxss` 的 paper / brand / spark | 有私人笔记本的温度，主操作可辨认；方向 A 延续令牌，避免整套换皮 |
| 原文在页面底色上，完整展示；补充相邻 | `detail/index.wxml` 的 origin / detail-next / timeline | 一眼认出自己的内容；保留正文锚点和时间线，不改成信息仪表盘 |
| 连续列表、细线分隔、整行进入 | `list/index.wxml` 的 list / row | 便于扫读，减少重复“查看”按钮；保留连续承载面 |
| 记录只需输入与点击，不放示例行 | `capture/index.wxml`；ui-design §2 的既有用户决定 | 尊重随手记录场景；不恢复示例 chips、每日任务或自动弹窗 |
| 未知保存保留输入，重试与复制可见 | `capture/index.wxml` unknown 分支；detail 未确认状态 | 保住已经付出的输入劳动；扩展到所有稿件另存场景统一语义 |
| 整理页进入即有可编辑稿件 | `output/index.js` 的 build；`content-output.js` 模板只编排既有文字 | 第一次看到结果不用先回答表单；保留默认自由稿和复制主操作 |
| AI 选材、可编辑预览、显式采纳 | `ai-workbench/index.wxml` | 用户能核对并保留控制；保留原始材料与预览分层，避免把预览说成已保存 |
| 分享前明确范围，可撤销链接 | `share-preview/index.wxml`；sharing 服务 | 分享个人想法时可预见风险；照片、修改历史保持私有，保留失效与举报入口 |
| 44px 热区、16px 正文和 13px 辅助字下限 | `app.wxss` 的 max() 兜底 | 小屏可点、可读；本轮只补齐页间一致性和真实适配验收 |

推荐服务对象是“经常在手机上出现零散工作/创作想法，之后要把它们用于表达或执行的人”。这是由现有社交内容、短视频脚本、工作提纲、行动清单模板推得的目标用户假设，需要访谈验证。暂不把熟人协作、团队任务管理、积分运营或热度评分加入核心价值。

## 2. 两种视觉方向

| 项目 | A：纸页与灵光（推荐） | B：清晰工作台 |
| --- | --- | --- |
| 气质 | 安静的私人笔记、清楚的成稿工具 | 更直接的工作材料工具 |
| 主色 / 底色 | 沿用靛蓝 `#34377F` / 暖纸 `#F7F6F2` | 深墨绿 `#145B4A` / 近白 `#F5F9F6` |
| 辅色 | 金 `#E4A83A` 仅用于既有品牌灵光 | 薄荷 `#DEF1E7` 承载选中区，墨 `#172D26` 做标题 |
| 排版 | 原文 19px，宽松行距；标题 24–26px；行与线组成内容节奏 | 标题 24px，元信息更规整；结构标签更醒目；输入面略紧凑 |
| 识别方式 | 既有 brand-mark、暖纸、靛蓝动作和原文排版 | 深墨标题、薄荷选中块、对齐的步骤标记 |
| 适合用户 | 随手记下，再慢慢完善的工作/创作用户 | 高频批量整理、追求效率的用户 |
| 代价 | 需要补足“整理后能拿来用”的表达，避免只像普通笔记 | 需要更新品牌与全部语义配色，工具感可能削弱私人记录的亲近感 |
| 本轮取舍 | 保留已有辨识度，把资源投入价值说明、成稿与分享闭环 | 保留作对照方向，不建议本轮实施 |

A 的变化集中在内容顺序和动作优先级：首屏说出“记下一闪念，整理成可用稿”；详情先看原文与补充，整理能力在需要时展开；成稿能直接复制并发起受控分享；接收页先看文字价值，再开始自己的任务。颜色不会承担功能承诺。B 的薄荷只是一种备选视觉系统，不能叠加到 A。

## 3. 推荐方向的基础规格

### 3.1 颜色

| Token / 用途 | 值 | 使用约束 |
| --- | --- | --- |
| `--paper` 页面 | `#F7F6F2` | 所有私人页面统一；二级页不随功能换主题 |
| `--surface` 承载面 | `#FFFFFF` | 输入、连续列表、可编辑稿件、分享预览 |
| `--ink` 标题/正文 | `#191A23` | 正文与标题；避免大量纯黑装饰块 |
| `--ink-2` 次要说明 | `#5F6070` | 价值说明、来源和状态说明 |
| `--ink-3` 时间/计数 | `#6F6F7B` | 最小 13px；不再降透明度 |
| `--line` / `--line-strong` | `#E6E4DE` / `#D7D4CB` | 非交互分隔线 / 承载面边线 |
| `--field-line` 输入边界 | `#858596` | 表单、未选择框，不用浅分隔线代替输入边界 |
| `--brand` / `--brand-soft` | `#34377F` / `#EEEEF8` | 主按钮 / 选中与确认成功底；白字主按钮 |
| `--brand-line` | `#C9CAE6` | 次级按钮描边；焦点描边用 brand 实色 |
| `--spark` 品牌 | `#E4A83A` | 仅品牌灵光与已有“当前”锚点；不承载小字、警告、成功、评分 |
| `--danger` / `--danger-soft` | `#B43C32` / `#FBEEEC` | 确认拒绝、删除等；配叉形图标及明确说明 |
| `--warn-ink` / `--warn-soft` | `#8A6420` / `#FDF4E3` | 保存结果未知、离开风险、AI 准确性提示；配感叹号 |
| 禁用填充 | `#E4E4EC` | 按钮置灰且 disabled；解释禁用原因；可编辑文本不作低对比灰化 |

正文与辅助文字对页面及承载面目标对比度均为至少 4.5:1，焦点/输入边界目标为至少 3:1；需按最终相邻色回算。警告、失败、成功同时由标题、形状、文案区分，灰度状态可识别。不会用纯颜色或“红点”表达保存结果。

### 3.2 字体、布局与组件

| 项目 | 375px 参考 | WXSS 建议 |
| --- | --- | --- |
| 系统字体 | 苹果/安卓系统中文字体 | 沿用 app.wxss，不下载字体、不把文案绘制成图片 |
| 首页价值标题 | 26px / 36px，600；最多两行 | `52rpx`，必要时 `max(48rpx,24px)`；不固定容器高度 |
| 其他页标题 | 24px / 31px，600 | 沿用 `48rpx`；字号与正常字重由系统字体承载 |
| 详情原文 | 19px / 32px，400 | 沿用 `38rpx`、1.7–1.78；完整展示，不逐字省略 |
| 输入/稿件/列表正文 | 16–17px / 27–29px | `max(32rpx,16px)`；稿件保留换行，超長字串可折行 |
| 标签/辅助说明 | 13–14px / 20–22px | `max(26rpx,13px)` / `max(28rpx,14px)` |
| 页面水平留白 | 20px | 沿用 `40rpx`；320px 屏至少 16px |
| 区块间距 | 24px；关联内容 8/12/16px | `48rpx` 主区块；不以空白挤走核心输入 |
| 面内留白 | 16px；列表行上下 16px | `32rpx`；详情原文不加承载卡 |
| 圆角 | 按钮/字段 8px，承载面 12px，底部面板 16px | 现有 16/24/32rpx；不新增多套半径 |
| 主按钮 | 建议高 48px，字 16px；每个任务区一项实色 | `min-height:96rpx; min-height:max(96rpx,48px)`，两层宽度选择器 |
| 次级/链接按钮 | 有效热区至少 44×44px | 原有 `min-height/min-width:max(88rpx,44px)`；文字 14–16px |
| 输入边界 | 1px field-line；焦点 2px brand；label 常驻 | 不能只靠 placeholder 解释字段；错误文案在字段下 |
| 选择行 | 行高随文字增长，最小 72px；整个行可点 | 22px 可视选择框，整行至少 44px；选中编号/勾形+颜色 |
| 图标 | 沿用 81px 源 PNG 的 tab 图标；其他统一线性 20–22px | 不用 emoji 替代图标。更多保留文字；decorative image 不误报为按钮 |
| 动效 | 按压 80–120ms；成功区不自动跳走；骨架静态 | loading 用原生 spinner；不加入连续闪烁、积分动画或自动轮播 |

通用组件继续放 `app.wxss`，页内布局放各页 WXSS。本轮设计稿使用 CSS 绘制结构，实际小程序继续用原生 WXML/WXSS；HTML 的 device 外框、桌面标题和样例标签均为交付说明，不进入产品。

### 3.3 微信页面与输入适配

- 保留系统导航栏，三个 tab 的标题为“灵感拾光簿”，二级页使用功能名；不叠一套自制胶囊或自定义返回按钮。设计稿胶囊只是安全区占位。
- Tab 页面采用普通页面滚动，避免输入 textarea 与多层 scroll-view 争手势。顶栏以下内容自然排版；页面底部留现有 safe-area 空间。
- 记录输入不在进入时自动聚焦，用户点字段后开键盘。首次空输入建议固定可见 160px、输入后允许增长或转受控滚动；真机比对当前 auto-height 后再定，不能仅靠 HTML 推断键盘。
- textarea 保留完整输入，`maxlength=-1`，由提交层校验 2000 字正文 / 1000 字手工补充；AI 单条 200 字、汇总 2000 字，依既有 LIMITS。超限提示明确差额，复制仍可用。
- `cursor-spacing=24`，监听 `bindkeyboardheightchange` 或已有键盘回执，仅当键盘高度大于零隐藏浮动整理/补充动作。提交按钮随页面位于输入之后；键盘不应盖住当前光标和保存提示。
- 选材、AI 的固定底部区需要测量自身高度，滚动内容 bottom padding >= footer 高度 + 16px。键盘出现时编辑页操作区随输入重排或退出 fixed；不能把一套 `position:fixed` 同时用于全部页面。
- 面板优先 70–80% 可用高度，静态标题和底部动作、内部 scroll-view 的可用高度沿用现有测量；关闭按钮始终可见。
- 320/375/414px、系统字体 100/120/140%、iOS/安卓带安全区与无安全区分别验收。大字号按钮可换行并增高，禁止固定高度截字；两按钮空间不足时上下排列，保持各自 44px 热区。长英文/链接使用 word-break，正文仍保留段落。
- 返回、系统退出和页面重入继续绑定原有 page/session/store 版本。改版不能把旧成功提示、旧预览或旧分享链接带入新账户、隐藏页或新页面。

## 4. 关键页面规格

### P01 首页：先记下，再看到用途

**目标**：第一次进入知道“我可以先写一句，之后把它整理成可用稿”，并在首屏开始输入。再次进入能接续自己的最近想法，不要求打卡。

**首屏顺序**：系统导航 → brand-mark（52×52px）与小字“灵感拾光簿” → 两行标题 → 一句收益说明 → 原生输入承载面 → 字数/输入状态 → 全宽主按钮 → 一行流程 → 隐私说明。375×812px 参考：内容始于 y=96；输入位于 y≈252–425；主按钮 y≈476；tab 顶部 y≈731。标题自然增高时下文滚动，不绝对定位。

| 元素 | 具体文案/规格 |
| --- | --- |
| 主标题 | “记下一闪念，\n整理成可用稿” |
| 说明 | “先写一句。需要时，把零散想法整理成能直接使用的文字。” |
| 字段标签 / placeholder | “此刻的想法” / “此刻想到什么？”；不加示例行、不注入内容 |
| 主按钮 | “记下来”；非空、不过限且账户/保存条件可用后启用；提交变“正在记下…” |
| 流程行 | “记录 → 补充 → 成稿”；13px，作为流程说明，不可假装 tab |
| 隐私行 | “灵感默认仅你可见。”；无照片/AI 尚未验证的效果承诺 |
| 成功 | 保留“已记下”+两行确认内容；主按钮“继续补充”、次按钮“整理这条”、低强调文字链“再记一条”。不自动跳转；保持可确认的成功回执。可有低强调“看看如何整理”展开演示，但用户主动打开才显示，样例不进入自有记录 |
| 回来后 | 首屏输入仍可达；仅当账户读取成功且有记录时，下方一行“继续上次的想法”+真实最近更新摘录+“继续补充”。不得存本机草稿、不得称未保存文字为已记录 |

**状态**：空输入显示 0/2000，主按钮禁用；输入中显示“尚未保存，退出后可能丢失。”；加载账户不挡输入，但提交前不能假成功；保存中冻结本次提交；成功才清输入；未知显示“尚未确认保存”“内容还在输入框中。退出前请重试保存或复制内容。”和“重试保存 / 复制内容”；明确拒绝显示服务端已知原因，输入保留；超限显示差额。取消/离开沿用既有提醒规则，未知状态不再叠一套损失弹窗。

**验收**：未滚动即可看到输入和主动作；首次用户在不讲解的情况下能说出记录与成稿两种用途；空态无功能按钮堆叠；未知时输入字节不变、重试不新增第二条。回访入口只引用当前账户已确认记录。

### P02 灵感列表：方便找回与取用

**目标**：找到相关想法，继续补充或组合成稿。

**顺序**：标题“我的灵感”与“记一条灵感” → 搜索 → 全部/有补充/筛选 → 已有条目时一行“选材成稿”与次级“AI 汇总” → 最近更新 → 连续列表。现有入口、导航标题、页内标题和返回操作的用户文案统一为“选材成稿”，route 继续使用 material-output，不改文件名。

- 第一行条目：正文至多两行、真实时间、补充数量；默认“想法”阶段不占额外行，标签最多两项。元信息不过度突出，AI 来源需要标注。
- 保留现有第一条后的“回看一个想法”，不自动展开、不推提醒。恢复列表位置、搜索和筛选行为保留。
- 按钮数量多时工具动作上下排，不挤成四个小字入口。AI 是否露出依据真实能力与服务器状态，不靠客户端布尔值作可用性承诺。
- 真空态“还没有记录 / 从一个想法开始，之后再补充。”“记下第一个想法”；无结果“没有找到匹配的灵感 / 试试其他关键词，或清空搜索和筛选。”“清空搜索和筛选”；仅剩已合并保持“查看已合并内容”；加载静态三行骨架；首次读失败保留“重新读取”；刷新失败保留当前列表并标注刷新未完成。

**验收**：首次空态只有一个主操作；返回列表位置保留；检索命中补充时能看到匹配摘录及来源；AI 不可用时选材成稿仍可达；没有虚构最近进度、热度或统计。

### P03 灵感详情：原文、补充、用途形成一条线

**目标**：认出自己的内容，添上新想法，再按需要整理。

**首屏顺序**：时间·更多 → 原文 → 任务行“继续补充 / 整理成稿” → 低强调入口“AI 整理” → 补充输入（64px 折叠 / 160px 活跃）→ 已有补充时间线。阶段/标签、照片仍排在时间线之后。推荐把 AI 扩展与汇总补充归为一项“AI 整理”，点击才选择“扩展这条想法 / 汇总已有补充”；要保留一条点击直达的常用入口可在工作台自动依据来源 scope 确定，新增路由选择需要提案，不用伪装已实施。

| 元素 | 文案与规格 |
| --- | --- |
| 原文 | 19px / 32px，页面底色，无卡片边框；完整可选择文字 |
| 补充标题 | “继续补充”；placeholder“又想到什么？” |
| 补充主按钮 | “添加补充”；保存中“添加中…”；未知“重试保存” |
| 时间线 | “补充 · N 条”；每项先时间后文字，右侧“更多”44px；正序，已收起单独展开 |
| 低频操作 | 更多中的修改正文、复制全文、分享文字、修改记录、删除灵感；危险项分组 |
| 长正文 | 超过约六行继续沿用浮动“继续补充”，键盘出现隐藏；整理不是永久悬浮主按钮 |

**状态**：加载原文骨架；读取失败不能说已删除；确认不存在“找不到这条灵感”；补充空态“还没有补充，可以从上方写下一句。”；上传能力未确认则不渲染空照片区；AI 不可用不能挡补充；写入失败/未知保留输入；已合并提示可恢复来源。删除确认保留摘录与时间，结果未确认不移除内容。

**验收**：375px 下约三行原文与一条补充时，首屏能看到补充入口和至少首条补充开头；长原文不强求首屏全显示；当前光标不被键盘遮挡；返回/取消编辑保留正确上下文。

### P04 选材成稿：先选内容，再得到能改的稿

**目标**：把多条灵感中的相关文字放到一份稿件，保持选择与排序可解释。

**顺序**：标题“选材成稿” → “把相关的文字放到一起，整理成一份稿件。” → 搜索素材 → “全部 / 只看已选”切换 → 正文/补充行 → 底部数量与“整理成稿”。“刷新素材”保留为低频文字入口；显示原来源摘要，整行点选；可视编号 1、2…表示稿件顺序，与现有服务一致，不在本轮额外发明拖拽排序。

- 底部 375px 参考高 112px（含34px safe area），主按钮 48px，标题数量“已选 N 段 · 来自 M 条灵感”。上方说明“按选择顺序排入稿件。”限值沿用最多 40 段/20 条/12000 字，不把 UI 改版与提高限值绑定。
- 未选默认全不选，禁用“整理成稿”，说明“至少选一段文字”；搜索无结果显示“没有找到匹配的素材 / 换个词，或显示全部素材。”“清空搜索”；只看已选且为空显示“还没有选中素材”“显示全部素材”。
- 已选行加 1px brand 实线、brand-soft 底、编号，不只改变颜色。全部来源过长可在行内展开，展开不取消选择。
- 生成手工稿件的按钮不用“AI 生成”；进入结果说明“只编排所选文字，不自动补写。”
- 回选材保留已有稿件；再次整理且改过稿时继续现有替换保护；来源内容变化保留当前稿件，要求刷新选材。P1 明确建议：临时进入后台或同会话返回时恢复本次选择、格式与手工稿件。主审查已在合成 hide/show 中观察当前 material-output 会清掉编辑稿与选择；该问题不是要新增本机持久草稿。

**验收**：选中顺序与最终稿件一致，补充始终有来源；取消再选排末尾；底部按钮不盖最后一行；无网络/AI 时已有已确认会话内容仍可手工编排，另存必须按现有服务确认。

### P05 可编辑成稿：使用结果成为主任务

**目标**：确认、编辑、带走文字；分享恰好在觉得结果有用的时刻出现。

**顺序**：标题“整理成稿” → “正文 + N 条补充 · 自由稿”（跨条注明 N 段/M 来源） → “调整内容 / 选择格式 / 更多” → 编辑区 → 字数与未另存提示 → 主按钮“复制稿件” → 次按钮“另存为新灵感” → 次级传播按钮“保存并预览分享”或已另存时“分享这份稿件”。编辑区首屏高约 240–320px，可自然随小屏减少但不低于160px；字号16px/1.75。375px 下主按钮一行，另存/分享可等宽并排；320px或大字号时改为上下排并允许页面滚动。不会把样例中的已填写目标、下一步伪装成规则模板会自动产出的内容。

**格式**：保留自由稿/社交内容/短视频脚本/工作提纲/行动清单五种。换格式先预览模板结构，材料仍完整；手工改动后替换需确认，取消保持原字节与光标。默认自由稿。

**分享落地优先方案（建议新行为，需提案）**：复用已有分享协议，避免第一期直接开放任意未保存稿件的公开接口。未另存点击“保存并预览分享”，展示一句“分享前会将这份稿件另存为新灵感。”和“保存并预览 / 继续编辑”；用户确认后走现有稳定标识另存，成功才进入该新灵感的 share-preview。原始来源保持。保存未知停在稿件、提供重试与复制，不能生成链接。已另存且内容未变则直接进入该保存版本的预览。编辑后分享必须先确认新的稿件版本，不能共享旧 savedId。按钮说明的是准备路径，实际发给好友仍由下一屏用户点击系统分享。

**状态**：没有有效源返回明确缺失页；加载先骨架；稿件清空时复制/另存/分享禁用，说明“稿件还没有内容”；复制成功给“已复制，可粘贴到需要的地方”，复制失败保留编辑；另存中冻结本次稿件，未知用黄色常驻区与稳定重试，明确拒绝用红色；已另存显示“已另存”与“查看新灵感”，不重复新增；改稿后恢复另存能力；超2000字仅禁另存/依赖另存的分享，不禁复制。

**验收**：单条详情→整理成稿→复制，不超过两次点击；复制文字不混入品牌/时间/标签；现有手工模式零 AI 调用；分享版本与屏幕全文严格一致；取消分享不会删除或收起来源。保存失败的提示文案与状态必须在 output 和 material-output 一致。

### P06 AI 工作台：看得懂材料，控制采纳

**目标**：在已有文字基础上获得候选思路，核对、编辑、明确保存；使用它时能理解来源和后果。

**顺序**：小阶段“选择素材 → 核对与保存 → 已保存”中的当前阶段 → 功能标题 → 原文面板 → 可选补充/灵感 → 数量与字符 → 本次使用范围 → 常驻底部“返回 / 生成 AI 预览”。扩展至少8字原文，汇总至少2条、最多20条、12000字；保留当前 LIMITS，不通过 UI 放宽。

预览中：风险提示“由 AI 生成，可能不准确，请核对后使用。”；“预览尚未保存，离开后不会保留。”；三个分区“要点 / 下一步 / 风险”，虚线浅底草案与可编辑项；展开编辑的文字不小于16px；每项勾选对应“保留这条…”。汇总是一段连续文本，不强拆分区。底部复制与明确保存，语义沿用现有能力；写回与收起来源必须明确目标、后果和确认，不能因改版默认危险模式。

**状态**：生成中显示原材料和“正在梳理内容，请稍候。”，仅禁相关生成/材料变化；后端不可用显示“暂时无法使用 AI 整理”“可以先把所选文字整理成稿。”“手动整理 / 稍后重试”；触发一次已知 AI_DISABLED 后本次会话降低入口强调，避免无限重试循环（新行为需提案）。额度/审核类确定拒绝使用明确原因，不能把所有错误写成重试。预览保存未知冻结选择/模式/文字，保留复制和同请求重试；来源变化要求重选/重生成；成功给“查看已保存内容 / 返回灵感列表”。同会话返回或后台重入先恢复只读编辑草稿，重新认证相同账户并核对相同scope/来源后才解锁编辑；旧请求即使返回也不重新写入或显示新结果。

**验收**：未实际开放时不展示样例模型结果；用户能区分原文与候选内容；不采纳的项不写入；同会话后台/返回后按下述规则恢复草稿，明确“放弃预览”或杀进程才清除；AI 不可用时手工成稿出口可用；一次生成的失败不清掉材料。

**同会话草稿规则（P1建议，需提案）**：只在会话内存保存选材、格式、编辑文字和已有预览；按受信账户上下文、session/generation、scope、来源标识和内容版本绑定。onHide/onUnload 令旧网络请求与页面版本失效，显示的敏感内容撤下；重新进入先恢复只读文字，再认证相同账户并检查来源未变，成功后解除编辑限制。账户切换/代际改变不得跨上下文恢复；来源变更保留文字供复制但禁止沿旧来源保存，提供重新选材；保存未知仍冻结其对应提交并使用同标识重试。草稿不写 Storage、文件或云端，不扫描旧缓存；杀进程不恢复。真正“放弃预览”需用户明确决定，不能把切到后台等同放弃。现有离开提示需要随本规则更新，准确说清哪些退出会丢失。

### P07 分享预览：范围清楚，操作可预见

**目标**：明确接收者看到的版本、范围和有效期，再进入微信分享。

**顺序建议**：标题“分享这份文字” → 一句“确认对方会看到的内容。” → 对方将看到的内容摘要/全文承载面 → 本次范围（正文/已选补充） → “调整分享内容”（有补充时展开已有选择） → 访问范围/有效期 → 全宽准备按钮 → 准备成功后同位置“选择微信好友” → 低强调“制作海报 / 我的分享”。成稿另存来源已包含选材内容，默认无补充，不能再把原素材隐式带出。内容范围以可见全文为准。

| 元素 | 文案/规格 |
| --- | --- |
| 正文 preview | 16px/1.75；长文先前6行+“展开全文”，用户可核对所有文字；展开按钮44px |
| 内容范围 | “仅分享下方文字。照片和修改记录不会加入。” |
| 链接说明 | “链接有效期30天，获得链接的人都能查看。撤销链接无法收回已复制的文字或已保存的海报。”保留当前真实规则，远端需验收 |
| 准备按钮 | “确认内容并准备分享”；loading“准备中…”；就绪“选择微信好友” |
| 就绪反馈 | “内容已准备好，选择好友后发送。”不把准备完成报成已分享/已送达 |
| 微信卡片标题 | 单篇成稿优先作者可确认的文字标题；示例“周末旧物交换：一份活动想法”，不得默认“AI神器”“好友助力” |
| 微信卡片封面 | 5:4 安全框内，brand-mark+标题至多2行+一行价值“看一份想法如何整理成稿”；不公开照片、身份或全文敏感摘要。官方最终尺寸及分享表现按主报告的平台核验 |
| 海报 | 第二阶段，标题+经确认正文+小程序码；长文分页沿用现有实现。相册权限只在用户主动保存时触发，不提前授权 |

**状态**：加载/源缺失/审核失败/准备失败分开；准备失败保持当前范围；改变选择、来源或账户则让已准备分享失效，重新核对；从系统分享返回不声称发送成功；取消不自动生成第二份链接；海报失败仍可微信分享和复制。已创建链接在“我的分享”可撤销，撤销确认明确不能收回外部复制副本。主审查观察到含两条补充的预览在准备后新增 notice 会把“选择微信好友”推到首屏以下；因此核心准备/好友按钮放在独立底部操作区，正文区域预留该区实际高度，消息在固定范围内替换，不继续堆叠。

**验收**：对方看到的文字与预览逐字一致，照片/历史/被收起补充均不进入；用户能在发送前说出谁能查看、撤销的边界；系统发送需要用户主动二次点击；分享不以奖励或强制好友数换取功能。

### P08 接收者：先看到价值，再写自己的

**目标**：读懂朋友带来的文字，必要时复制使用；喜欢结构时快速完成自己的第一份记录/稿件。

**顺序**：品牌小标“来自灵感拾光簿 · 文字分享” → 内容标题 → 时间 → 只读全文 → “这是分享时的文字。原作者之后的修改不会更新到这里。” → 主按钮“用这个结构写自己的”（存在合规模板标识时） → 次按钮“复制这份文字” → 低强调“记下自己的想法”与举报。阅读本身不索取手机号、头像、相册；平台必要隐私说明按官方要求在实际调用相关能力前出现。

**“用这个结构写自己的”落地（建议新能力，需提案）**：分享记录仅新增现有五模板白名单的 `templateId` 元信息；只带结构，不把作者文字自动复制进接收者账户。点击后显示一句“沿用工作提纲的结构，内容由你自己写。”；复用现有输入页的会话内模板上下文，写一段自己的素材→服务端确认记下→进入对应格式的可编辑稿件→复制或另存。第一期只支持白名单格式，自由稿/旧分享缺少模板时主按钮改为“记下自己的想法”；用户可选择现有格式，不伪装存在作者结构。输入取消不产生新记录。模板上下文只保存在本次页面/会话；账户变化失效。

未登录/未授权：源码当前 share.get 前会读取账户，这一依赖需要产品与技术联合评估。建议只读 token 的分享读取从私有快照加载中解耦，同时仍由云函数受信身份做风控/访问校验；不信任 URL 的 AppID/OpenID。平台必要账户建立失败则保留“暂时无法查看 / 重新读取”，不逼用户先填资料。此协议调整在后续 OpenSpec 单列，不能只靠把授权弹窗隐藏。

**状态**：loading“正在打开分享…”；网络错误“暂时无法查看 / 请检查网络后重试。”“重新读取”；明确失效“分享已失效 / 可以请分享者重新发送。”“记下自己的想法”；缺 token 同失效入口但不露后台错误；举报仍可达；原作者修改不改变已发快照；旧分享无模板使用降级主操作；首次任务保存未知仍按 P01，不丢自己的输入。

**验收**：接收者先阅读内容，再决定创建；进入分享后不跳到私人列表；旧分享与无模板不报错；结构复用不复制作者个人文字；来源 token/身份不进入日志、统计或公开地址。首次有用任务完成后才出现自发分享入口。

## 5. 流程对照与设计取舍

| 流程 | 当前源码支持的步骤 | 推荐步骤 | 减少的负担 / 代价 |
| --- | --- | --- | --- |
| 第一次记录 | 首页“记录想法”→写→记下来→已记下→继续补充 | 首页看到记录/成稿收益→写→记下来→保留成功回执并选择继续补充/整理这条 | 一句价值说明让用户知道后续用途；不增加任务步骤，不恢复示例行 |
| 单条成稿 | 详情→整理成稿（进入即有稿）→复制 | 保留相同步骤，格式和编辑边界更清楚 | 这一条已有效；重点保证真实可用，不再强加选材步骤 |
| 跨条成稿 | 列表→选材整理→逐段选择→整理成稿→编辑/复制 | 列表→选材成稿→逐段选择→整理成稿→编辑/复制；来源、数量/顺序一致可见 | 不虚报少了点击；减少误选和不知道结果顺序的认知负担 |
| 成稿给朋友 | 稿件复制或另存；若要链接，需另存→打开新灵感→更多→分享文字→准备→好友 | 稿件→保存并预览分享（明确确认）→准备→好友；已另存时直接预览 | 减少查找已保存记录与更多菜单；增加一次明确保存确认，保护分享版本 |
| 朋友开始用 | 接收页读/复制→记录我的想法→空记录 | 接收页读/复制→用结构写自己的→写素材→保存→对应稿件 | 保留用途上下文；需要模板元信息及会话路由，开发成本中等 |
| AI 暂不可用 | 工作台错误→先手动整理 | 识别不可用原因→手动整理主出口；稍后重试为次项 | 降低重复失败的挫败感；真实错误分型及会话状态要有测试 |

## 6. 传播路径规格与测量接口

最适合的传播是“把有用的文字/稿件给一个相关的人”，例如讨论活动想法、发工作提纲、表达创作方向。分享者节省解释成本；接收者得到可读、可复制的文字，以及可复用的现有结构。没有证据支持邀请奖励、强制转发、排名或组队，把它们加入会分散私人记录价值并引入平台与隐私成本。

1. 自己整理并核对稿件，觉得它已经可以沟通。
2. 结果页主动点击分享，确认保存与内容范围。
3. 用户选择微信好友，收到的是明确的内容标题与品牌卡片。
4. 接收者进入只读页先看正文；可直接复制，也可按同结构写自己的内容。
5. 接收者完成自己的记录/成稿后，结果页出现同一分享入口；再次分享由内容需求触发。

测量只记录最小事件类型、入口类别、模板枚举、结果码和粗粒度耗时，不记录正文、照片、分享 token、openid、身份样本。建立匹配归因前需后续规范确认数据字段、保留期及告知。建议事件：`result_view`、`share_entry_tap`、`share_prepared`、`recipient_content_view`、`recipient_start_own`、`first_save_confirmed`、`first_result_copied`、`return_use`；系统分享发起不等于发送成功、打开不等于有用，wx 分享回调/后台数据可用范围由官方规则决定。

| 指标 | 定义 | 验证注意 |
| --- | --- | --- |
| 分享入口发起率 | 点击分享入口人数 / 看过可分享结果的人数 | 衡量意愿，不称真实送达率 |
| 分享准备成功率 | 准备成功次数 / 准备请求次数 | 与网络、审核、服务可用性一起看 |
| 接收者打开率 | 若可得合规匹配归因，收到有效页面打开的分享数 / 准备成功分享数 | 分母只是创建，不能当实际发送；未知曝光则标“无法计算真实打开率” |
| 首次任务完成率 | 来源接收页的新用户首次保存被确认人数 / 来源接收页开始自己任务人数 | 另报复制稿件人数，避免只测保存 |
| 结果使用率 | 复制或另存成功人数 / 看过稿件人数 | 复制不证明外部粘贴/使用，访谈补证 |
| 后续使用 | 相关需求再次出现后的7/14天记录或成稿人数 | 不以每日打卡为目标；样本少时仅报告实际人数 |
| 再分享 | 完成自己的结果后主动再发起分享的人数 | 值得分享与奖励驱动要分开验证 |

所有增长收益均为待验证假设。用户测试先看用户能否说出“我会把这份内容给谁、为什么”；无人愿分享时先修结果价值，不把按钮加亮当增长证据。

## 7. 可实施任务与依赖

## 8. 设计验收与用户测试

### 8.1 页面与状态验收

- P01/P03/P05/P06：分别检查未输入、输入、超限、提交中、确定成功、明确拒绝、超时未知；最后三种有不同标题与操作，截图带步骤、环境与来源；不得以 fixture 截图证明云端成功。
- P02/P04：真实空数据、读取失败、无搜索结果、仅剩已合并、长内容/标签、返回后位置；最末条目不被底部操作遮挡。
- P05：五种格式不会凭空补写事实；手工稿件可直接编辑复制；改稿后换格式确认，取消逐字保持；保存版本/分享版本一致；超过2000字仍能复制。
- P04/P05/P06：同会话后台→返回，重新认证相同账户/来源后恢复选择、手工稿件/预览；旧请求失效；来源变化可复制不能沿旧来源保存；账户切换无旧内容；杀进程不恢复，明确放弃才清除。
- P06：选择不足不调用；生成中不误跳结果；输出契约/审核失败不展示结果；未采纳不写入；保存未知与来源变化测试；不可用有可达手工出口。
- P07/P08：正文范围准确；取消好友选择不显示已发送；改选择旧 token 不能再次发；有效/撤销/过期/缺 token/网络失败分型；旧分享无 templateId 正常显示；照片、历史保持私有。
- 小屏与大字：每个主按钮44px以上，有焦点/按压/禁用；320px、140%字体下不横向溢出、字符不裁剪、双按钮会重排；键盘遮挡靠 iOS/安卓真机操作验证。
- 本地代码阶段按 AGENTS 运行 npm test / npm run check / OpenSpec strict；server/core 变更 build-cloud。WXML真实编译、模拟器、真机、真实云端、用户测试分别报告。

### 8.2 任务测试（建议8位目标用户，指标为验收目标，不是已有结果）

| 维度 | 操作与记录 | 可观察验收目标 |
| --- | --- | --- |
| 任务理解 | 看首页10秒，不讲解，问“它有什么用，你会怎么开始？” | 至少6/8能说出先记再整理的价值并找到输入；不能只回答“AI软件” |
| 首次完成 | 给真实个人灵感，记录→补充→整理→复制 | 至少7/8无关键提示完成；拆记输入耗时与界面操作耗时，不伪造云等待收益 |
| 操作耗时 | 观察找到整理入口、选择素材、复制/分享 | 记录中位数与最慢情况；与当前版同任务比较，报告实际差异，无预设百分比提升 |
| 错误恢复 | 测试环境注入保存超时、AI不可用，事先说明内容为测试材料 | 至少7/8知道内容未确认、能复制/重试；0人误认为已保存；AI失败能自行找手工整理 |
| 视觉感受 | 同等内容随机顺序看A/B，问可读性、亲近感、重点与喜好原因 | 不以“好看”总分独立决定；能指出主操作，阅读无明显障碍；保留每人理由 |
| 想用/回访 | 问下一次在哪个实际情境会用，任务一周后访谈 | 报实际提及场景与是否再次使用；“很喜欢”不算留存证据 |
| 分享意愿 | 给自己的成稿，问愿给谁/为什么；主动点击与拒绝原因分开记 | 不是强迫人人分享；至少出现具体收件人与价值理由才认为路径成立 |
| 接收者首任务 | 由另一测试者打开分享，读→写自己素材→取得自己的稿 | 至少6/8能理解只读分享与自有创作的区别；0人误以为原作者照片/账户被公开 |

优先看失败和犹豫点，访谈反馈与操作证据并排保存。样本小不外推总体增长；若用户觉得普通微信收藏或备忘录已足够，核对“材料接续→可用稿”是否真的解决其工作，不以分享机制替代价值。
