# 灵感拾光簿 UI 与交互实施复核

复核日期：2026-10-01。基线：`dev`，`a6dd036`；已核对与 `origin/dev` 一致。复核对象为当前客户端实现，对照 `UX-HANDOFF-20260930.md`、`UX-COPY-20260930.md` 及用户后续确认的调整。

本报告保留修复前发现；用户随后授权修复，最新实施与验证结论见 [UI与交互修复记录](UI-INTERACTION-FIX-20261001.md)。

## 1. 结论

**主要改版已落地，但尚不能判定“全部改好”。** 单条记录、列表、详情和整理成稿的主路径已更清楚；仍存在两个保存期间的输入一致性缺陷，以及多素材页样式回退、弹层安全区不足、未另存稿件离开提示缺失等问题。建议先完成下方 R01—R05，再进行真机验收。

本轮仅新增复核文档和证据，没有修改业务代码，没有部署、上传或提交。

### 已有效的设计，保留

- 记录页直接进入输入，保存后有摘录与下一步；无额外教程。没有输入示例是用户已确认的取舍。
- 列表先呈现最近记录，回顾后置；搜索与筛选入口明确，筛选面板能展开。
- 详情按正文、补充输入、补充时间线、标记、照片排列；补充菜单与删除确认更清楚。
- 单条整理进入即有可编辑自由稿；内容与格式按需打开；取消替换会保留已编辑稿件。
- “我的”收敛为用途清楚的入口。单个原生“提交反馈”按钮及删除“使用帮助”均符合用户后续决定，不要求恢复诊断、回顾设置或旧反馈入口。
- 缺失灵感的整理页提供返回列表，实测可以恢复；分享预览明确先确认文字内容。
- 启动页使用品牌与读取状态，慢读取、失败均有出口；现有实现不设最短停留时间，不建议增加等待动画时长。

### R01 添加补充：保存中的新输入会丢失

**场景与复现：** 详情输入 A，点击“添加补充”，将确认响应延迟 5 秒；等待中输入 B；A 成功后，输入框和会话草稿均被清空。记录只包含 A。证据：`22-supplement-pending-edit.png`、`23-supplement-input-lost.png`、`behavior-reproductions.json.supplementEditDuringSave`。

**原因：** `pages/detail/index.wxml:67` 的 textarea 未绑定提交期间禁用；`index.js:519` 输入处理继续接受内容；`:564` 成功后无条件清空当前输入。

**修改要求：** 推荐提交时冻结该补充编辑器，并在输入事件层阻止提交期间变更；按钮显示“保存中…”，保留提交的 A。若选择允许继续输入，则成功回调只清空仍等于 A 的输入，B 保留且可再次提交。两种方案选定一种，不混合状态。

**流程：** 输入 → 点击添加 → 冻结 A、显示进行中 → 确认成功、时间线新增 A、清空 A；失败则解冻并保留 A。不得新增持久草稿。

**收益与代价：** 消除无提示的内容丢失；冻结方案仅短暂限制输入，成本小。

**验收：** 延迟 5 秒、输入/粘贴 B、连续点击、失败、旧账户响应迟到分别测。B 必须无法写入或完整保留；只新增一次 A；失败不清空 A；迟到响应不能修改新账户页面。补充回归断言与开发者工具截图，真机复测输入法。

### R02 单条整理：未保存的新文字被标成已另存

**场景与复现：** 稿件 A 点击“另存为新灵感”，延迟确认；编辑成 B；A 成功后页面显示 B，却出现“已另存为新灵感”，按钮禁用并显示“已另存”。实际保存的只有 A。证据：`24-output-pending-edit.png`、`25-output-false-saved.png`、`behavior-reproductions.json.outputEditDuringSave`。

**原因：** `pages/output/index.wxml:30` 未像多素材页一样绑定 `disabled="{{busy}}"`；`index.js:228` 无忙碌输入防护；`:306` 无条件设置 `savedSame: true`。

**修改要求：** 推荐与 R01 一致，提交时冻结编辑器，事件层增加防护。成功状态仍应由 `savedDraft === currentDraft` 推导，避免以后再次引入错误。若允许编辑，保存 A 后 B 必须保持可另存，提示明确“提交的稿件已另存”，查看入口指向 A。

**验收：** 延迟确认下修改、粘贴、切格式、双击另存；界面不得将 B 标为已保存；确认后的新记录正文与提交快照逐字一致；失败保留文字；按钮和成功链接对应正确 ID。完成后截图对比 A、B、保存结果三者。

**收益与代价：** 保证用户相信保存反馈；修改成本小，需覆盖成功回调、禁用状态和账户失效。

### R03 多素材整理：样式依赖已失配

**观察：** 五个格式变成整行默认灰按钮；选中“社交内容”后仍无可识别的选中样式。材料行的类型、日期、来源、正文混在同一居中段落，序号独立悬在上方。证据：`15-material.png`、`29-material-selected.png`。

**原因：** `pages/material-output/index.wxss:1` 导入了已重构的单条 output 样式；其 WXML 仍使用 `.template-options`、`.option`、`.option-body`、`.option-time`、`.option-content`。单条页的新规则主要针对 `.format-options` 与 `.option-item`，没有覆盖这些旧结构。

**修改要求：** 给多素材页恢复完整样式契约，或抽取共同组件样式后统一两个页面。格式区采用紧凑折行选项；选中状态使用品牌浅底、边框和勾选/文字标识。材料行采用左侧选择序号、右侧左对齐正文；类型与日期单独一行，来源单独一行，正文单独一块。

**布局规格：** 页面左右 20px；格式横向间隔 8px、纵向 8px，最小点击区 44×44px；材料行左右 12px、上下 12px，内容间隔 6px，正文 16px/1.6，元信息 13px/1.5；材料选择整行可点击。底部显示“已选 N 段 · M 条灵感”和唯一主按钮“整理成稿”。列表末项预留真实底部栏高度与安全区，避免固定 420rpx 造成过大空白。

**验收：** 375/390px 下格式正常折行，不能呈现五行全宽默认按钮；选中状态在灰度下可辨；选中顺序与生成顺序一致；320/430px、长来源、长正文、100 项筛选、已有稿件返回选材时无横向溢出、无底栏遮挡。生成、取消替换、返回当前稿件保留现有行为。

**收益与代价：** 恢复选材的扫描效率与组件一致性；样式成本小至中，共享抽取要同时回归单条页。

### R04 共用底部弹层：安全区不足

**观察与测量：** 格式弹层底部按钮和 Home 指示条重叠。模拟器 safe inset 为 34px；`.sheet` 底 753px，操作按钮底 741px，剩余仅 12px。`app.wxss:303` 使用 24rpx 底内边距，未包含安全区。证据：`13-content.png`、`14-format.png`、`26-format-safe-area.png`、`layout-reproductions.json.sheet`。

**修改要求：** 共用 `.sheet` 留出基础间距加实际安全区；如 `padding-bottom: calc(12px + env(safe-area-inset-bottom))`，兼容性回退与页面容器一并核对。标题和操作区固定在弹层内，超长内容单独滚动；总高度预算包含标题、操作、关闭入口与安全区。不要对带原生 tabBar 的页面重复计入同一安全区。

**验收：** 实际按钮底部与弹层底部距离至少为该容器安全 inset + 8px；iOS 34px、Android 手势导航、无 safeArea 字段机型都验证。内容、格式、详情菜单、留档逐一截图；留档长文并生成 TXT 后出现第三个按钮时仍能点击“返回稿件”。长文当前可滚动不代表新增操作状态已通过。照片失败重试页也纳入底部区域回归（`37-photo-unavailable.png`），单独核对其容器留白，不能只修改 `.sheet` 就判全局安全区通过。

**收益与代价：** 避免误触和系统手势竞争；共用规则会影响多个面板，需逐一回归。

平台依据：[getWindowInfo 官方文档](https://developers.weixin.qq.com/miniprogram/dev/api/base/system/wx.getWindowInfo.html)，部分机型可能不返回 safeArea，计算时应有回退。

### R05 单条整理：离开未另存稿件缺少损失提示

**已证实范围：** 修改自由稿后执行页面卸载并重新进入，重新生成原稿，手动编辑丢失；未注册离开保护，页面也无 C58 提示。证据：`behavior-reproductions.json.outputLeave`。本轮未做真机系统返回和手势拦截实测。

**原因：** `pages/output/index.js:98` 卸载只清理临时文件；`index.wxml` 缺少与多素材页相应的“未另存的稿件离开后不保留，请先复制或另存。”说明。

**修改要求：** 在可编辑稿件附近增加上述简短提示；有未确认编辑时，对平台支持的返回动作启用离开提醒，建议文案“这份稿件还没有另存，离开后不会保留。要离开吗？”；取消后保留当前文字，明确离开才卸载。不引入本机持久化。复制成功可以表述为已复制，不能当成已另存。

**验收：** 编辑→导航栏返回→取消，文字逐字不变；再次返回并确认离开，风险文案清楚。另存后当前内容完全相同不重复提示；之后再编辑恢复未另存提示。手势返回、关闭小程序、中断场景不承诺一定拦截或能够找回；必须始终有退出前可见的风险说明。单条与多素材提示一致。

**收益与代价：** 降低用户意外损失编辑的风险；状态判断成本中等。

平台依据：[enableAlertBeforeUnload 官方文档](https://developers.weixin.qq.com/miniprogram/dev/api/ui/interaction/wx.enableAlertBeforeUnload.html)。该能力只覆盖指定非底层页面返回场景，手势滑动返回不拦截，也不能阻止退出小程序。

### R06 继续补充：未绑定原生焦点

**观察：** `onLocateCompose()` 设置 `composeFocus: true` 并滚动，输入框随状态变高，但原生 textarea 的 focus 属性仍为 0；WXML 没有 `focus` 绑定。证据：`31-focus-detail.png`、`layout-reproductions.json.focus`；位置 `pages/detail/index.js:256`、`index.wxml:67`。

**修改要求：** 为程序请求焦点绑定实际 textarea `focus`，点击成功页“继续补充”或详情相同按钮后，请求焦点并滚动到可输入位置；失焦清除请求状态。不要在普通详情首次打开时自动弹键盘。可以使用独立焦点请求变量，避免将“正在输入”和“请求焦点”混成一个生命周期。

**验收：** 一次点击后真实 textarea 聚焦；iOS/Android 中文输入法能直接输入，无第二次点击；候选栏不会覆盖光标或添加按钮；连续失焦再点、长正文、成功页跳入正确记录都测。模拟器已确认缺少绑定，键盘完整效果仍需真机。

**收益与代价：** 实现原 AC05 的“一次定位可输入”；成本小。

平台依据：[textarea 官方文档](https://developers.weixin.qq.com/miniprogram/dev/component/textarea.html)，`focus` 与 `disabled` 为实际组件属性，页面自定义变量不会自行获得该效果。

### R07 列表返回：刷新失败会清空已确认内容

**复现：** 同账户列表已有 6 项，进入详情再返回时令读取抛错，列表变为 0 项并出现全页错误。Node 独立样例 1→0 结果一致。证据：`30-list-return-failure.png`、`layout-reproductions.json.listFailure`；`pages/list/index.js:49—50` 在加载前无条件清空。

**修改要求：** 同账户、同 session 下刷新时保留确认列表、当前搜索/筛选与滚动锚点；读取失败在列表上方说明“暂时无法更新，仍显示上次读取的内容。”并提供“重试”。首次无内容的加载失败使用全页错误。账户改变时必须先清掉旧内容，再开始新账户加载；不得以保留列表为由取消账户校验。

**验收：** 从第 30 项返回，响应延迟、失败、成功三种情况下查询与位置都可恢复；失败仍有之前确认内容。首次失败不是“没有灵感”；切账户立即移除旧数据，旧请求迟到不得回填。增加覆盖原 AC08 的失败断言。

**收益与代价：** 保留找内容的上下文；成本中等，账户隔离与恢复策略需同时验证。

### R08 另存网络未知：提示不应断言失败

**复现：** 单条另存收到 `NETWORK`，显示“另存失败，稿件还在，可稍后重试或先复制。”。在丢回执情况下客户端不能确定服务器未写入。证据：`27-output-unknown-as-failed.png`；`pages/output/index.js:299`。

**修改要求：** 按写入协议区分明确拒绝与结果未知：未知显示“尚未确认另存，稿件还在。请重试确认，或先复制。”；明确拒绝可说“未能另存”，并给具体恢复方式。重试继续使用同一逻辑请求幂等 ID。核查多素材另存等写入入口是否有同类问题，只修改确有相同结果语义的入口。

**验收：** 模拟服务器已写但回执丢失→未知提示→同 ID 重试→唯一记录、正确 ID 与成功状态；明确拒绝保留输入；迟到成功后旧错误消失；不因更改文案增加新的请求 ID。云端行为需在另行授权环境验收。

**收益与代价：** 统一记录与另存的保存语义；文案成本小，协议分类与回归成本中等。

### R09 局部字号与输入边界仍未统一

**测量：** 稿件编辑器实际 15px，计数 12px，格式按钮 13px；编辑器边框为 `#E6E4DE`、白底。原设计正文目标 16—17px、辅助信息至少 13px、按钮至少 14px，关键表单边界应使用更明确的颜色。证据：`layout-reproductions.json.typography/sheet`；`pages/output/index.wxss:34`、`:47` 与 `.format-options .template-option`。

**修改要求：** 页面规则增加对应 px 下限，避免覆盖全局字号后退回小 rpx；编辑正文建议 `max(30rpx,16px)`、辅助信息 `max(25rpx,13px)`、格式按钮 `max(28rpx,14px)`。编辑器边界使用设计规定的表单边界 token，弱分隔线仍保留现有浅色；不要将所有装饰分隔线一律加深。

**验收：** 320/375/390/430px 实际计算样式满足正文≥16px、辅助≥13px、按钮≥14px；关键文字对比度≥4.5:1，关键表单边界目标≥3:1；测量实际控件热区≥44×44px，不能以 88rpx 直接代替 44px。字号放大 1.3 倍和长标签不裁切。现有 `hit-areas.json` 只有局部有效测量，不能作为全部点击区通过证据。

**收益与代价：** 提高阅读与输入区识别的一致性；成本小，需留意折行与按钮高度联动。
